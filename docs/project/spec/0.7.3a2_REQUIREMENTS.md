# 0.7.3a2: Импорт проектов MaxQuant

Сейчас есть реализованная утилита MQ2Dasmix, её код лежит тут: `/home/kirill/PycharmProjects/mq_test_imports/mq2dasmix`

Она работает в командной строке, умеет:
- Парсить mqpar-файл (параметры MaxQuant)
- Читать файлы вывода MaxQuant, включая txt-файлы описания идентификаций и файлы спектров в формате .apl
- Промежуточно конвертировать в MGF, обогащая спектры отсутствующей в них информацией.
- Сохранять результат как проект DASMixer

Утилита не опубликована как отдельный пакет или другим способом, решение сделать отдельную утилиту - временное.

Требуется интегрировать эту утилиту в основной DASMixer.

Основную логику импорта MaxQuant требуется добавить в новый модуль: dasmixer-core/src/dasmixer/api/inputs/complex/MaxQuantProject

Добавляем GUI для импорта на Samples Tab, в один ряд с блоком import spectra добавляем блок Import From MaxQuant

По клику открывается модальное окно, в исходном виде содержит одно поле ввода файла "MQPar File" (пользвоатель выбирает путь к mqpar.xml) и кнопка parse. По нажатию: логикой mq2dasmix парсим MQPar, определяем пути к папкам с raw files и custom txt. Выводим их отдельными редактируемыми полями, показываем зеленую галочку если путь из mqpar существует, красный значок если отсутствует. то же для файла Fasta, но помимо проверку наличия добавляем чекбокс "Import proteins from FASTA file".

Также ниже поля:
- Tool name: имя инструмента для импортируемых данных (по умолчанию MaxQuant)
- Subset name: имя группы (subset) для добавляемых файлов. По умолчанию MaxQuant Imports 
- чекбокс "Delete temporary MGF and identification files after import" (default=True)
- чекбокс "Skip contaminant identifications" (default=True), если он не установлен, то сохраняются также идентификации с флагом potential contaminant

Также ниже отображается список RAW-файлов, полученных из MQPar и используемых для дальнейшей работы, с чекбоксами и логикой select all/deselect all

Пользователь таким образом:
1. может увидеть пути к данным из mqpar-файла
2. если пути недоступны (файлы перемещены, расчёт выполнялся на другом компьютере), может задать корректные пути
3. может задать название для группы и инструмента, используемых при импорте (по умолчаню tool.name = MaxQuant, subset.name="MaxQuant Import")
4. Может решить, необходимо ли удалять временные файлы данных (MGF, CSV)
5. Может решить, сохранять или нет в проекте идентификации белков, отмеченных MaxQuant'ом как загрязняющие
4. Может испортировать данные только тех образцов, которые были выбраны (т.е. убрать галочки с тех образцов, которые не планируется импортировать)

Примечание по п.3: если группа с указанным именем уже существует, то импортируем в неё. Для инструмента проверка, что используется парсер MaxQuant, если используется - ОК, иначе отображаем предупреждение

Внизу диалога кнопки "Cancel" и "Import". Cancel доступен всегда, Import - только когда указаны существующие пути к файлам (для FASTA критично только если установлен чекбокс) и выбран хотя бы один RAW-файл.

После нажатия, начинает работать логика утилиты, отображается progressbar. Сначала показываем просто текст с нулевым прогрессом: Reading metadata... потом по мере конвертации файлов показываем `Converting {filename}...`. После конвертации отображаем Creating tool and subset (если этап актуален, т.е. инструмент и группу необходимо создать), потом стандартный прогресс импорта спектров и идентификаций

Принципиальные отличия от текущей логики утилиты:

- этап парсинга mqpar в самом начале, до запуска расчётов и подтверждение от пользователя уже после, с возможностью указать пути
- выбор файлов, возможность импортировать файлы частично
- выбор сохранять или нет потенциально контаминированные последовательности (сейчас в логике mq2dasmix они не попадают в identifications)
- самое важное: новый проект при этом не создаётся, данные загружаются в существующий проект

В конце отображаем результат в snack bar

В CLI добавляем команду `dasmixer-cli import maxquant [options] PROJECT_PATH MQPAR_PATH`.
options аналогичны таковым у исходной утилиты mq2dasmix (override-пути к папкам, --delete-temporary-files), а также --tool-name, --subset-name, --keep-contaminants

Т.е. CLI должен позволять то же, что и GUI, за исключением выбора файлов. Также для CLI путь к проекту может не существовать, в таком случае создаётся новый проект, в который импортируются файлы MaxQuant
