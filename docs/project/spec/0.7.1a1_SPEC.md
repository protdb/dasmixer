## 0. Краткое содержание

Релиз вводит показатель **Identification Quality** в весь пайплайн Ion Match: расчёт (уже есть) → сохранение в БД → использование как гейт для перебора PTM в SEQFixer → фильтр в Select Preferred → отображение/фильтрация в таблице пептидов. Дополнительно расширяется `get_joined_peptide_data` и GUI-таблица (новые колонки, вычисляемые `final_charge`/`final_pepmass` с глифом ♻ и тултипами, новые фильтры), добавляется кнопка **Clear Calculations**.

> Базовая формула Quality и функция `calculate_peptide_quality` **уже реализованы** в `dasmixer-core/src/dasmixer/api/calculations/spectra/quality_calculations.py` и возвращаются в `MatchResult.quality` из `match_predictions`. Работы по расчёту нет — нужна проводка значения через схему/пайплайн/UI и новая логика гейтинга.

## 2. Текущее состояние (контекст для исполнителя)

### 2.1 Расчёт Quality
- `quality_calculations.py::calculate_peptide_quality(matches, sequence, ion_types) -> float` — формула `(1/n_ion_types) * (n_ions / (seq_length - 1))`, 0.0..1.0. Ссылка: `https://doi.org/10.1093/bioinformatics/bth947`.
- `ion_match.py::MatchResult` имеет поле `quality: float`.
- `match_predictions()` уже вызывает `calculate_peptide_quality` и кладёт результат в `MatchResult.quality`.
- **Значение нигде не сохраняется**: `process_single_ident` не включает `quality` в результирующий dict; колонки в `identification` нет; `put_identification_data_batch` её не пишет.

### 2.2 Пайплайн (`identification_processor.py::process_single_ident`)
- Текущий порядок: **SeqFixer (`fixer.get_ppm`) ПЕРВЫМ** → `match_predictions` ВТОРЫМ (на override/исходной последовательности).
- `_get_best_override` содержит баг: `criteria = "intensity_percent"` перетирает аргумент (в рамках релиза не трогаем, отмечаем как known).
- `process_identificatons_batch` извлекает из `item`: `id, spectre_id, sequence, pepmass, charge, mz_array, intensity_array` — **canonical_sequence НЕ извлекается**, хотя `to_worker_dict()` его уже отдаёт.
- `item["source_sequence"] = sequence` устанавливается в `process_identificatons_batch` (стр. 314).

### 2.3 SEQFixer (`seqfixer.py::get_ppm`)
- 3-шаговый pipeline: (1) direct hit по mgf_charge; (2) charge override scan; (3) isotope offset × PTM enumeration.
- За Step 3 (перебор PTM) отвечает `_scan_offsets_and_ptms`, вызванный с `ptm_sites`. Когда `self.unallocated_only=True` → `ptm_sites = []` (новые позиции не перебираются, разрешаются только существующие unlocalized `?`). Это поведение = «PTM выключены, только isotope offset + charge» — то, что нужно для гейта по quality.

### 2.4 Схема БД (`schema.py`)
- `identification` уже имеет: `override_charge`, `source_sequence`, `isotope_offset`, `theor_mass`, `ppm`, `intensity_coverage`, `ions_matched`, `ion_match_type`, `top_peaks_covered`.
- **Нет**: `quality`, `override_pepmass`, `has_ptm`.
- `MIGRATIONS` (в `migrations.py`) содержит записи для 0.2.0, 0.3.0, 0.7.0. `apply_migrations()` **вызывается** из `app.py:433` (с прогресс-диалогом) — механизм живой.

### 2.5 Preferred selection
- Активная функция: `matching.py::calculate_preferred_identifications_for_file` (вызывается из `select_preferred` action).
- Trusted pool: `identification_mixin.get_all_idents_for_preferred` — без фильтров.
- Normal pool: `identification_mixin.get_idents_for_preferred` — SQL-фильтры по score/ppm/coverage/length/peaks/ions/top_peaks.
- Старая `select_preferred_identifications` (pandas-подход) — NOT используема из GUI, но присутствует.

### 2.6 get_joined_peptide_data
- Не выбирает из `identification`: `override_charge, source_sequence, isotope_offset, theor_mass, quality, override_pepmass, has_ptm`.
- Из `spectre`: нет `peaks_count` в SELECT (но `s.peaks_count` доступен на уровне outer query).
- Фильтров `min_quality, has_ptm, has_substitution` нет.

### 2.7 GUI
- `PeptideIonTableView` (peptide_ion_table_view.py) наследует `BaseTableView`.
- `get_data()` возвращает `tuple[pd.DataFrame, pd.DataFrame | None]` (tooltips_df).
- Tooltip-механизм: `BaseTableView.get_tooltip(col, idx)` читает `self._last_tooltips_df.at[idx, col]`.
- `_render_table` рендерит ячейку как `str(value)` (float → `f"{value:.4f}"`, None/NaN → `""`). Сортировки по столбцам нет → строковые вычисляемые колонки допустимы.
- `header_name_mapping`, `default_columns`, `column_filter_mapping` — атрибуты подкласса.
- `default_columns` (15): identification_id, spectre_id, sample, seq_no, scans, tool, sequence, ppm, intensity_coverage, ions_matched, ion_match_type, top_peaks_covered, is_preferred, protein_id, gene. `charge`/`pepmass` уже НЕ в default (скрыты), но и нет для них `header_name_mapping`.
- Кнопки actions — в `actions_section.py`; «Save settings» одна в нижнем ряду после Divider.
- Preferred settings (Block 2) — в `tool_settings_section.py::_create_tool_controls`/`_build_tool_card`; сохраняются через `save_tool_settings` в `tool.settings` dict (JSON TEXT). `get_tool_settings_for_matching()` отдаёт dict для пайплайна.
- Ion coverage action (`ion_actions.py::IonCoverageAction`) читает per-tool `trust_ppm`/`unallocated_only`/`ptm_list`/`max_ptm` из `state.tool_settings_controls` и пробрасывает в `process_identificatons_batch` позиционно через `loop.run_in_executor`.

### 2.8 Иконки/г_export
- Символ «перевыбора» — `♻` (U+267B). Используется в ячейках `final_charge`/`final_pepmass` (строка за значением).

#### T2.2 — process_single_ident: pre-match → quality → гейт → reuse → новые поля
**Файл:** `dasmixer-core/src/dasmixer/api/calculations/spectra/identification_processor.py` (`process_single_ident`, стр. 105–224)
- Добавить параметры в сигнатуру:
  ```python
  def process_single_ident(
      fixer, params, fragment_charges,
      sequence, pepmass, mz_array, intensity_array,
      canonical_sequence: str | None = None,   # НОВОЕ
      mgf_charge: int | None = None,
      selection_criteria: str = "intensity_percent",
      trust_ppm: bool = False,
      existing_ppm: float | None = None,
      quality_threshold: float = 0.25,          # НОВОЕ
  ) -> dict:
  ```
- **Новый алгоритм** (кроме ветки `trust_ppm`):
  1. Если `'?' in sequence` → pre-match НЕ выполняем (нельзя осмысленно посчитать quality по unlocalized); `pre_match = None`; `quality = None`; `allow_ptm = True`. Идём в существующий путь раскрытия unlocalized (`_expand_unlocalized` + перебор вариантов по `intensity_percent`), как сейчас.
  2. Иначе — **pre-match на исходной последовательности**:
     ```python
     pre_match = match_predictions(params, mz_array, intensity_array, fragment_charges, sequence)
     quality = pre_match.quality
     allow_ptm = quality < quality_threshold   # высокий quality → не перебираем PTM
     ```
  3. `seq_results = fixer.get_ppm(sequence, pepmass, mgf_charge, allow_ptm=allow_ptm)`.
  4. Если нет override (`seq_results.override` falsy) И нет `'?'`:
     - `ppm_result = seq_results.original` (его `sequence == sequence`).
     - **Reuse**: `match_result = pre_match` (НЕ вызываем `match_predictions` повторно).
  5. Если нет override И есть `'?'`: существующий путь раскрытия unlocalized (без изменений), `match_result` = лучший вариант, `quality = match_result.quality`.
  6. Если override есть:
     - Строим `all_matches = []`. Для каждого `override`:
       - Если `override.sequence == sequence` И `pre_match is not None` → добавляем `(override, pre_match)` (reuse, без повторого `match_predictions`).
       - Иначе → `(override, match_predictions(..., override.sequence))`.
     - Если `pre_match is not None` — дополнительно можно добавить `(seq_results.original, pre_match)` кандидатом (опциональная оптимизация; если добавляется — учитывается в `_get_best_override`). **Решение: НЕ добавлять** original, чтобы сохранить существующее поведение выбора только из overrides. (pre_match используется для reuse только в случае override с неизменной последовательностью.)
     - `ppm_result, match_result = _get_best_override(all_matches, criteria=selection_criteria)`.
     - `quality = match_result.quality`.
- **Новые поля в возвращаемом dict**:
  ```python
  # override_pepmass: NULL если isotope_offset отсутствует (None или 0)
  override_pepmass_value = (
      ppm_result.pepmass if (ppm_result.isotope_offset) else None
  )
  # has_ptm: по финальной последовательности vs canonical
  has_ptm_value = None
  if canonical_sequence is not None:
      has_ptm_value = 1 if ppm_result.sequence != canonical_sequence else 0
  ```
  Итоговый dict (к полному списку ниже) += `quality`, `override_pepmass`, `has_ptm`.
- **trust_ppm ветка** (стр. 119–154): добавить в возвращаемый dict `quality = match_result.quality`, `override_pepmass = None` (isotope_offset = 0 → None), `has_ptm` по `canonical_sequence` (если передан) иначе None.

**Полный возвращаемый dict:**
```python
{
    "sequence": ppm_result.sequence,
    "ppm": ppm_result.ppm,
    "theor_mass": ppm_result.seq_neutral_mass,
    "override_charge": ppm_result.charge,
    "isotope_offset": ppm_result.isotope_offset,
    "intensity_coverage": match_result.intensity_percent,
    "ions_matched": match_result.max_ion_matches,
    "ion_match_type": match_result.top_matched_ion_type,
    "top_peaks_covered": match_result.top10_intensity_matches,
    "quality": quality,                       # НОВОЕ
    "override_pepmass": override_pepmass_value,  # НОВОЕ
    "has_ptm": has_ptm_value,                 # НОВОЕ
}
```

## Приложение A. Пользовательская документация по Quality

> Текст для файла `docs/project/identification_quality.md`. Переводимая в HTML/Markdown как есть.

````markdown
# Identification Quality

**Identification Quality** — это числовой показатель (от 0.0 до 1.0), оценивающий, насколько хорошо теоретические фрагмент-ионы наблюдаемого пептида покрыты peaks экспериментального тандемного масс-спектра. Он вычисляется для каждой идентификации на этапе *Ion Coverage* и используется в DASMixer:

1. **как Gate для перебора PTM** в SEQFixer: высокое Quality означает, что разметка спектра надёжна и высокий precursor PPM скорее всего объясняется изотопным сдвигом (isotope offset), а не пропущенной модификацией;
2. **как фильтр в Select Preferred** (порог *Quality Threshold* на вкладке Peptides → настройки инструмента);
3. **как колонка и фильтр** в таблице пептидов.

## Формула

Индекс согласуется с подходом, описанным в:

> Bern, M., Goldberg, D., McDonald, W. H., & Yates, J. R. (2004).
> *Automatic Quality Assessment of Peptide Tandem Mass Spectra.*
> **Bioinformatics**, 20(suppl_1), i49–i54.
> https://doi.org/10.1093/bioinformatics/bth947

Для пептида длиной `L` (в аминокислотах, без модификаций) и набора типов ионов `ion_types` (по умолчанию `b` и `y`):

```
quality = (1 / N_ion_types) * (N_matched_unique / (L - 1))
```

где:
- `N_ion_types` — число используемых типов ионов (`b`, `y` → 2);
- `L - 1` — теоретически возможное число фрагментов одного типа для пептида длиной `L`;
- `N_matched_unique` — число **уникальных** совпадений fragment-ионов. Уникальность определяется по ключу `{ion_type}{fragment_length}` (повторы одного и того же фрагмента в разных зарядах считаются одним покрытием).

Таким образом, `quality = 1.0` означает, что все теоретически возможные фрагменты (обоих рядов) наблюдаются; `quality = 0.0` — ни одного совпадения.

> **Замечание.** Формула корректна только для `b`/`y` ионов. Добавление дополнительных рядов (`a`, `c`, `x`, `z`) делает значение трудноинтерпретируемым — поэтому DASMixer использует пару `b`/`y` по умолчанию.

## Как это используется в пайплайне

При расчёте Ion Coverage для каждой идентификации:

1. Сначала выполняется `match_predictions` на **исходной** (импортированной) последовательности — считается Quality.
2. Далеe работает SEQFixer (исправление precursor PPM):
   - если **Quality ≥ Quality Threshold** — перебор новых PTM-позиций **пропускается**, исправление идёт только за счёт заряда и изотопного сдвига (идея: качественная разметка спектра указывает, что высокий PPM — это isotope offset, а не пропущенная модификация);
   - если **Quality < Quality Threshold** — выполняется полный перебор комбинаций PTM + isotope offset + charge;
3. исключение: последовательности с неразнесёнными модификациями (ProForma `?`) — pre-match не выполняется, варианты раскрываются и выбираются по интенсивности покрытия.

## Настройка порога

*Peptides → настройки инструмента → Preferred settings → Quality Threshold.* Значение по умолчанию: **0.25**. Порог сохраняется вместе с остальными настройками инструмента (кнопка *Save settings*) и применяется:

- при «Select Preferred» (идентификации с Quality ниже порога не выбираются предпочтительными, кроме инструментов с флагом *Trust all identifications*);
- при «Calculate Ion Coverage» (как гейт PTM внутри SEQFixer).

## Отображение в таблице

В таблице *Peptide Identifications*:

- колонка **Quality** видна по умолчанию;
- фильтр **Min Quality** отсекает строки с Quality ниже порога (строки с не обсчитанным Quality исключаются при установке фильтра);
- глиф `♻` в колонках **Charge**/**Pepmass** указывает, что значение получено из override (SEQFixer): tooltip показывает исходные spectre-значения и, для pepmass, изотопный сдвиг.
````
