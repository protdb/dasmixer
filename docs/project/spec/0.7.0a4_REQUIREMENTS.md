# 0.7.0a4: Оптимизация manage samples view

Сейчас производительность страдает из-за большогоколичества компонентов в manage samples view при большом числе образцов в проекте.

Все доработки касаются Manage Samples View: `dasmixer-gui/src/dasmixer/gui/views/manage_samples_view/manage_samples_view.py`

Необходимо значитлеьно оптимизировать работу этой вкладки в соответствии с описанными ниже подходами. Оптимизация планируется за счёт уменьшения количества элементов в дереве Flet одновременно.

Также к списку образцов нужно применить подходы, в целом характерные для таблиц, при этом не реализуя его как Table, т.е. визуально каждая строка остаётся такой же, как сейчас, но добавляются типично табличные функеции - фильтры и пагинация

Также НЕ трогаем шапку над списком образцов, не отменяем логику работы с выделением образцов (select all/deselect all, групповые операции) которые есть сейчас

При работе см. на `dasmixer-gui/src/dasmixer/gui/components/base_table_view.py`, там приличная часть этого функционала реализована для таблиц, делаем визуально максимально похоже и копируем логику, названия методов и т.д.

## Ленивая загрузка "аккордеонов"

Компоненты управления образцм (дополнительные кнопки, список файлов) должны появляться только при разворачивании и удаляться из дерева компонентов Flet при сворачивании.

Первый раз при открытии данные подгружаются из БД, при схлопывании кэшируются для следующего открытия, но компоненты Flet удаляются при сворачивании и пересоздаются при открытии.

## Поиск, паджинация

Требуется добавить контролы фильтров отображаемых в моменте образцов:
- Поиск по названию
- Поиск по статусу (выпадающий список)
- Поиск по subset (выпадающий список)
- Поиск по статусу outlier (да, нет, все)
- Кнопка Apply Filters, применяет фильтр

Также под списком необходимо сделать функционал паджинации, аналогично BaseTableView с одним исключением - в списке возможных количеств сделать пункт "All", который показывает сразу все образцы вне зависимости от количества

## Оптимизация статистики

Сейчас статистика по образцам формируется через индивидуальные запросы на каждый образец и как следствие - работает невероятно медленно.

Нужно улучшить процесс обновления списка образцов, сделав один SQL-запрос, который отдаёт все необходимые данные сразу.

Результаты так же кэшируются в `sample_status_cache`, но их необходимо и для перерасчёта получать одним запросом.
