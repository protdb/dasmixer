## 0. Обзор

Интеграция функциональности отдельной CLI-утилиты `mq2dasmix`
(`/home/kirill/PycharmProjects/mq_test_imports/mq2dasmix`, файлы `parse_mqpar.py`, `convert.py`,
`app.py`) в основной DASMixer: импорт результатов MaxQuant (`mqpar.xml` + `msms.txt` +
`msmsScans.txt` + `.apl`-файлы спектров) напрямую в существующий (или, для CLI, опционально новый)
`.dasmix`-проект, без промежуточного standalone-инструмента.

| # | Задача | Затронутые пакеты |
|---|---|---|
| A | Core: модуль `MaxQuantProject` — парсинг `mqpar.xml`, конвертация APL→MGF+identifications, импорт в `Project` | `dasmixer-core` |
| B | GUI: блок «Import From MaxQuant» на Samples Tab + модальный диалог (parse → configure → progress) | `dasmixer-gui` |
| C | CLI: команда `dasmixer-cli import maxquant` | `dasmixer-cli` |

Реализуется в порядке A → B, C (B и C оба зависят от A, могут делаться параллельно после A).

**Принципиальные отличия от `mq2dasmix` (по REQUIREMENTS + уточнениям):**

1. Парсинг `mqpar.xml` — **отдельный, самый первый шаг**, до любых тяжёлых расчётов; результат
   (пути, список RAW-файлов) показывается пользователю для подтверждения/правки **до** запуска
   конвертации.
2. Частичный импорт — пользователь может снять галочки с части RAW-файлов.
3. Выбор — сохранять ли `Potential contaminant`-идентификации (чекбокс, по умолчанию отфильтрованы,
   как и раньше). `Decoy`-идентификации отфильтровываются **всегда**, без чекбокса (без изменений
   относительно `mq2dasmix`).
4. **Новый проект не создаётся** в GUI-потоке — импорт идёт в уже открытый `Project`. В CLI —
   путь к проекту может не существовать, тогда создаётся новый (`create_if_not_exists=True`).
5. Дубликаты (повторный импорт того же RAW-файла) обрабатываются той же логикой
   on-duplicates (`skip` / `reload` / `add_as_new`), что и в обычном импорте спектров/
   идентификаций (`import_handlers.py`), а не безусловным падением на `add_sample`.
6. FASTA — опциональный импорт белков по чекбоксу (`is_uniprot=True` всегда, плюс чекбокс
   "Import proteins from FASTA file", включён по умолчанию).

## 1. Согласованные решения (из диалога с разработчиком)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Расположение `.apl`-файлов | Только `{raw_parent}/{raw_name}/p0/*.apl` (per-sample файлы). Расположение `combined/andromeda/*.apl` (смешанные, без разбивки по образцам) **не поддерживается** — сознательное ограничение, как в `mq2dasmix`. Артефакт `combined_path` в `MQParPaths` остаётся неиспользуемым (как и в исходной утилите). |
| 2 | Несколько `raw_parents` (родительских директорий RAW-файлов) в одном `mqpar.xml` | В GUI/CLI показываем/используем только **первую** директорию (`raw_parents[0]`). Если реальные RAW-файлы разбросаны по нескольким директориям — не поддерживается в рамках этой версии. |
| 3 | Повторный импорт / коллизия имени Sample | Не ошибка. Sample с существующим именем **переиспользуется** (как обычный `get_sample_by_name` → если найден, используем его, иначе создаём). Коллизии на уровне `spectre_file`/`identification_file` (повторный импорт того же RAW-файла) обрабатываются через **on-duplicates radio** (`skip` / `reload` / `add_as_new`), идентично `ImportPatternDialog`/`import_handlers.py`. Значение по умолчанию — `skip`. |
| 4 | Несовпадение `Tool.parser` (существующий Tool с именем "MaxQuant", но `parser != "MaxQuant"`) | Блокирует кнопку Import. Проверка выполняется (а) сразу при отображении диалога конфигурации (для значения по умолчанию `MaxQuant`), (б) повторно при потере фокуса полем "Tool name". Рядом с полем — индикатор статуса: зелёная галочка (tool не существует **или** существует с `parser == "MaxQuant"`), жёлтый warning-значок (существует с другим parser). |
| 5 | Зависимость `lxml` | Добавляется как **прямая** зависимость `dasmixer-core` (уже присутствует как транзитивная в `dasmixer-gui/poetry.lock` через другой пакет — риска потяжеления сборки нет). Код парсера `mqpar.xml` переносится из `mq2dasmix/parse_mqpar.py` без переписывания на `ElementTree`. |
| 6 | Decoy-идентификации | Отбрасываются всегда безусловно (как в `mq2dasmix`), без отдельного UI-контрола. |
| 7 | Временные файлы (MGF/CSV) | Пишутся в `~/.cache/dasmixer/tmp/maxquant_import/<timestamp>/` (по аналогии с `get_temp_html_dir()` в `dasmixer.api.config`), не в `cwd()`. При снятом чекбоже "Delete temporary files" — файлы остаются по этому пути, путь показывается в итоговом snackbar. |
| 8 | Возможность Cancel во время прогресса импорта | **Нет.** Cancel доступен только в диалогах "parse"/"configure" (до нажатия Import). После нажатия Import идёт безостановочный прогресс до завершения (успеха или ошибки) — как во всех существующих `import_handlers.py`-флоу. |
| 9 | Опция `--limit` из `mq2dasmix` | Не переносится (была debug-опцией). |
| 10 | CLI-поведение при несовпадении `Tool.parser` | Команда завершается с ошибкой (`typer.Exit(1)`), без варианта "продолжить на свой риск" — в отличие от GUI, где это просто заблокированная кнопка. |
| 11 | Импорт FASTA — UniProt-формат | Добавляется чекбокс "Sequences are in UniProt format" (по умолчанию `True`), аналогично `LoadFastaDialog`. Значение прокидывается в `FastaParser(is_uniprot=...)`. |

## 2. Core: модуль `dasmixer-core/src/dasmixer/api/inputs/complex/MaxQuantProject`

### 2.1. Структура нового пакета

```
dasmixer-core/src/dasmixer/api/inputs/complex/
├── __init__.py
└── MaxQuantProject/
    ├── __init__.py               # публичный API модуля (реэкспорт)
    ├── mqpar_parser.py            # T1 — парсинг mqpar.xml (из parse_mqpar.py)
    ├── apl_convert.py              # T2 — чтение msms.txt/msmsScans.txt, APL→MGF+CSV (из convert.py)
    ├── importer.py                 # T3 — оркестратор: создание tool/subset/sample, импорт в Project
    └── progress.py                 # T4 — dataclass-и стадий прогресса (общие для GUI/CLI)
```

`dasmixer.api.inputs.complex` — новая под-пакет-категория импортёров (наряду с `spectra`,
`peptides`, `proteins`), предназначенная для многошаговых/составных импортов, работающих сразу с
несколькими типами данных и создающих несколько сущностей проекта за один вызов. `MaxQuantProject`
— первый (и пока единственный) модуль в этой категории. В `registry.py` **не регистрируется** —
у него принципиально другой контракт (не `SpectralDataParser`/`IdentificationParser`, а
самостоятельный оркестратор с прямым доступом к `Project`), поэтому вызывается напрямую по
классу/функции, а не через `registry.get_parser(...)`.

### 2.4. T3 — `importer.py`: оркестратор импорта

Ключевой новый код. Не наследует `BaseImporter`/`IdentificationParser` — это самостоятельный
класс с прямым доступом к `Project`, т.к. должен создавать tool/subset/sample и последовательно
работать с несколькими типами данных за один проход (spectra + identifications + опционально
proteins).

**Важные архитектурные примечания:**

- Функция **не открывает и не закрывает** `Project` — в отличие от `mq2dasmix/app.py`, где
  `async with Project(...)` создавался внутри. Открытие/закрытие — забота вызывающей стороны
  (GUI уже держит открытый `self.project`; CLI открывает явно, с `create_if_not_exists`,
  управляемым снаружи).
- `MaxQuantEvidenceParser` (`MQ_Evidences.py`) переиспользуется как есть — CSV, который
  генерирует `process_apl`, уже имеет нужные колонки (`MS/MS scan number`, `Modified sequence`,
  `Sequence`, `Proteins`, `Mass error [ppm]`, `Score`), совпадающие с `ColumnRenames` парсера. Без
  изменений в `MQ_Evidences.py`.
- Проверка совпадения `Tool.parser` **дублируется** здесь (defensive), хотя основная проверка,
  блокирующая UI, происходит на уровне диалога/CLI до вызова `run_maxquant_import` — на случай
  прямого использования модуля из скриптов/будущих интеграций.
- Порядок стадий прогресса соответствует REQUIREMENTS п. «Сначала показываем... Reading
  metadata... потом Converting {filename}... После конвертации... Creating tool and subset (если
  этап актуален)... потом стандартный прогресс импорта спектров и идентификаций».

### 2.5. Временная директория — вспомогательная функция

Добавить в `dasmixer-core/src/dasmixer/api/config.py` (рядом с `get_temp_html_dir()`):

```python
def get_maxquant_import_temp_dir() -> Path:
    """
    Директория для временных MGF/CSV файлов MaxQuant-импорта.
    ~/.cache/dasmixer/tmp/maxquant_import/<YYYYMMDD_HHMMSS>/ на Linux/macOS,
    <tempfile.gettempdir()>/dasmixer/maxquant_import/<...>/ на Windows.
    Создаётся (с parents) при первом вызове; вызывающая сторона отвечает за очистку.
    """
    from datetime import datetime
    ts = datetime.now().strftime("%Y%m%d_%H%M%S_%f")
    if sys.platform == "win32":
        base = Path(tempfile.gettempdir()) / "dasmixer" / "maxquant_import"
    else:
        base = Path.home() / ".cache" / "dasmixer" / "tmp" / "maxquant_import"
    temp_dir = base / ts
    temp_dir.mkdir(parents=True, exist_ok=True)
    return temp_dir
```

Используется по умолчанию в `MaxQuantImportOptions.temp_dir` (если `None`) внутри
`run_maxquant_import` (T3, шаг 2).

```python
async def _start_import(self, e):
    self._show_progress_screen()

    options = MaxQuantImportOptions(
        mqpar_path=self._mqpar_path,
        txt_path=Path(self._txt_field.value),
        raw_parent=Path(self._raw_path_field.value),
        fasta_path=Path(self._fasta_field.value) if self._fasta_field.value else None,
        import_fasta=self._cb_import_fasta.value,
        fasta_is_uniprot=self._cb_fasta_uniprot.value,
        tool_name=self._tool_name_field.value,
        subset_name=self._subset_name_field.value,
        delete_temp_files=self._cb_delete_temp.value,
        keep_contaminants=not self._cb_skip_contaminants.value,
        selected_raw_names=[name for name, cb in self._raw_file_checkboxes.items() if cb.value],
        on_duplicates=self._on_duplicates_group.value,
    )

    try:
        summary = await run_maxquant_import(self.project, options, progress_callback=self._on_progress)
        self._close()
        show_snack(
            self.page,
            f"MaxQuant import complete: {summary['samples_processed']} sample(s), "
            f"{summary['spectra_imported']} spectra, "
            f"{summary['identifications_imported']} identifications"
            + (f", {summary['proteins_imported']} proteins" if summary['proteins_imported'] else ""),
            ft.Colors.GREEN_400,
        )
        if self.on_complete_callback:
            await self.on_complete_callback()
    except Exception as ex:
        logger.exception(ex)
        self._close()
        show_snack(self.page, f"MaxQuant import error: {ex}", ft.Colors.RED_400)
    self.page.update()
```

### 4.2. Тело команды (логика)

```python
from dasmixer.api.inputs.complex.MaxQuantProject.mqpar_parser import get_paths_from_mqpar
from dasmixer.api.inputs.complex.MaxQuantProject.importer import (
    MaxQuantImportOptions, run_maxquant_import,
)

async def _run():
    mqpar_paths = get_paths_from_mqpar(mqpar_path)

    effective_fasta = Path(fasta_path) if fasta_path else mqpar_paths.fasta_path.path
    effective_raw = Path(raw_path) if raw_path else (
        mqpar_paths.raw_parents[0].path if mqpar_paths.raw_parents else None
    )
    effective_txt = Path(txt_path) if txt_path else mqpar_paths.custom_txt_path.path

    if effective_raw is None or not effective_raw.is_dir():
        typer.echo(f"Error: RAW files directory not found: {effective_raw}", err=True)
        raise typer.Exit(1)
    if not effective_txt.is_dir():
        typer.echo(f"Error: txt results folder not found: {effective_txt}", err=True)
        raise typer.Exit(1)
    if import_fasta and not effective_fasta.is_file():
        typer.echo(f"Error: FASTA file not found: {effective_fasta}", err=True)
        raise typer.Exit(1)

    project_file = Path(project_path)
    create_new = not project_file.exists()

    async with Project(path=project_file, create_if_not_exists=create_new) as project:
        # Проверка tool.parser — прерываем с ошибкой, п.10 раздела 1
        tools = await project.get_tools()
        existing_tool = next((t for t in tools if t.name == tool_name), None)
        if existing_tool is not None and existing_tool.parser != "MaxQuant":
            typer.echo(
                f"Error: Tool '{tool_name}' already exists with parser '{existing_tool.parser}' "
                f"(expected 'MaxQuant')", err=True
            )
            raise typer.Exit(1)

        options = MaxQuantImportOptions(
            mqpar_path=Path(mqpar_path),
            txt_path=effective_txt,
            raw_parent=effective_raw,
            fasta_path=effective_fasta if import_fasta else None,
            import_fasta=import_fasta,
            fasta_is_uniprot=fasta_is_uniprot,
            tool_name=tool_name,
            subset_name=subset_name,
            delete_temp_files=delete_temporary_files,
            keep_contaminants=keep_contaminants,
            selected_raw_names=[rf.name for rf in mqpar_paths.raw_files],  # CLI — всегда все
            on_duplicates=on_duplicates,
        )

        async def _progress(p):
            typer.echo(f"[{p.stage}] {p.message}")

        summary = await run_maxquant_import(project, options, progress_callback=_progress)

    typer.echo(f"\n✓ Import complete: {summary['samples_processed']} sample(s), "
               f"{summary['spectra_imported']} spectra, "
               f"{summary['identifications_imported']} identifications")
    if summary['proteins_imported']:
        typer.echo(f"  Proteins: {summary['proteins_imported']}")
    if summary['skipped_duplicates']:
        typer.echo(f"  Skipped duplicates: {summary['skipped_duplicates']}")

try:
    asyncio.run(_run())
    if create_new:
        config.add_recent_project(str(project_file))
except typer.Exit:
    raise
except Exception as e:
    typer.echo(f"Error during MaxQuant import: {e}", err=True)
    raise typer.Exit(1)
```

**Отличия CLI от GUI (по требованиям — "то же самое, за исключением выбора файлов"):**
- Нет интерактивного выбора RAW-файлов — импортируются **все**, перечисленные в `mqpar.xml`

- Нет диалога подтверждения путей — override-опции (`--fasta-path`, `--raw-path`, `--txt-path`)
  применяются напрямую, без предварительного показа/according-checka пользователю (согласуется с
  неинтерактивным характером CLI, как в остальных `import_data.py` командах).
- Проверка существования путей — падает с `typer.Exit(1)` сразу (без warning-fallback, как было
  в `mq2dasmix._resolve_fasta` — там просто печатался warning и `None`; здесь FASTA обязателен,
