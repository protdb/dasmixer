Представление Sample management (`dasmixer/gui/views/manage_samples_view.py`). Ряд задач, связанный с этим экраном

- Рефакторинг: превратить в модуль manage_samples_view, реструктурировать внутри на файлы меньшего размера. Сейчас > 800 строк, это плохо. 
  - отдельно: логика верхнего ряда, логика формы update
  - отдельно: класс SampleViewPanel(ft.Container) - контейнер конкретного пользователя
  - отдельно - логика обновления данных, именно логика
- Массовые операции:
  - Добавляем в модуль образца в заголовок панели в самом начале чекбокс для выбора образца.
  - Над списком образцов, но под существующей строчкой Update добавляем строку mass operations, позволяющую работать с выделенными образцами. Содержит кнопки:
    - select all
    - deselect all
    - outlier (если среди выделенных образцов есть не-аутлаеры, статус outlier присваивается всем выделенным; если выделены только аутлаеры, то сбрасывается)
    - drop file (см ниже, диалог)
    - assing group (диалог)
    - delete
    - Визуально обособленно: drop empty files
  - Действие drop file: всплывающий диалог (диалог в отдельном файле), позволяет выбрать, что удалить для образца (radio):
    - Spectre files (all)
    - Spectre files (keep first)
    - Spectre files (keep last)
    - Identification files (all)
    - Identification files by (выпадающий список инструментов)
    - Кнопки "Confirm" и "Cancel"
    - Удаление подтверждается диалогом со списком файлов для удаления (тип, ID, путь к файлу - в сокращенном виде) и текстом предупреждения: "Отмена действия невозможна. Действие не затрагивает исходные файлы в файловой системе, только данные в проекте"
  - Действие assign subset: диалог, выбор группы из имеющихся в проекте (dropdown). Назначается группа всем выбранным образцам
  - drop empty files: удаляет файлы идентификаций, в которых 0 идентификаций и spectre file, в которых 0 спектров

## Улучшения процесса импорта

На вкладке Samples (`dasmixer/gui/views/tabs/samples/samples_tab.py`) в диалогах импорта (и Spectra, и Identification) добавить radio group "On duplicates" с вариантами: skip (по умолчанию), reload, add as new

Если skip, то в случае если файл с таким путём уже есть в БД - он пропускается. Если выбрано reload - старый файл удаляется; add as new - никаких действий над старыми файлами не производится, файл идентификации добавляется ещё раз.
