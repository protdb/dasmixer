## 1. Задача A+B — Batch-экспорт MGF + фильтр Sequence contains + File Suffix

### 1.1. Текущее состояние (контекст)

`export_mgf()` (`dasmixer-core/src/dasmixer/api/export/mgf_export.py`) для каждого "unit" (сэмпл/spectre_file/все сэмплы, см. `_build_export_units`):
1. `_get_spectrum_ids()` — один SQL-запрос, возвращает `list[int]` id спектров по режиму `by`.
2. `_write_mgf_to_file()` — для батча `spectrum_ids` (по `_BATCH_SIZE=500`) **на каждый id по отдельности**:
   - `project.get_spectrum_full(spec_id)` — 1 SQL-запрос (`SELECT * FROM spectre WHERE id=?`) + decompress массивов;
   - если `need_ident` (любой из `write_offset/write_spectra_charge/write_seq`) — `_get_preferred_identification()` — ещё 1 SQL-запрос (`SELECT * FROM identification WHERE spectre_id=? [AND tool_id=?] AND is_preferred=1 LIMIT 1`).

То есть на каждый спектр — до 2 отдельных запросов к БД. Именно это должно быть заменено на batch-чтение с `LIMIT/OFFSET`.

### 1.2. T1 — Core: новый метод `SpectraMixin.get_full_spectrum_for_export`

**Файл:** `dasmixer-core/src/dasmixer/api/project/mixins/spectra_mixin.py`

```python
async def get_full_spectrum_for_export(
    self,
    sf_ids: list[int],
    by: str,                        # "all" | "all_preferred" | "preferred_by_tool"
    tool_id: int | None,
    need_ident: bool,               # True если нужен хотя бы один из write_offset/write_spectra_charge/write_seq
    sequence_contains: str | None,  # подстрока для фильтра по identification.sequence (LIKE, регистронезависимо)
    limit: int,
    offset: int,
) -> list[dict]:
    """
    Возвращает батч спектров (включая декомпрессированные массивы) вместе с
    данными preferred-идентификации (если need_ident=True), одним JOIN-запросом,
    отсортированных по s.seq_no, с пагинацией LIMIT/OFFSET.

    Формат каждого dict — объединение полей строки `spectre` (все колонки таблицы,
    включая декомпрессированные mz_array/intensity_array/charge_array и
    распарсенный all_params) и — если need_ident=True — плоских identification-полей
    (без префикса, под именами, ожидаемыми _build_spectrum_params):
        sequence, canonical_sequence, override_charge, isotope_offset
    Если для спектра нет подходящей identification (need_ident=True, но JOIN не нашёл
    строку) — эти 4 поля отсутствуют в dict (или равны None) — вызывающий код трактует
    это как ident=None.

    Фильтрация sequence_contains (см. п.1.3) применяется всегда через identification
    таблицу; при need_ident=False но sequence_contains задан — JOIN с identification
    всё равно строится (только для фильтрации, EXISTS/INNER JOIN по режиму), но
    identification-поля в результат не включаются.
    """
```

**Логика построения SQL** (реализуется как один метод, без переиспользования старых `_get_spectrum_ids`/`_get_preferred_identification` — они удаляются из `mgf_export.py`):

- Базовый `FROM spectre s WHERE s.spectre_file_id IN (...)`.
- **JOIN с identification** нужен в двух независимых случаях — их нужно различать при построении запроса:
  - `need_ident=True` → JOIN должен **вернуть** identification-поля → используется `LEFT JOIN` при `by="all"` (спектр может не иметь preferred-идентификации — тогда ident-поля будут `NULL`, это ожидаемо и обрабатывается как `ident=None`), либо `INNER JOIN` при `by in ("all_preferred", "preferred_by_tool")` (см. ниже — фильтрация по `by` и так требует INNER JOIN).
  - `sequence_contains` задан → нужен доп. фильтр "у спектра есть **хотя бы одна** identification с этой подстрокой" — реализуется как `EXISTS`-подзапрос (см. п.1.3), **независимо** от того, участвует ли JOIN с identification в выборке данных.
- Режим `by`:
  - `"all"`: без ограничения по identification для выборки строк (кроме поля данных, если `need_ident=True` — тогда `LEFT JOIN identification i ON i.spectre_id=s.id AND i.is_preferred=1` без ограничения по `tool_id`).
  - `"all_preferred"`: `INNER JOIN identification i ON i.spectre_id=s.id AND i.is_preferred=1` (ограничивает выборку строк — только спектры с preferred-идентификацией любого инструмента).
  - `"preferred_by_tool"`: `INNER JOIN identification i ON i.spectre_id=s.id AND i.is_preferred=1 AND i.tool_id=?` (`tool_id` обязателен, если `None` — метод возвращает `[]` сразу, как в текущей `_get_spectrum_ids`).
- **`sequence_contains` фильтр** (п.1.3, согласовано с разработчиком):
  - при `by="all"` → `EXISTS (SELECT 1 FROM identification ix WHERE ix.spectre_id = s.id AND ix.sequence LIKE ?)` (проверяет **любую** identification спектра, независимо от `is_preferred`/`tool_id`);
  - при `by="all_preferred"` → фильтр применяется к **той же** `i` (уже `INNER JOIN`-нутой preferred-идентификации любого инструмента): `AND i.sequence LIKE ?` (без отдельного `EXISTS`);
  - при `by="preferred_by_tool"` → аналогично, `AND i.sequence LIKE ?` на той же `i` (preferred для конкретного `tool_id`).
  - Значение параметра LIKE: `f"%{sequence_contains}%"`. Регистронезависимость обеспечивается стандартным поведением SQLite `LIKE` для ASCII (по умолчанию case-insensitive) — доп. `COLLATE NOCASE` не требуется, но добавить его явно в SQL ради явности и переносимости (`ix.sequence LIKE ? COLLATE NOCASE`).
  - Если `sequence_contains` пустая строка или `None` — фильтр не применяется вовсе (ни `EXISTS`, ни `AND ... LIKE`).
- `ORDER BY s.seq_no` (сохраняет текущий порядок из `_get_spectrum_ids`), `LIMIT ? OFFSET ?`.
- **Порядок SELECT-полей**: `s.*` (все колонки `spectre` как есть — `id, spectre_file_id, seq_no, title, scans, charge, rt, pepmass, intensity, mz_array, intensity_array, peaks_count, charge_array, charge_array_common_value, all_params`) плюс, если `need_ident`, алиасы `i.sequence AS sequence, i.canonical_sequence AS canonical_sequence, i.override_charge AS override_charge, i.isotope_offset AS isotope_offset`. Т.к. `s.*` уже не содержит полей с такими именами — конфликтов алиасов нет.
- Курсор построчного чтения: использовать паттерн из текущей `_iter_spectra_batched` (`self._execute(query, params)` → `cursor.description` → `cursor.fetchmany`) — но здесь батч задаётся снаружи через `limit/offset`, не через генератор. Реализация метода — обычный `self._fetchall(query, params)` с `LIMIT ? OFFSET ?` в самом SQL (это проще и достаточно, т.к. вызывающий код сам управляет пагинацией по батчам; отдельный async-генератор внутри Project не нужен — задача явно требует именно `limit/offset`-параметры метода).
- **Декомпрессия массивов**: для каждой строки батча — то же самое, что делает `get_spectrum_full` (используя уже импортированный в файле `decompress_array`): `mz_array`, `intensity_array`, `charge_array` (если не `None` — иначе оставить `None`); `all_params` — `json.loads` если не `None`.
- Возврат: `list[dict]`, пустой список если ничего не найдено (совместимо с текущим поведением "no matching spectra" в `export_mgf`).

**Примечание по производительности:** метод не хранит в памяти весь список id — только один батч (до `limit` строк со всеми decompressed-массивами). Пагинация через `LIMIT/OFFSET` в SQLite при относительно небольшом суммарном числе спектров (десятки/сотни тысяч на sf) приемлема; полноценный `WHERE id > last_id` keyset-пагинацию не делаем — не требуется требованием и не даёт выигрыша при упорядочивании по `seq_no` (не PK).

### 1.3. Уточнение по режиму `by="all"` и `need_ident`

Важный нюанс: при `by="all"` и `need_ident=True` спектр может **не иметь** preferred-идентификации вовсе (это нормальный кейс — сейчас `_get_preferred_identification` в этом случае просто возвращает `None`, и `_build_spectrum_params` работает без `ident`). Поэтому JOIN здесь обязан быть `LEFT JOIN`, а не `INNER JOIN` — иначе спектры без identification исчезнут из выдачи (регрессия). Если при этом ещё и `sequence_contains` задан — фильтр реализуется отдельным `EXISTS`-подзапросом (см. выше), а не через `AND i.sequence LIKE ?` на `LEFT JOIN`-нутой `i` (т.к. `i.sequence` может быть NULL для случая без identification, и семантика "хотя бы одна идентификация содержит подстроку" требует отдельной проверки, не завязанной на то, какая именно строка "выиграла" LEFT JOIN при нескольких identification на спектр — хотя `is_preferred=1` обычно уникален на (spectre_id, tool_id=NULL-агрегат)... для строгости используем во всех трёх режимах `by` единообразный подход: фильтрация всегда через `EXISTS`, когда `by="all"`; и через `AND i.sequence LIKE ?` на уже отфильтрованной по `is_preferred`/`tool_id` `i`, когда `by` — один из preferred-режимов, т.к. в этих случаях `i` в выдаче — это ровно та строка, которая должна быть проверена).

### 1.4. T2 — Core: переработка `mgf_export.py` под batch

**Файл:** `dasmixer-core/src/dasmixer/api/export/mgf_export.py`

Удаляются функции: `_get_preferred_identification`, `_get_spectrum_ids`, `_iter_spectra_batched` (не используется нигде за пределами файла — проверено, весь код только внутри `mgf_export.py`).

**`_build_spectrum_params(...)`**: сигнатура и тело **не меняются**. Единственная адаптация — `ident` теперь передаётся как **тот же самый** `spec_row` dict (т.к. `get_full_spectrum_for_export` возвращает identification-поля плоско, в том же dict, что и данные спектра), см. ниже про рефакторинг вызова.

Так как `_build_spectrum_params(spec_row, ident, ...)` ожидает `ident` отдельным dict с ключами `override_charge`, `canonical_sequence`, `sequence`, `isotope_offset` — а новый batch-метод кладёт их в тот же `spec_row` — в `_write_mgf_to_file` формируем `ident` как:
```python
ident = None
if need_ident and spec_row.get("sequence") is not None:
    ident = {
        "override_charge": spec_row.get("override_charge"),
        "canonical_sequence": spec_row.get("canonical_sequence"),
        "sequence": spec_row.get("sequence"),
        "isotope_offset": spec_row.get("isotope_offset"),
    }
```
(проверка на `spec_row.get("sequence") is not None` — эквивалент текущего `if rows: rows[0] else None`, т.к. при `by="all"` LEFT JOIN даёt `NULL` в этих полях, если preferred-идентификации нет).

**`_write_mgf_to_file(...)`** — новая сигнатура, batch-driven:

```python
async def _write_mgf_to_file(
    project,
    output_file,
    sf_ids: list[int],
    by: str,
    tool_id: int | None,
    need_ident: bool,
    write_offset: bool,
    write_spectra_charge: bool,
    write_seq: bool,
    seq_type: str,
    sequence_contains: str | None,
    replace_scans: bool = False,
    batch_size: int = _BATCH_SIZE,
) -> int:
    """Возвращает количество экспортированных спектров (для проверки 'no matching spectra')."""
    output_file.write("# Exported from DASMixer\n")
    total_written = 0
    offset = 0
    while True:
        batch = await project.get_full_spectrum_for_export(
            sf_ids=sf_ids, by=by, tool_id=tool_id, need_ident=need_ident,
            sequence_contains=sequence_contains, limit=batch_size, offset=offset,
        )
        if not batch:
            break
        batch_spectra = []
        for spec_row in batch:
            ident = None
            if need_ident and spec_row.get("sequence") is not None:
                ident = {
                    "override_charge": spec_row.get("override_charge"),
                    "canonical_sequence": spec_row.get("canonical_sequence"),
                    "sequence": spec_row.get("sequence"),
                    "isotope_offset": spec_row.get("isotope_offset"),
                }
            mz_arr = spec_row.get("mz_array")
            int_arr = spec_row.get("intensity_array")
            params = _build_spectrum_params(
                spec_row, ident, write_offset, write_spectra_charge, write_seq, seq_type,
                replace_scans=replace_scans,
            )
            charge_arr = spec_row.get("charge_array")
            if charge_arr is None:
                common_val = spec_row.get("charge_array_common_value")
                if common_val is not None and mz_arr is not None:
                    charge_arr = np.full(len(mz_arr), int(common_val))
            else:
                charge_arr = np.where(np.isnan(charge_arr), 0, charge_arr).astype(int)
            spectrum_dict = {"params": params, "m/z array": mz_arr, "intensity array": int_arr}
            if charge_arr is not None:
                spectrum_dict["charge array"] = charge_arr
            batch_spectra.append(spectrum_dict)
        if batch_spectra:
            mgf.write(batch_spectra, output=output_file)
            total_written += len(batch_spectra)
        offset += batch_size
    return total_written
```

Тело цикла по конкретному спектру (`params`/`charge_arr`/`spectrum_dict`) — переносится из старой `_write_mgf_to_file` без изменений логики, меняется только источник данных (`spec_row` теперь из batch-метода, а не из `get_spectrum_full` + отдельный `ident`).

**`export_mgf(...)`**: добавить параметр `sequence_contains: str | None = None`. Пробросить его во все 4 вызова `_write_mgf_to_file(...)`. Также убрать промежуточный вызов `spectrum_ids = await _get_spectrum_ids(...)` и связанную с ним проверку `if not spectrum_ids: continue` — вместо этого использовать возвращаемое из `_write_mgf_to_file` количество записанных спектров, и если 0 — считать unit пропущенным ("no matching spectra"), **но** файл на диске к этому моменту уже мог быть создан (для веток `gzip`/`none`/`zip_each` — `open()`/`gzip.open()` создаёт файл до начала записи). Чтобы сохранить корректное поведение "нет файла, если 0 спектров" (как сейчас — `continue` до открытия файла), нужно **сохранить предварительную проверку**: делать один "разведывательный" вызов `get_full_spectrum_for_export(..., limit=1, offset=0)` перед открытием файла, чтобы узнать, есть ли хотя бы один спектр — если нет, пропускаем unit без создания файла (как в текущем поведении). Это соответствует требованию "формат экспортируемых данных не должен меняться" (нет файлов с нулевым числом спектров).

Итоговая структура тела цикла по `units` в `export_mgf`:

if not probe:

    continue
base_name = f"{unit['base_name']}{ts_suffix}"
# ветки compression — вызывают _write_mgf_to_file(project, <file>, sf_ids, by, tool_id, need_ident,
#     write_offset, write_spectra_charge, write_seq, seq_type, sequence_contains,

```

**Валидация нового кода**: не менять формат MGF, не менять сигнатуру `export_mgf` для существующих параметров (только добавление нового опционального `sequence_contains`) — соответствует требованию "интерфейсы из export_mgf не должны меняться" (трактуется как "публичная сигнатура остаётся расширяемо совместимой", согласовано с разработчиком).

# ...

```

## 2. Задача C — Конфигурация PTM

### 2.1. Общая схема размещения файлов

Оба файла — `all_ptm_config.csv` и `import_ptm_renames.csv` — располагаются в `{app_dir}/ptm/`, где `app_dir = Path(typer.get_app_dir("dasmixer"))` (то же, что `AppConfig.get_config_path().parent`), т.е. на Linux — `~/.config/dasmixer/ptm/`.

**Новый модуль:** `dasmixer-core/src/dasmixer/api/ptm_config.py` — единая точка доступа к обоим файлам (загрузка/создание при отсутствии), используется и `seqfixer_utils.py`, и `IdentificationParser.get_ptm_renames`.

```python
"""PTM configuration: user-editable CSV files for FixedPTM defaults and
identification-parser PTM renames. Files live in {app_dir}/ptm/ and are
created from built-in defaults on first run if absent."""

from pathlib import Path
import csv
import typer


def get_ptm_config_dir() -> Path:
    d = Path(typer.get_app_dir("dasmixer")) / "ptm"

def load_ptm_config() -> list[dict]:
    """
    Читает all_ptm_config.csv (создаёт при отсутствии), возвращает список
    сырых записей dict: {"name", "attach_to" (list[str]|None), "mono_mass" (float|None),

    """
    path = _ensure_all_ptm_config_file()
    result = []
    with open(path, "r", encoding="utf-8") as f:
        for row in csv.DictReader(f):
            attach_raw = (row.get("attach_to") or "").strip()
            attach_to = attach_raw.split(";") if attach_raw else None

                "name": row["name"].strip(),
                "attach_to": attach_to,
                "mono_mass": float(mass_raw) if mass_raw else None,

                "default": (row.get("default") or "").strip().upper() == "Y",
            })

            parser_id: значение колонки "parser" в CSV (== registry name == tool.parser).
            is_terminal: если задан — фильтрует только terminal (True) или non-terminal (False)
                строки; если None — возвращает все строки данного parser_id (в порядке файла).

        Returns:
            dict[source, proforma], сохраняющий порядок строк файла (Python dict ordered).
            Дубликаты source (маловероятны) — последнее значение в файле побеждает.
        """
        from dasmixer.utils.ptm_config import load_ptm_renames

        result: dict[str, str] = {}
        for rec in load_ptm_renames():
            if rec["parser"] != parser_id:
                continue
            if is_terminal is not None and rec["is_terminal"] != is_terminal:
                continue
            result[rec["source"]] = rec["proforma"]
        return result
```

### 2.10. T13 — `SimpleTableImporter.field_to_proforma`

**Файл:** `dasmixer-core/src/dasmixer/api/inputs/peptides/table_importer.py`

Добавить атрибут класса и логику применения в `SimpleTableImporter`:

```python
class SimpleTableImporter(TableImporter):
    renames: ColumnRenames
    peptide_sheet_selector: dict | None = None
    field_to_proforma: str | None = None   # NEW: имя колонки (исходное имя, до remap_columns),
                                            # к которой применяется автозамена подстрок по
                                            # IdentificationParser.get_ptm_renames(self.PARSER_ID)

    def apply_ptm_renames(self, df: pd.DataFrame) -> pd.DataFrame:
        """
        Применяет последовательную замену подстрок (.replace) в колонке field_to_proforma
        согласно import_ptm_renames.csv для self.PARSER_ID (is_terminal=None — все строки,
        и terminal, и non-terminal, в порядке файла). Не изменяет df, если field_to_proforma
        is None или колонка отсутствует.
        """
        if self.field_to_proforma is None or self.field_to_proforma not in df.columns:
            return df
        if self.PARSER_ID is None:
            raise ValueError(
                f"{self.__class__.__name__}: field_to_proforma is set but PARSER_ID is None"
            )
        renames = self.get_ptm_renames(self.PARSER_ID, is_terminal=None)

        def _apply(value):
            if not isinstance(value, str):
                return value
            for source, proforma in renames.items():
                value = value.replace(source, proforma)
            return value

        df = df.copy()
        df[self.field_to_proforma] = df[self.field_to_proforma].apply(_apply)
        return df
```

**Порядок вызова** в `parse_batch` (в `TableImporter`/`SimpleTableImporter.parse_batch`, строки 350-388 текущего `table_importer.py`): применяется **после** `prepare_df`, **до** `transform_df` — т.к. `transform_df` в текущих подклассах (например, PLGS) может опираться на уже проставленные значения `sequence`, а `field_to_proforma` работает на исходных колонках. Изменить строку:
```python
sheet_df = self.prepare_df(sheet_df)
```
на
```python
sheet_df = self.prepare_df(sheet_df)
sheet_df = self.apply_ptm_renames(sheet_df)
```
(один вызов на весь sheet, аналогично `prepare_df` — до батчинга, не на каждый батч отдельно — не имеет значения для чистой поколоночной замены строк, но экономит один проход `apply_ptm_renames` не per-batch, а один раз).

### 3.1. T17 — `open_folder()` в `dasmixer-gui/src/dasmixer/gui/utils.py`

```python
def open_folder(path: str | Path) -> None:
    """
    Open a folder in the system file manager (cross-platform).

    Creates the folder if it does not exist. Uses os.startfile on Windows,
    'open' on macOS, 'xdg-open' on Linux.
    """
    import os
    import subprocess
    import sys

    directory = Path(path)
    directory.mkdir(parents=True, exist_ok=True)
    if sys.platform == "win32":
        os.startfile(str(directory))  # noqa: S606 (не доступно на Linux — тип-чекер/линтер может ругаться, см. plugins_view.py — уже есть прецедент)
    elif sys.platform == "darwin":
        subprocess.run(["open", str(directory)], check=False)
    else:
        subprocess.run(["xdg-open", str(directory)], check=False)
```
