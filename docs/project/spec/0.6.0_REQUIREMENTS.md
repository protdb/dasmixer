## Импорт проекта

Идея: в существующий проект должна быть возможность добавить полный набор данных из другого проекта с учетом внутренних зависимостей между данными и того факта, что идентификаторы в текущем виде могут пересекаться между разными проектами

Реализация:

Проекты рассматриваются как исходный (в который добавляются данные) и импортируемый (который импортируется).

Имеется специфика для отдельных сущностей

- сущности, которые можно объединить: tool, subset, protein, project_settings - настраиваются пользвоателем, если принимается решение объединить, то используются исходные сущности первого проекта. Таблицу protein всегда объединяем через INSERT IF NOT EXISIS, т.к. там не может быть задвоения уникального не цифрового ID
- сущности, которые только добавляются: sample, *_file, spectre, identification и т.д.: логика ниже

Сущности импортируются в систему поэтапно, с учетом взимосвязей по внешним ключам, т.е. сначала добавляются все sample, потом spectre_file, потом spectre, потом identifications и т.д.

При импорте модифицируем ID. Сначала получаем ммаксимальный ID в таблице исходного проекта, прибавляем это значение к величине ID в импортируемом проекте, вставляем с этим ID. В конце импорта всех данных таблицы изменяем значение последоватлеьности, чтобы избежать конфликта при вставке новых данных

Аналогично делаем при импорте связанных сущностей: для каждой таблицы помним это значение максимального ID исходного проекта - учитываем при вставке по foreign key

Для tool и subset - используем мэппинг ID

Опции объединения данных при импорте:
- объединять инструменты? Нет (все инструменты импортируемого проекта добавляются как новые) / by name / by parser (по умолчанию)
- объединять subset'ы? Да (по умолчанию) / Нет 
- обновить project settings? Да (project_settings импортируются как insert or update) / Нет (insert if not exists, по умолчанию)

### Производительность

PRAGMA synchronous = NORMAL на время импорта, потом вернуть FULL. Одна большая транзакция вместо построчных инсертов — это самое важное. PRAGMA cache_size = -65536 (64MB кэш). Вставка через ATTACH DATABASE 'db2.sqlite' AS db2 и прямой INSERT INTO ... SELECT FROM db2... — это на порядок быстрее, чем читать в память и писать через приложение, потому что всё происходит внутри одного процесса SQLite без сериализации данных. Соответственно, модификации ID производятся в рамках запроса

### API

случай крайне специфический относительно стандартных импортов, поэтому реализуем не через inputs, а как ImportProjectMixin с методом:
```python
def import_project(self, tool_match: Literal['name', 'parser'] | None = 'parser', subset_match: bool=True, project_settings_match: bool=False, status_callback: Callable[str, float] | None = None):
```

Где callback - функция, вызываемая между запросами на отдельные таблицы и позволяющая на GUI отобразить текущий статус задачи. str параметр - название обновляемой таблицы, float - доля готовности (процент выполненных операций над данными)

### CLI

Команда import_project, принимает на вход путь до нового проекта
