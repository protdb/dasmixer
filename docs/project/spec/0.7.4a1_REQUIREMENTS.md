# 0.7.4a1 Report overhaul

## Реструктурирование отчётов

Для report лежит сейчас отдельно - модуль с самим отчетом (тут: `dasmixer-core/src/dasmixer/api/reporting/reports`), а отдельно - формы отчётов (`dasmixer-gui/src/dasmixer/gui/reports/forms.py`)

Необходимо сделать новый субмодуль для используемых отчётов в dasmixer-core/src/dasmixer/reports и перенести связанное туда (при этом базовые классы остаются на своих местах)

Изменяется также сама струкутра отчётов. Отчеты в системе представляем в виде модуля:

```
reports
├── report_name:
│   ├── __init__.py
│   ├── report.py # основной код отчёта
│   ├── params.py # dataclass параметров 
│   └── form.py   # код формы отчёта
└── __init__.py
```

Здесь важный нюанс: form.py выносится отдельно. В рамках report.py необходимо делать проверку на способность импортировать GUI-компоненты. Т.е. если dasmixer-gui не установлен, возвращать необходимо None. Как это сделать? Необходимо продумать.

При этом должна оставаться возможность сделать (особенно для плагинов) возможность отчёта из одного файла, включающего report_form по умолчанию

также добавляется дополнитлеьный слой валидации и абстракции для параметров отчёта. Должен быть определен dataclass с параметрами. Он, в отличие от формы, не опционален. ReportForm должна возвращать его экземпляр, существующие отчёты должны принимать именно его на вход вместо просто словаря с параметрами. Сериализация для хранения в БД в json остаётся.

необходимо преобразовать существующие отчёты к этому формату.

## Именование отчётов

Сейчас у сгенерированного отчёта нет названия, он идентифицируется по дате, это неудобно. Требуется:
- Расширить структуру БД, добавить поле name в таблицу generated_reports с повышением project_version до 0.7.4
- В BaseReport добавляем:
  - параметр name_template
  - метод `get_report_name(self, params) -> str`
- в GUI на вкладке reports добавляем для отчёта поле Name format, позволяющее переопределить имя отчёта.

Для имени отчета должны быть допустимы подстановки значений из params (те самые параметры отчёта) через {param_name} (обработка через str.format в функции get_report_name).

Помимо параметров, также должны быть доступны две подстановки: {date} в формате ГГММДД и {time} в формате ЧЧ:ММ (где ЧЧ - время в 24х-часовом формате)

Также для параметров важно: если значение - список/кортеж, объединяем все его значения через "_"ю

При экспорте отчёта сохраняем в формате {report_type_name}_{report_name}, где первое - название отчёта (напр. Volcano Report), а второе - то самое название отчёта. Тут также нюанс, при сохранении из имени просто удалить символы, не поддерживающиеся в NTFS, в частности и в первую очередь двоеточия из формата времени

Шаблон имени, если изменён пользвоателем, также сохраняем в параметры отчёта

## Доработки страницы отчётов

- выпадающий список отчётов необходимо обновлять после завершения расчёта, показывая в нём тот отчёт, который был только что сгенерирован, чтобы для его просмотра не пришлось повторно генерировать.
- в этом же выпадающем списке вместо даты показываем новое поле report_name если не null (если null - показываем дату как сейчас)
- на форме настройки параметров отчёта добавляем кнопку "Save and generate", по нажатию котрой закрывается всплывающее окно параметров и запускается генерация отчёта
- при нажатии на export отображается новое всплывающее окно для настройки сохранения с параметрами:
  - Save path (путь с кнопкой Browse, которая открывает file picker)
  - Export (блок чекбоксов):
    - DOCX
    - HTML
    - XLSX: если выбран, доступен выпадающий список (Large tables only/All tables). Если выбран Large tables only, то выгружаются в Excel только те таблицы, которые не включаются в документ отчёта
  - Кнопки Export и Cancel

## Доработки шаблона отчёта

Меняем структуру шаблона. Перед таблицами и графиками оставляем только Report parameters. Параметры проекта и инструмента переносим в конец.

Для параметров проекта создаём "Белый список", выводим только следующие параметры:
- max_blast_accept
- max_blast_reject
- ion_types
- water_loss
- nh3_loss
- ion_ppm_threshold

- ignore_spectre_charges
- min_precursor_charge
- max_precursor_charge
- force_isotope_offset
- max_isotope_offset
- seq_criteria
- proteins_min_peptides
- proteins_min_unique_evidence
- lfq_enzyme
- lfq_min_peptide_length
- lfq_max_peptide_length
- lfq_max_cleavage_sites

Параметры инструментов при этом не меняются.
