# 0.7.3a3: Улучшение экспорта MGF, улучшение логики работы с PTM

## Улучшение производитлеьности экспорта MGF:

При экспорте MGF необходимо реализовать чтение и запись данных в batch вместо построчного экспорта. Для этого нужно:
- Добавить метод в spectra_mixin: get_full_spectrum_for_export, который будет также иметь набор параметров, соответствующий флагам на форме, а также limit/offsset
  - Если выбраны параметры, требующие чтения деталей идентификации, то в рамках этого метода выполняется JOIN с identification
  - Логика сохраняется, данные выводятся как `list[dict]`.
- Дорабатываем функционал экспорта MGF. Получаем batch'ем данные, преобразовываем,Ю записываем в файл.

В рамках этой задачи формат экспортируемых данных не должен меняться; интерфейсы из export_mgf не должныменяться.

## Дополньительные настройки экспорта MGF

Требуется добавить дополнительный фильтр Sequnece contains (строка) при экспорте MGF. Фильтр должен применяться на уровне БД, с помощью like в запросе get_full_spectrum_for_export. Очевидно, что при использвоании этого фильтра экспортируются только спектры, для которых есть хотя бы одна идентификация с этой подстрокой

Также требуется добавить на форме экспорта MGF поле File Suffix. Если не пустое, то к имени экспортируемого файла добавляется значение из этого поля. Также если заданный суффикс не начинается с "_", то между именем файла и суффиксом добавляется "_". Если установлен флаг добавлять к имени файла timestamp, то он добавляется после суффикса.

## Конфигурация PTM

Требуется добавить два конфигурационных файла, которые должны сохраняться рядом с файлом конфигураци (`~/.config/dasmixer/ptm).

- all_ptm_config.csv - в формате .CSV список возможных PTM для писка в БД. Должен содержать поля:
  - name
  - attach_to
  - mono_mass
  - n_term (фрормат: "Y"/"N", если пустое - то "N")
  - c_term (аналогично)
  - default (аналогичный формат)
- import_ptm_renames.csv: PTM renames для последовательностей при импорте
  - source
  - proforma
  - parser
  - is_terminal ("Y"/"N")

Строки из первого файла должны заменять логику константы PTMS в `dasmixer-core/src/dasmixer/utils/seqfixer_utils.py`. То есть из файла формируем массив FixedPTM-объектов. исключение: поле default, ПТМ со значением в нём в параметрах инструмента на вкладке peptides выбраны по умолчанию для перебора в последоватлеьности.

По умолчанию в этот файл конфигурации добавить существующие PTM как default, расширить за счёт файла: `/home/kirill/PycharmProjects/prepare_mgf_set/unimod_sites.csv`. Из этого файла мы берём только PTM с hidden==False и также схлопываем одинаковые PTM (в этом файле строки дублируются для разных сайтов).

import_ptm_renames требует более сложной логики, относящейсвия к парсерам.

Сейчас в парсерах (`dasmixer-core/src/dasmixer/api/inputs/peptides`, файлы `MQ_Evidences.py`, `PeptideShaker.py`, `PLGS.py`) немного по-разному реализована примерно одна и та же логика: замена названий ПТМ в исходных вариантах последовательности на допустимые в Proforma.

Файл должен собрать все вариации ptm_renames в рамках общей логики. Данные также собрать по текущим парсерам.

Получение списка модификаций для замены по конкретному парсеру из файла реализовать как staticmethod в IdentificationParser (`dasmixer-core/src/dasmixer/api/inputs/peptides/base.py`), с фильтром по terminal, возвращать как dict, где key=source, value=proforma

Реализовать стандартную логику замены подстрок в SimpleTableImporter, с указанием параметра field_to_proforma: str | None = None, где если поле не None, то применяется логика замены подстрок на уровне SimpleTableImporter вне метода transform_df. Это позволит упростить логику на уровне конкретных импортеров

Значения по умолчанию собрать из существующих парсеров.

Набор значений по умолчанию храним в исходном коде, при отсутствии файла в пути назначения - создаём при запуске, при наличии - читаем и создаём PTMS. алиасы читаем при инициализации парсера.
