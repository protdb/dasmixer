# 0.8.0a1 - пересмотр структуры вкладок GUI

В текущей реализации есть, помимо прочего, две вкладки: Peptides и Proteins. На каждой из них есть:
- Параметры запуска расчётов
- Кнопки для запуска процессов
- Табличное представление данных с возможностью отрисовки графиков

Из-за этого возникает путаница, особенно в части процессов, которые опираются на результаты друг друга - часть требует перезапуска, часть нет.

Поэтому требуется заменить их на две отдельные влкадки:
- Pipeline: параметры, процессы, результаты
- Data: три переключаемых TableAndPlotView без лишних элементов

В системе есть несколько процессов, не связанных с импортом, в штатном варианте порядок процессов такой:
- Match proteins: поиск совпадения последовательностей в белках для identifications
- Calculate Ion coverage: расчёт физических показателей пептида, соответствие спектру
- Select preferred: выбор оптимальных идентификаций, в том числе при наличии нескольких идентификаций на один спектр
- Calculate protein identification: вычисление идентификаций белков в образце на основании мэппинга пептидов
- Label-Free Quantification: расчёт относительных концентраций белков в образце
- Enrich protein data : обогащение записей о белках данными из UniProt

Самый тяжелый процесс сейчас - Calculate ion coverage, может занимать часы на больших проектах, остальное штатно выполняется быстрее. При этом порядок между Match proteins и ion coverage не столь принципиален и может быть изменён по желанию пользователя.

## Новая вкладка Pipeline

Общая концепция:
- Все настройки процессинга в одном месте
- Запуск всех (или части) процессов одной кнопкой
- Отчеты о завершенных запусках, включая статус (ошибка/нет ошибки) и специфический отчёт о состоянии проекта.

Т.е. вкладка состоит из следующих блоков:
- Global settings: блоки с настройками, не являющимися специфичными для инструментов с разбивкой по процессам (см. ниже)
- Tool settings: настройки, зависящие от инструмента, полный перенос секции tool settings с Peptides
- Pipeline: выбор порядка и настройка (см. ниже)
- Reports: результаты выполнения (см. ниже)

### Струкутра блока Pipeline

Представляет собой один ft.ReorderableListView, каждый элмент которого состоит из чекбокса (отображает включение этапа в рамках выполнения конвейера), названия этапа, краткого описания. Этапы:

| Этап                    | Описание                                                                                                                                                                                                                                                             |
|-------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Fragment match          | Claculate theoretical fragments for every identification and match it to the spectra. Enriches identification with PPM, Intensity coverage, Quality, LCRR etc. Optionally includes PTM recalculation, isotope offset lookover and charge correction.                 |
| Protein match           | Match identified sequences to proteins using BLAST-like nsearch algorithm. Optionally includes De Novo correction step if celected                                                                                                                                   |
| Preferred selection     | Check if identification sequence matched to spectre within configured thresholds. If there is more than one identification for a specrte, selects the best one based on given criteria. Only preferred identifications are considered as protein existence evidences |
| Protein identifications | Create a list of proteins identfied in samples based on preferred identifications as trusted evidences                                                                                                                                                               |
| UniProt KB Enrichment   | Enriche detected proteins with metadata from UniProtKB                                                                                                                                                                                                               | 
| LFQ claculation         | Claculate the label-free quantification values for every found protein in samples                                                                                                                                                                                    |
| Project data report     | Form the report depicting overall data condition in project after all calculations                                                                                                                                                                                   |

Внизу под списком должна быть кнопка Run pipeline. По нажатию запускаются последоватлеьно все перечисленные процессы с указанными пользвоателем в персой секции настройками.

Все шаги, кроме последнего, уже реализованы как процессы в системе и не требуют изменения. Исключение: запись результата в БД. Описана ниже.

Отображает параметры, использвоанные при запуске (сохраняются в таблице pipeline_run). Показывает просто в виде секций (global и по инструментам), список пролистываемый. ## Выполнение pipeline и сохранение результатов

При запуске pipeline создаётся запись в таблице pipeline_run, в которой фиксируется время начала, параметры расчётов на момент запуска, список задач. Создаётся со статусом Running

Список определяется по установленным чекбоксам процессов, порядок - по порядку следования в ReorderableListView. Выполняется в строго заданном порядке.

Для каждой задачи создаётся запись в process_run со статусом Running.

Если какой-то из этапов завершается с ошибкой, завершается выполнение процесса, ошибка фиксируется в process_run и статус становится Error, также статус устанавливается в Error для всего pipeline run

При открытии проекта проверяется наличие записей process_run/pipeline_run со статусом Running. Эти задачи переводятся в статус Error с текстом ошибки "App closed or crashed". В этом случае НЕ заполняется поле datetime_finished (ни у процесса, ни у пайплайна)

При успехе статус процесса записывается в OK, запускается следующий процесс (и создается запись в process_run). При успешном завершении всех процессов OK записывается в статус Pipeline

Также при всех завершениях (успех/ошибка) кроме закрытия приложения записывается datetime_finished в БД

### Хранение даты и времени

Хранится в БД как UTC timestamp, отображается как дата и время в текущей временной зоне

### Project API

Реализуется как PipelineMixin, работа с пайплайнами и задачами выполняется через dataclasses (аналогично другим dataclass'ам в ProjectMixin'ах)

Также в рамках Mixin'а реализуется метод `async def close_running_on_startup(self) -> bool:`, который реализует описанную выше логику закрытия пайплайнов при запуске приложения, и именно он должен вызываться при запуске.

Интерфейс реализуется в виде ContextManager'а, примерно так:

```python
with project.pipeline(pipeline_dataclass_object) as pipeline:
    for process in processes:
        with pipeline.process(process) as proc:
            try:
                # calculate
                proc.status = "OK"
            except Exception as e:
                proc.status = "Error"
                proc.error_description = e
                break
```
