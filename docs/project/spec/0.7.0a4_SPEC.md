## 1. Контекст и цели

`ManageSamplesView` (`dasmixer-gui/src/dasmixer/gui/views/manage_samples_view/`) деградирует по производительности на проектах с большим числом sample'ов из-за:

1. **N+1 SQL-запросов.** `SampleDataManager.refresh_all_fresh()` и `ManageSamplesView._rebuild_panels_from_cache()` вызывают `Project.get_sample_stats(sample_id)` (7 correlated subqueries) **в цикле по всем sample'ам** проекта.
2. **Отсутствия пагинации/фильтрации.** Все `ft.ExpansionPanel` для всех sample'ов строятся и живут в дереве Flet одновременно — при сотнях sample'ов это создаёт тысячи компонентов.
3. **Немедленной загрузки тела аккордеона.** Тело каждой панели (список файлов) фактически строится сразу при построении списка (`SampleViewPanel.build()` безусловно вызывает `_build_body()`, которая делает `get_sample_detail()`), а не при разворачивании.

Требуемый результат:

- Один SQL-запрос вместо N+1 для полного пересчёта статистики (см. `docs/review/sample_management_query.md` — запрос уже согласован и принят, дальнейшая оптимизация самого запроса — отдельная задача).
- Фильтры (имя / статус / subset / outlier) + пагинация (аналогично `BaseTableView`, с опцией "All") — реализуются **над уже полученным набором данных в памяти**, без дополнительных SQL-запросов на каждое применение фильтра/переключение страницы.
- Ленивая загрузка тела аккордеона: компоненты тела (кнопки, список файлов) создаются только при разворачивании и удаляются из дерева Flet при сворачивании; данные при этом кэшируются в памяти (при повторном открытии — без нового SQL-запроса).
- Шапка над списком (`UpdateRow`), логика выделения (`_selected_ids`, select all/deselect all) и массовые операции (`MassOperationsRow`) — **не меняются** по функционалу (см. п. 8).

## 3. Core: новый единый SQL-запрос статистики

### 3.1. Метод `get_all_samples_stats()`

Добавляется в `sample_mixin.py`, рядом с `get_sample_stats()` (который **не удаляется** — остаётся для точечного пересчёта одного sample, используется в `refresh_single()` и после точечных пользовательских действий над одним sample, как и сейчас).

```python
async def get_all_samples_stats(self) -> dict[int, dict]:
    """
    Return aggregated statistics for ALL samples in a single SQL query.

    Replaces the N+1 pattern of calling get_sample_stats() in a loop.
    Always computes for the whole project (no pagination/filtering here —
    see docs/review/sample_management_query.md for the rationale: LIMIT/OFFSET
    gives negligible speedup on this query, since aggregation must scan
    the identification table fully anyway).

    Returns:
        dict mapping sample_id (int) → stats dict with the same keys as
        get_sample_stats(): spectra_files_count, ident_files_count,
        identifications_count, preferred_count, coverage_known_count,
        protein_ids_count, empty_ident_files_count.
    """
    query = """
        WITH sf_counts AS (
            SELECT sample_id, COUNT(*) AS spectra_files_count
            FROM spectre_file
            GROUP BY sample_id
        ),
        if_counts AS (
            SELECT
                sf.sample_id,
                COUNT(*) AS ident_files_count,
                SUM(
                    CASE WHEN NOT EXISTS (
                        SELECT 1 FROM identification i WHERE i.ident_file_id = idf.id
                    ) THEN 1 ELSE 0 END
                ) AS empty_ident_files_count
            FROM identification_file idf
            JOIN spectre_file sf ON idf.spectre_file_id = sf.id
            GROUP BY sf.sample_id
        ),
        ident_counts AS (
            SELECT
                sf.sample_id,
                COUNT(*) AS identifications_count,
                SUM(CASE WHEN i.is_preferred = 1 THEN 1 ELSE 0 END) AS preferred_count,
                SUM(CASE WHEN i.intensity_coverage IS NOT NULL THEN 1 ELSE 0 END) AS coverage_known_count
            FROM identification i
            JOIN spectre s ON i.spectre_id = s.id
            JOIN spectre_file sf ON s.spectre_file_id = sf.id
            GROUP BY sf.sample_id
        ),
        protein_counts AS (
            SELECT sample_id, COUNT(*) AS protein_ids_count
            FROM protein_identification_result
            GROUP BY sample_id
        )
        SELECT
            smp.id AS sample_id,
            COALESCE(sfc.spectra_files_count, 0)     AS spectra_files_count,
            COALESCE(ifc.ident_files_count, 0)       AS ident_files_count,
            COALESCE(ifc.empty_ident_files_count, 0) AS empty_ident_files_count,
            COALESCE(ic.identifications_count, 0)    AS identifications_count,
            COALESCE(ic.preferred_count, 0)          AS preferred_count,
            COALESCE(ic.coverage_known_count, 0)     AS coverage_known_count,
            COALESCE(pc.protein_ids_count, 0)        AS protein_ids_count
        FROM sample smp
        LEFT JOIN sf_counts sfc     ON sfc.sample_id = smp.id
        LEFT JOIN if_counts ifc     ON ifc.sample_id = smp.id
        LEFT JOIN ident_counts ic   ON ic.sample_id = smp.id
        LEFT JOIN protein_counts pc ON pc.sample_id = smp.id
    """
    rows = await self._fetchall(query)
    return {int(row['sample_id']): dict(row) for row in rows}
```

Отличие от чернового варианта, обсуждённого ранее: убран `(SELECT COUNT(*) FROM tool)` из тела запроса (устранение 5-кратного `SCAN tool`, см. `docs/review/sample_management_query.md` п. 4.1.3) — `tools_count` по-прежнему получаем отдельным вызовом `get_tools_count()`, как и сейчас. Также убраны `name`/`subset_name`/`outlier`/`additions` из результата — эти поля уже есть в `Sample` из `get_samples()`, дублировать их в статистике незачем; метод возвращает **только числовые счётчики**, консистентно с форматом `get_sample_stats()`.

### 3.2. Метод `upsert_sample_status_cache_batch()`

Добавляется в `sample_mixin.py`, рядом с `upsert_sample_status_cache()`:

```python
async def upsert_sample_status_cache_batch(self, all_stats: dict[int, dict]) -> None:
    """
    Batch insert/replace cached stats for multiple samples in one executemany().

    Args:
        all_stats: dict mapping sample_id → stats dict (same shape as
                   get_all_samples_stats() / get_sample_stats() result).
    """
    from datetime import datetime, timezone
    now = datetime.now(timezone.utc).isoformat()

    rows = [
        (
            int(sid),
            int(stats.get('spectra_files_count', 0)),
            int(stats.get('ident_files_count', 0)),
            int(stats.get('identifications_count', 0)),
            int(stats.get('preferred_count', 0)),
            int(stats.get('coverage_known_count', 0)),
            int(stats.get('protein_ids_count', 0)),
            int(stats.get('empty_ident_files_count', 0)),
            now,
        )
        for sid, stats in all_stats.items()
    ]
    if not rows:
        return

    await self._executemany(
        """INSERT OR REPLACE INTO sample_status_cache
           (sample_id, spectra_files_count, ident_files_count,
            identifications_count, preferred_count, coverage_known_count,
            protein_ids_count, empty_ident_files_count, updated_at)
           VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)""",
        rows
    )
    # No save() here — caller decides when to save (consistent with
    # upsert_sample_status_cache()).
```

### 3.3. `SampleDataManager.refresh_all_fresh()` — переписать на единый запрос

Файл: `data_manager.py`. Заменить цикл на:

```python
async def refresh_all_fresh(self) -> tuple[list[Sample], dict[int, dict], int]:
    """Full recalculation of all samples (Update mode).
    Uses a single aggregated SQL query instead of N calls to get_sample_stats().
    Returns (samples, cached_stats, tools_count)."""
    samples = await self.project.get_samples()
    tools_count = await self.project.get_tools_count()
    all_cached = await self.project.get_all_samples_stats()
    await self.project.upsert_sample_status_cache_batch(all_cached)
    await self.project.save()
    return samples, all_cached, tools_count
```

## 4. Core: инвалидация кэша при добавлении файлов

Согласно ответу Developer — кэш сбрасывается **только при добавлении новых файлов** (spectra/identification), остальные случаи (удаление, изменения outlier/subset и т.д.) продолжают точечно пересчитываться через существующий `refresh_single_panel()`/`_refresh_single_stats_in_place()`, как и сейчас.

### 4.1. `spectra_mixin.py::add_spectra_file()`

```python
async def add_spectra_file(
    self,
    sample_id: int,
    format: str,
    path: str
) -> int:
    sample = await self.get_sample(sample_id)
    if sample is None:
        raise ValueError(f"Sample with id={sample_id} does not exist")

    cursor = await self._execute(
        "INSERT INTO spectre_file (sample_id, format, path) VALUES (?, ?, ?)",
        (sample_id, format, path)
    )

    spectra_file_id = cursor.lastrowid

    # Cache invalidation: a new spectra file changes spectra_files_count
    # for this sample — force recompute on next read.
    await self.invalidate_sample_status_cache(sample_id)

    await self.save()

    logger.info(f"Added spectra file: {path} (id={spectra_file_id}, sample_id={sample_id})")

    return spectra_file_id
```

### 4.2. `identification_mixin.py::add_identification_file()`

Аналогично — нужно определить `sample_id` через `spectre_file_id` (в самом методе `sample_id` напрямую не передаётся, только `spectra_file_id`):

```python
async def add_identification_file(
    self,
    spectra_file_id: int,
    tool_id: int,
    file_path: str,
    selection_field: str | None = None,
    selection_field_value: str | None = None,
) -> int:
    logger.debug(f"spectra_file_id: {spectra_file_id}, tool_id: {tool_id} file_path: {file_path}")
    cursor = await self._execute(
        "INSERT INTO identification_file (spectre_file_id, tool_id, file_path, selection_field, selection_field_value) VALUES (?, ?, ?, ?, ?)",
        (spectra_file_id, tool_id, file_path, selection_field, selection_field_value)
    )

    ident_file_id = cursor.lastrowid

    # Cache invalidation: a new identification file changes ident_files_count
    # (and potentially empty_ident_files_count) for the owning sample.
    row = await self._fetchone(
        "SELECT sample_id FROM spectre_file WHERE id = ?", (spectra_file_id,)
    )
    if row:
        await self.invalidate_sample_status_cache(int(row['sample_id']))

    await self.save()

    logger.info(f"Added identification file: {file_path} (id={ident_file_id})")

    return ident_file_id
```

### 4.3. Поведение после инвалидации

`invalidate_sample_status_cache()` (уже существует, `sample_mixin.py:406-411`) удаляет запись из `sample_status_cache` для данного `sample_id`. После этого:

- При следующем открытии `ManageSamplesView` — сэмпл попадёт в список `uncached_ids` (текущая логика `_load_data()`, строки 193-201 `manage_samples_view.py`) и будет пересчитан фоново через `_refresh_single_stats_in_place()` — **без изменений**, эта логика уже написана правильно и продолжает работать.
- Explicit "Update" по-прежнему пересчитывает всё одним запросом независимо от инвалидации отдельных записей.

Никакой дополнительной логики в GUI не требуется — импорт (`ImportHandlers`) уже вызывает `project.add_spectra_file()`/`project.add_identification_file()` напрямую, инвалидация происходит "бесплатно" внутри этих методов.

Файл: `update_row.py`. Текущий класс не имеет доступа к `project` — добавляем его в конструктор и два метода:

```python
class UpdateRow(ft.Container):
    def __init__(
        self,
        project: Project,
        on_update_clicked: Callable[[], Awaitable[None]],
        on_import_additional: Callable[[], Awaitable[None]] | None = None,
    ):
        super().__init__(padding=ft.padding.symmetric(horizontal=16, vertical=8))
        self.project = project
        self._on_update_clicked = on_update_clicked
        self._on_import_additional = on_import_additional

        self._min_proteins_field = ft.TextField(
            label="Min proteins", value="30", width=130,
            keyboard_type=ft.KeyboardType.NUMBER, dense=True,
            on_change=lambda e: self.page.run_task(self._save_thresholds) if self.page else None,
        )
        self._min_idents_field = ft.TextField(
            label="Min identifications", value="1000", width=170,
            keyboard_type=ft.KeyboardType.NUMBER, dense=True,
            on_change=lambda e: self.page.run_task(self._save_thresholds) if self.page else None,
        )
        # ... остальное без изменений ...

    async def load_thresholds(self) -> None:
        """Load persisted thresholds from project_settings. Call once after mount."""
        mp = await self.project.get_setting('manage_samples_min_proteins', '30')
        mi = await self.project.get_setting('manage_samples_min_idents', '1000')
        self._min_proteins_field.value = mp
        self._min_idents_field.value = mi
        if self.page:
            self._min_proteins_field.update()
            self._min_idents_field.update()

    async def _save_thresholds(self) -> None:
        """Persist current threshold values to project_settings on change."""
        await self.project.set_setting(
            'manage_samples_min_proteins', str(self._min_proteins_field.value or '30')
        )
        await self.project.set_setting(
            'manage_samples_min_idents', str(self._min_idents_field.value or '1000')
        )
```

`get_thresholds()` — без изменений (читает текущие значения контролов).

## 6. GUI: фильтры и пагинация над результатом в памяти

### 6.1. Общая архитектура загрузки данных

`ManageSamplesView` хранит после загрузки:

```python
self._samples: list[Sample] = []          # все sample'ы проекта (без фильтра)
self._all_stats: dict[int, dict] = {}      # sample_id → stats, из кэша или полного пересчёта
self._filtered_samples: list[Sample] = []  # результат применения текущих фильтров
self._page_samples: list[Sample] = []      # текущая страница (после пагинации)
```

Пайплайн:

1. `_load_data()` / `_on_update_clicked()` / `_on_mass_op_complete()` заполняют `self._samples` + `self._all_stats` (одним из способов: чтение `sample_status_cache` при обычной загрузке, либо `get_all_samples_stats()` при Update — см. п. 3).
2. `_apply_filters_and_pagination()` — **новый метод**, чистая функция над `self._samples`/`self._all_stats`, без обращений к БД:
   - Вычисляет `status` для каждого sample (те же формулы, что в `_build_sample_header()`, использующие `tools_count`/`min_proteins`/`min_idents`).
   - Фильтрует по имени (`LIKE '%term%'`, регистронезависимо — реализуется как `term.lower() in name.lower()` в Python), subset_id, outlier, статусу.
   - Сохраняет результат в `self._filtered_samples`.
   - Применяет пагинацию (`current_page`, `page_size`, либо "All") → `self._page_samples`.
3. `_rebuild_panels_from_page()` — строит `SampleViewPanel` только для `self._page_samples` (не для всех `self._samples`) — это и есть основной источник сокращения количества компонентов Flet в дереве одновременно.

### 6.4. `SamplesPaginationRow` — новый компонент

Файл: `dasmixer-gui/src/dasmixer/gui/views/manage_samples_view/pagination_row.py`.

Копирует визуальный/поведенческий паттерн пагинации `BaseTableView` (`page_size_dropdown`, `prev_button`, `next_button`, `pagination_text`), но:
- Список размеров страницы: `10, 20, 50, 100, All` (единственное дополнение к паттерну — пункт `"All"`).
- **Без обращения к БД** — вызывает переданный `on_page_changed` callback, который в `ManageSamplesView` пересобирает `self._page_samples` из уже отфильтрованного `self._filtered_samples` (без нового SQL).
- Текст пагинации — согласно ответу Developer, при выборе "All" `total_rows` не считается отдельным `COUNT(*)`, а берётся как `len(self._filtered_samples)` — тот же список, что уже в памяти.

```python
class SamplesPaginationRow(ft.Container):
    """Pagination controls — mirrors BaseTableView pagination, operates over in-memory list."""

    PAGE_SIZES = ["10", "20", "50", "100", "All"]

    def __init__(self, on_page_changed: Callable[[], Awaitable[None]]):
        super().__init__(padding=ft.padding.symmetric(horizontal=16, vertical=4))
        self._on_page_changed = on_page_changed

        self.current_page = 0
        self.page_size: int | None = 20  # None means "All"
        self.total_rows = 0

        self.pagination_text = ft.Text("No data", size=12, color=ft.Colors.GREY_600)
        self.page_size_dropdown = ft.Dropdown(
            label="Rows per page",
            options=[ft.DropdownOption(key=v, text=v) for v in self.PAGE_SIZES],
            value="20", width=140,
            on_text_change=self._on_page_size_change,
        )
        self.prev_button = ft.IconButton(icon=ft.Icons.ARROW_BACK, on_click=self._on_prev, disabled=True)
        self.next_button = ft.IconButton(icon=ft.Icons.ARROW_FORWARD, on_click=self._on_next, disabled=True)

        self.content = ft.Row(
            [self.pagination_text, ft.Container(expand=True),
             self.page_size_dropdown, self.prev_button, self.next_button],
            alignment=ft.MainAxisAlignment.SPACE_BETWEEN,
        )

    def slice(self, items: list) -> list:
        """Return the current page slice of items (or all items if page_size is None)."""
        self.total_rows = len(items)
        if self.page_size is None:
            self._update_text_all()
            return items
        start = self.current_page * self.page_size
        end = start + self.page_size
        self._update_text_paged()
        return items[start:end]

    def _update_text_paged(self):
        if self.total_rows == 0:
            self.pagination_text.value = "No data"
            self.prev_button.disabled = True
            self.next_button.disabled = True
            return
        start = self.current_page * self.page_size + 1
        end = min((self.current_page + 1) * self.page_size, self.total_rows)
        total_pages = (self.total_rows + self.page_size - 1) // self.page_size
        self.pagination_text.value = f"Showing {start}-{end} of {self.total_rows} (Page {self.current_page + 1} of {total_pages})"
        self.prev_button.disabled = (self.current_page == 0)
        self.next_button.disabled = (self.current_page >= total_pages - 1)

    def _update_text_all(self):
        self.pagination_text.value = f"Showing {self.total_rows} of {self.total_rows}"
        self.prev_button.disabled = True
        self.next_button.disabled = True

    async def _on_page_size_change(self, e):
        value = e.control.value
        self.page_size = None if value == "All" else int(value)
        self.current_page = 0
        await self._on_page_changed()

    async def _on_prev(self, e):
        if self.current_page > 0:
            self.current_page -= 1
            await self._on_page_changed()

    async def _on_next(self, e):
        self.current_page += 1
        await self._on_page_changed()
```

### 6.5. Формула статуса (перенос из `sample_panel.py` в общее место)

Формулы статуса OK/WARNING/ERROR уже реализованы в `_build_sample_header()` (`sample_panel.py:37-49`). Чтобы не дублировать логику между рендерингом заголовка и фильтром по статусу, выносим чистую функцию:

```python
# sample_panel.py (или новый module-level helper, например status_utils.py
# в том же пакете manage_samples_view/)

def compute_sample_status(stats: dict, tools_count: int, min_proteins: int, min_idents: int) -> str:
    """Return 'OK' | 'WARNING' | 'ERROR' for a sample given its stats and thresholds."""
    sf_count = stats.get('spectra_files_count', 0)
    if_count = stats.get('ident_files_count', 0)
    idents = stats.get('identifications_count', 0)
    proteins = stats.get('protein_ids_count', 0)
    empty_if = stats.get('empty_ident_files_count', 0)

    has_spectra = sf_count > 0
    has_ident = if_count > 0
    expected_if = tools_count * sf_count if sf_count > 0 else 0
    ident_ok = (expected_if == 0) or (if_count == expected_if)
    idents_ok = idents >= min_idents
    proteins_ok = (proteins == 0) or (proteins >= min_proteins)

    if not has_spectra or (has_spectra and not has_ident):
        return 'ERROR'
    elif has_spectra and has_ident and ident_ok and idents_ok and proteins_ok and empty_if == 0:
        return 'OK'
    else:
        return 'WARNING'
```

`_build_sample_header()` в `sample_panel.py` переиспользует эту функцию вместо дублирования формулы (рефакторинг без изменения видимого поведения). `_apply_filters_and_pagination()` в `manage_samples_view.py` вызывает её же для фильтрации по статусу.

### 6.6. `_apply_filters_and_pagination()` — полная логика

```python
async def _apply_filters_and_pagination(self):
    filters = self._filters_row.get_filters()
    min_proteins, min_idents = self._update_row.get_thresholds()

    name_term = filters['name'].lower()
    status_filter = filters['status']
    subset_filter = filters['subset_id']
    outlier_filter = filters['outlier']

    result = []
    for sample in self._samples:
        if name_term and name_term not in (sample.name or '').lower():
            continue
        if subset_filter != 'all' and str(sample.subset_id) != subset_filter:
            continue
        if outlier_filter == 'yes' and not sample.outlier:
            continue
        if outlier_filter == 'no' and sample.outlier:
            continue
        if status_filter != 'all':
            sid = int(sample.id or 0)
            stats = self._all_stats.get(sid) or {}
            status = compute_sample_status(stats, self._tools_count, min_proteins, min_idents)
            if status != status_filter:
                continue
        result.append(sample)

    self._filtered_samples = result
    self._page_samples = self._pagination_row.slice(result)
    self._pagination_row.update_controls_if_mounted()
    await self._rebuild_panels_from_page()
```

Вызывается:
- После `_load_data()`/`_on_update_clicked()`/`_on_mass_op_complete()` (заново, т.к. набор sample'ов/статистика изменились).
- Из `SamplesFilterRow.on_apply` (кнопка Apply Filters) — сбрасывает `current_page` в `0` перед пересчётом.
- Из `SamplesPaginationRow.on_page_changed` — **не** пересчитывает фильтры заново, а просто применяет новый `page_size`/`current_page` к уже посчитанному `self._filtered_samples` (без повторного прохода фильтрации, т.к. набор не изменился — только страница).

Для разделения этих двух путей `_apply_filters_and_pagination()` разбивается на:
- `_recompute_filtered()` — фильтрация `self._samples` → `self._filtered_samples` (тяжёлая часть, но всё равно чисто в памяти, без БД).
- `_recompute_page()` — `self._pagination_row.slice(self._filtered_samples)` → `self._page_samples` + `_rebuild_panels_from_page()`.

`SamplesFilterRow.on_apply` вызывает обе; `SamplesPaginationRow.on_page_changed` вызывает только вторую.

### 6.7. `_rebuild_panels_from_page()`

Заменяет текущие `_rebuild_panels()`/`_on_update_clicked()`-дублирование (сейчас код построения панелей повторяется трижды: `_load_data`, `_on_update_clicked`, `_rebuild_panels` — задача заодно устраняет дублирование, оставляя один метод):

```python
async def _rebuild_panels_from_page(self):
    if self._panels_list is None:
        return
    min_proteins, min_idents = self._update_row.get_thresholds()
    self._panels_list.controls.clear()
    self._panel_index.clear()
    self._panel_controls.clear()

    if not self._page_samples:
        self._panels_list.controls.append(self._build_empty_placeholder())
    else:
        for idx, sample in enumerate(self._page_samples):
            sid = int(sample.id or 0)
            stats = self._all_stats.get(sid) or {}
            panel_ctrl = SampleViewPanel(
                sample=sample, stats=stats, tools_count=self._tools_count,
                min_proteins=min_proteins, min_idents=min_idents,
                on_action=self._on_panel_action,
                on_selection_changed=self._on_selection_changed,
            )
            panel = await panel_ctrl.build()
            self._panel_index[sid] = idx
            self._panel_controls.append(panel_ctrl)
            self._panels_list.controls.append(panel)

    if self._panels_list.page:
        self._panels_list.update()
```

`_on_select_all()`/`_on_deselect_all()` (текущая логика выделения) продолжают работать **как есть** — они уже итерируются по `self._panel_controls`, которые теперь соответствуют **текущей странице**, а не всем sample'ам. Это следует явно задокументировать как небольшое изменение поведения: "Select All" выделяет только видимые на текущей странице sample'ы, не все sample'ы проекта. Это ожидаемо и соответствует типичному UX таблиц с пагинацией (тот же `BaseTableView` не имеет функции "select all across pages"). Массовые операции (Outlier/Drop file/Assign group/Delete) при этом продолжают работать через `self._selected_ids`, который не завязан на текущую страницу — если пользователь выделил sample'ы, затем сменил страницу без нажатия Select All/Deselect All заново, `_selected_ids` **сохраняет** ранее выбранные id (набор не сбрасывается при смене страницы/фильтров), только сами чекбоксы для sample'ов вне текущей страницы физически не отображаются, пока страница не сменится обратно.

## 7. GUI: ленивая загрузка аккордеонов

### 7.1. Проблема с API `ft.ExpansionPanel`

`ft.ExpansionPanel` (Flet 0.80.5, см. `flet/controls/material/expansion_panel.py`) не имеет собственного события разворачивания — событие `on_change` определено на уровне **`ft.ExpansionPanelList`**, а не отдельной панели:

```python
on_change: Optional[ControlEventHandler["ExpansionPanelList"]]
"""Called when an item of controls is expanded or collapsed.
The data property of the event handler argument contains the index
of the child panel (in controls) which triggered this event."""
```

Значит, слушать разворачивание/сворачивание конкретной панели можно только через `on_change` родительского `ft.ExpansionPanelList` — обработчик получает **индекс** панели в `controls`, а не сам объект. Реализация должна учитывать это ограничение API.

### 7.2. Новая логика `SampleViewPanel`

Файл: `sample_panel.py`. Меняется контракт: `build()` теперь строит **только заголовок** и пустое/placeholder тело; тело подгружается по требованию.

```python
class SampleViewPanel(ft.Container):
    def __init__(self, ...):
        ...
        self._body_cache: ft.Control | None = None  # cached built body, survives collapse
        self._detail_cache: list[dict] | None = None  # cached raw detail data from DB
        self._is_expanded: bool = False

    async def build(self) -> ft.ExpansionPanel:
        header_row = ft.Row([self._checkbox], spacing=4, vertical_alignment=ft.CrossAxisAlignment.CENTER)
        header_row.controls.append(_build_sample_header(...))

        self._expansion_panel = ft.ExpansionPanel(
            header=ft.ListTile(title=header_row),
            content=ft.Container(
                content=self._collapsed_placeholder(),
                padding=ft.padding.only(left=16, right=16, bottom=16),
            ),
            expanded=False,
            can_tap_header=True,
        )
        return self._expansion_panel

    def _collapsed_placeholder(self) -> ft.Control:
        """Lightweight placeholder shown while the panel is collapsed —
        avoids building the (potentially large) body tree until needed."""
        return ft.Container(height=0)

    async def on_expand(self) -> None:
        """Called by ManageSamplesView when this panel becomes expanded
        (via ExpansionPanelList.on_change). Builds the body lazily,
        using cached detail data if available (no new DB query on re-expand)."""
        if self._is_expanded:
            return
        self._is_expanded = True
        if self._body_cache is None:
            self._body_cache = await self._build_body()  # may hit DB (get_sample_detail) on first expand
        self._expansion_panel.content.content = self._body_cache
        self._expansion_panel.expanded = True
        if self._expansion_panel.page:
            self._expansion_panel.update()

    def on_collapse(self) -> None:
        """Called by ManageSamplesView when this panel becomes collapsed.
        Removes the body controls from the Flet tree (frees up rendering cost)
        while keeping self._body_cache / self._detail_cache in memory for instant reopen."""
        if not self._is_expanded:
            return
        self._is_expanded = False
        self._expansion_panel.content.content = self._collapsed_placeholder()
        self._expansion_panel.expanded = False
        if self._expansion_panel.page:
            self._expansion_panel.update()
```

`_build_body()` — существующий метод, без изменений по существу, кроме одного момента: первый вызов `self._on_action('get_detail', self._sample.id)` должен кэшироваться в `self._detail_cache`, чтобы повторное разворачивание (после сворачивания) **не порождало новый SQL-запрос** — используется `self._detail_cache` если он уже заполнен:

```python
async def _build_body(self) -> ft.Control:
    if self._detail_cache is None:
        self._detail_cache = await self._on_action('get_detail', self._sample.id)
    detail = self._detail_cache
    ... # остальной код без изменений, использует `detail` вместо повторного await
```

При операциях, которые меняют состав файлов sample'а (add/delete spectra file, add/delete ident file — уже существующие `_on_action` ветки в `ManageSamplesView`), `self._detail_cache` должен сбрасываться, чтобы следующее разворачивание перечитало актуальные данные:

```python
def invalidate_detail_cache(self) -> None:
    """Call after any operation that changes this sample's file tree,
    so the next expand re-fetches fresh detail data."""
    self._detail_cache = None
    self._body_cache = None
```

`ManageSamplesView._delete_spectra_file()`, `_delete_ident_file()`, `_add_spectra_file()`/`_do_add_identification_file()` — их `on_complete`/после-действия callback'и уже вызывают `refresh_single_panel(sample.id)`; в этот путь добавляется вызов `self._panel_controls[idx].invalidate_detail_cache()` перед пересборкой панели (см. п. 7.4).

### 7.3. `ManageSamplesView` — подписка на `ExpansionPanelList.on_change`

Файл: `manage_samples_view.py`, `_build_body()`:

```python
self._panels_list = ft.ExpansionPanelList(
    expand_icon_color=ft.Colors.BLUE_400,
    elevation=2,
    divider_color=ft.Colors.GREY_300,
```

```python
def _on_panel_expansion_changed(self, e: ft.ControlEvent):
    """ExpansionPanelList.on_change fires with e.data = index of the toggled panel.
    We must determine whether it was expanded or collapsed by reading the
    panel's current `expanded` flag AFTER the toggle (Flet updates it before
    firing on_change)."""
    try:
        idx = int(e.data)
    except (TypeError, ValueError):
        return
    if idx < 0 or idx >= len(self._panel_controls):
        return
    panel_ctrl = self._panel_controls[idx]
    is_now_expanded = self._panels_list.controls[idx].expanded
    if is_now_expanded:
        self.page.run_task(panel_ctrl.on_expand)
    else:
        panel_ctrl.on_collapse()
```

**Важное техническое уточнение для реализации:** необходимо на этапе реализации экспериментально проверить, содержит ли `e.data` индекс корректно и в каком порядке Flet обновляет `expanded`/вызывает `on_change` (до или после фактического тумблинга) в используемой версии 0.80.5 — при необходимости можно рассчитывать "новое" состояние `expanded` как инверсию текущего сохранённого в `panel_ctrl._is_expanded`, вместо чтения `self._panels_list.controls[idx].expanded` напрямую, если оно окажется ненадёжным. Это единственный пункт спецификации, требующий проверки на реальном UI в процессе реализации (пометить как "проверить на практике" в декомпозиции, задача 7.2).

### 7.4. Обновление точечных операций для сброса `_detail_cache`

Файл: `manage_samples_view.py`. В местах, где сейчас вызывается `refresh_single_panel(sample.id)` после операций, меняющих файлы (`_delete_spectra_file`, `_delete_ident_file`, `_add_spectra_file` → `on_complete`, `_do_add_identification_file` → `on_complete`), перед пересборкой панели нужно инвалидировать её detail-кэш:

```python
async def refresh_single_panel(self, sample_id: int) -> None:
    ...
    idx = self._panel_index.get(sample_id)
    if idx is not None and idx < len(self._panel_controls):
        self._panel_controls[idx].invalidate_detail_cache()
    await self._refresh_single_stats_in_place(sample_id, save_cache=True)
```

(Внутри `_refresh_single_stats_in_place()` уже вызывается `self._panel_controls[idx].build()`, который при развёрнутом состоянии панели должен снова вызвать `on_expand()`, чтобы тело перестроилось со свежими данными — это уточнение реализации, panel должен помнить `_is_expanded` и при `build()` вызванном после `invalidate_detail_cache()`, если панель была развёрнута, сразу инициировать пересборку тела.)
