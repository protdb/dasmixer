# 0.7.4a2: оптимизация производительности для ion_matching и De novo correction в части работы с PTM

Требуется изучить текущую логику и выполнить доработки, не влияющие на результат, но повышающие производительность.

## Перестроение логики многопоточности при ion_matching

Текущая проблема: в логике sub-batches возникает регулярная ситуация, когда один из sub-batch'ей работает дольше других, при этом остальные ядра процессора простаивают. Необходимо реализовать логику очереди и вместо небольших sub-batch использвоать логику очереди с небольшими чанками. Её нужно как следует продумать, как это лучше реализовать, при этом выполняя периодическую запись в БД и периодические commit'ы, чтобы не раздувать до безумия WAL-файл и не вызывать конфликтов чтения/записи при работе с БД

## Оптимизации protein match

Сейчас есть ряд неоптимальных моментов при поиске белков, особенно при de novo correction и save substitution. Нужны следующие изменения логики:

- поиск выполняется последовательно по чанкам, при этом в один чанк могут попадать одни и те же последовательности, инициализация поиска также занимает время.
