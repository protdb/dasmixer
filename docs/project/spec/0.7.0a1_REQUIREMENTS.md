# 0.7.0a1, работа со значениями абсолютной концентрации

## Импорт дополнительной информации об образцах

Необходимо реализовать импорт дополнительной информации об образцах.

На представлении manage samples в верхней части добавляем кнопку "import additional data".

По нажатию открывается выбор файла, поддерживаем xlsx, csv.

После выбора читаем с помощью pandas. Открываем диалог с выпадающим списком select sample column: в выпадающем спике - перечень столбцов файла (df.columns), по умолчанию выбрана первая.

рядом с выпадающем списком - кнопка Prewiev. Показываем пересечение между файлом и таблицей sample в три столбца: sample name, file (содержит галочки), project (также галочки). Подсвечиваем цветом: зеленые - образцы. которые есть и в файле и в БД; желтым: есть только в БД, нет в файле; красным: есть в файле, нет в БД

если есть хотя бы один "зеленый" образец, внизу страницы делаем активной кнопку "import". Образцы из исхондого файла, которых нет в проекте, игнорируются. образцы в проекте, для которых нет данных в файле, пропускаются.

Загрузку НЕ делаем как Batch, обрабатываем образцы поштучно.

Если additionals != null у образца, делаем update и сохраняем совмещенный словарь с перезаписью значений.

При заливке каждый ряд в dataframe превращаем в словарь python и его как json сохраняем в поле sample.additionals в проекте.

В manage samples в блок описания образца (заголвок expansionPanel) также добавляем дополнительный показатель additionals, показывается как символ чекбокса: если в таблице null или пустой объект, то: `☐`, если есть хоя бы одно значение: `☑`.

Если у хотя бы одного образца есть additionals, то те образцы, у которых их нет, отмечаются как имеющие предупреждение. Если нет ни у одного, на режим предупреждения не влияет.

## LFQ и расчёт абсолютных концентраций

Для LFQ-концентраций возможен переход от относительных к абсолютным показателям через дополнительный параметр: концентрацию общего белка или концентрацию отдельного специфического белка.

С точки зрения пользовательского интерфейса нам нужны на вкладке Proteins в секции LFQ:
- чекбокс Abs. concentrations
- рядом с ним кнопка set references:

по кнопке set references открывается окно с набором параметров:
- dropdown: "Total protein field"
- dropdown: "Reference protein field"
- text "Reference protein ID" (по умолчанию: `P02768`)
- checkbox: use default concentrations (default value: false)
- number: "Default reference value" (=40.0)
- number: "Default total protein value" (=75.0)
- note: "Concentrations should be given in g/l! LFQ method depends on reference type: for emPAI and NSAF it's recommended to use Total protein while iBAQ and Top3 perform best with reference protein. If both values are given, the most suitable is used" (фразу нужно скорректировать с т.з. грамотности, но не сути)

Где dropdown формируется из всех возможных ключей в additionals образцов

Логика примерно следующая:

```python
import json

headers = set()

all
additionals = await project._execute('SELECT additionals from sample')

for add in all_additionals:
    j = json.loads(add)
```

Этот код можно улучшить и оптимизировать, он описывает именно логику работы с полученем заголовков.

Также в выпадающих списка должно быть допустимо и выбрано по умолчанию пустое значение, если так, то поле не учитывается.

Все задаваемые параметры сохраняются в project_settings. 

### Оценка и корректировка логики LFQ

Здесь необходимо посмотреть внимательно на встроенный модуль sempai: `dasmixer-core/src/dasmixer/api/calculations/proteins/sempai`

Описание общего случая логики работы выбранных алгоритмов есть здесь: `docs/project/INTERNAL_EXAMPLES/LFQ_abs.md`

Т.е. необходимо провалидировать, что во всех случаях концентрации рассчитываются корректно - это первый момент; второй момент: доработать так, чтобы при наличии обоих значений, для алгоритма выбиралось оптимальное.

Также необходимо доработать алгоритм расчёта Top3 - алгоритм должен выдавать null если для белка в образце < 3 пептидов.

При расчёте абсолютной концентрации (стоит галочка, сконфигурирован хотя бы один параметр) выполняется расчёт концентрации как в mol/l, так и в g/l.

Концентрация, задаваемая пользвоателем, считается в g/l

### Сохранение результата расчета концентрации и отображение

Создаём мигрцию БД! В protein_quantification_result переименовывем текущее поле abs_value в abs_value_mol, добавляем поле abs_value_gl (real).

С учётом миграции, меняем значение версии проекта (не приложения! см. versions.py) на 0.7.0.

Дорабатываем текущий алгоритм сохранения квантификации: перед сохранением данных по образцу, удаляем для него не все данные квантификации, а только те, которые рассчитаны с тем же значением algorythm. Если ранее был посчитан empai, а теперь отдельно посчитан iBAQ - данные не должны теряться.

### Отображение и настройки

При построении графиков по белкам на вкладке proteins добавляем ещё один параметр для выбора (поле выбора LFQ метода): value: rel, g/l, mol/l. Также добавляем выпадающий список multiplier для умножения величины: позволяет выбрать для величины при отображении множитель, чтобы получить результат, соответственно, в микрограммах, милиграммах, нанограммах и по аналогии для молей. Применяется только к абсолютным величинам.

Для отчётов создаём комплексный компонент в `dasmixer-gui/src/dasmixer/gui/components/report_form.py`: LFQSelector, который состоит из выпадающего списка (тип LFQ) и radio rel, g/l, mol/l - в отчёт возвращает tuple: LFQ, rel_value/abs_value_gl/abs_value_mol (название поля, из которого нужно получить данные). Используем его в текущих расчётах.
