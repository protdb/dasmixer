Алгоритм расчёта уже есть (тут: `dasmixer-core/src/dasmixer/api/calculations/spectra/quality_calculations.py`), расчёт внедрён в функцию match_predictions и возвращаемый ей datalass MatchResult (`dasmixer-core/src/dasmixer/api/calculations/spectra/ion_match.py`)

Задача:

- добавить в струкутру БД в таблицу identifications значение Quality. Увеличиваем в связи с этим значение PROJECT_VERSION до 0.7.1
- GUI: для tool в preferred_settings на вкладке пептидов добавляем параметр Quality threshold в preferred settings. Значение по умолчанию: 0.25. Сохраняем в project setting вместе с остальными параметрами
- При расчёте покрытия ионами сохраняем quality из match_predictions в это новое поле БД
- Расчёт preferred (Select preferred): учитываем показатель quality_threshold вместе с остальными (если для идентификации значение ниже указанного, то не устанавливается в preferred)


## PTM и Quality

Выполняются доработки SQEFixer (`dasmixer-core/src/dasmixer/api/calculations/ppm/seqfixer.py`) и pipeline в `dasmixer-core/src/dasmixer/api/calculations/spectra/identification_processor.py`

- match_predictions выполняется для исходной последоватлеьности до вызова seqfixer
- если значение quality >= quality_threshold, то перебор PTM не выполняется, ограничиваемся перебором charge, isotope_offset
- если quality < quality_threshold - перебираем PTM и потом isotope_offset для вариантов модифицированой последовательности с PPM > limit
- Исключение: при наличии unlocalized PTM в последовательности не делаем match_predictions перед SEQFixer
- Если мы посчитали match_predictions для последовательности и получили от SeqFixer результат без отличий по последовательности (нет перебора PTM, только локализация), то используем исходный расчёт, не выполняем match_predictions ещё раз.
 

Идея в том, что при качественной разметке спектра высокий PPM выван скорее всего isotope offset'ом, в то время как PTM может исправить плохую разметку

## Сохранение дополнитлеьных данных

В табилцу identifications при расчёте покрытия добавляем два поля:
- override_pepmass: величина, которую вернул SEQFixer, NULL если isotope_offset отсутствует
- source_sequence: последовательность пептида до перебора модификаций, NULL если не была изменена
- has_ptm: наличие PTM в последовательности (определяем по  sequence != canonical_sequence)

Указанные выше поля должны отображаться в таблице. при этом Quality должно быть видно в таблице по умолчанию

Также - преобразования на уровне dataframe:

Переименовываем поля charge, pepmass, по умолчанию делаем скрытыми. добавляем вычисляемые поля: final_charge, final_pepmass, их показываем по умолчанию.

Логика за этими полями почти идентичная и заключается в следующем:

final_charge - тот заряд, который реально использован при расчёте данных: override_charge если не равен null (учитываем, что работаем с pandas dataframe на основе таблицы в SQLite, делаем корректные проверки на NaN и None). Если величина override_charge есть и не null (NaN, None) - отображаем её, показываем за ней в строке символ ♻ и делаем tooltip через tooltip_df: f'Source: {charge}'

Для final_pepmass логика аналогичная, но помимо исходной величины pepmass показываем isotope_offset

Также в tooltip для sequence при не пустом source_sequence добавляем с новой строки 'Source: {source_sequence}' (отображать значок ♻ для последовательностей не надо)

В заголовке таблицы переименовываем:
charge -> Source charge
pepmass -> Source pepmass
final_charge -> Charge
final_pepmass -> Pepmass

Также стоит прописать для всех столбцов человекочитаемые заголовки, где этого сейчас нет. Переписываем по текущему образцу.

## Очистка данных coverage

Вкладка peptides, actions section, в том же ряду, где save settings, добавляем красную кнопку clear calculations.

По нажатию показываем модальное окно с описание процедуры и последствий (текст придумай сам) и логикой защиты: две кнопки: Cancel, Confirm + чекбокс "I am sure". Кнопка Confirm неактивна пока пользвоатель не установит чекбокс.

Действия по Confirm затрагивают таблицу Identifications:

- везде, где не пустое значение source_sequence - приравниваем sequence к source_sequence
- удаляем все данные, заполняемые при вычислении ion_coverage, а также поле is_preferred, везде null. также очищаем поле ppm.
