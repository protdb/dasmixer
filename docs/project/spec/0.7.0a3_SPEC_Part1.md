## 1. Контекст

Форма параметров инструмента (`ToolSettingsSection`, вкладка Peptides) сейчас отображает все контролы плоским списком без визуальной группировки и без блокировки зависимых полей. Требуется:

1. Перегруппировать форму на 4 визуальных блока.
2. Добавить блокировку контролов по чекбоксам верхнего блока.
3. Добавить два новых флага в `tool.settings`: `trust_ppm` и `recalculate_ptms` (default `True`), с соответствующей логикой в core-пайплайне расчёта ion coverage.
4. Переименовать лейбл `Use Leucine Combinatorics (I/L)` → `I/L Combinatorics` (ключ в `tool.settings` не меняется — `leucine_combinatorics`).

Все обсуждённые с Developer решения зафиксированы в разделе 3 (UI) и разделе 4 (Core logic).

## 3. UI — форма параметров инструмента

### 3.1. Новая структура формы

Карточка инструмента (`_build_tool_card`) перестраивается в 4 блока, разделённых тонкой линией сверху (`ft.border.only(top=ft.BorderSide(1, ft.Colors.GREY_300))`), без общей рамки вокруг каждого блока. Заголовок блока — `ft.Text(..., size=13, weight=ft.FontWeight.W_500, color=ft.Colors.GREY_700)`, кроме верхнего блока (без заголовка).

Секции **не сворачиваются** (без `ExpansionTile`/аккордеона) — всегда видимы полностью, меняется только `disabled`-состояние контролов внутри.

#### Блок 1 — верхний, без подзаголовка

Четыре чекбокса, расположенные по два в строке (`ft.ResponsiveRow` или два `ft.Row` по 2 элемента):

```
Row 1: [ Trust all identifications ]   [ Trust PPM ]
Row 2: [ Use protein ID from file  ]   [ Recalculate PTMs ]
```

- `Trust all identifications` — существующий `ignore_criteria`.
- `Trust PPM` — **новый** чекбокс, ключ `trust_ppm`, default `False`. Не блокирует ничего (см. п. 3.2).
- `Use protein ID from file` — существующий `use_protein_from_file`.
- `Recalculate PTMs` — **новый** чекбокс, ключ `recalculate_ptms`, default `True`.

#### Блок 2 — "Preferred settings:"

Заголовок `Preferred settings:` + линия сверху. Содержит (порядок как в текущей форме, без изменений состава):
- `Max PPM`, `Min Score`, `Min ion Coverage` (одна строка)
- `Min peptide length`, `Max peptide length` (одна строка)
- `Min Top-10 peaks covered`, `Min ions covered`, `Min spectrum peaks` (одна строка)
- `De novo correction`

#### Блок 3 — "PTM"

Заголовок `PTM` + линия сверху. Содержит:
- `Max PTM combinations`
- `Select PTMs...` (кнопка + отображение выбранных, без изменений)

#### Блок 4 — "Protein search"

Заголовок `Protein search` + линия сверху. Содержит:
- `Min protein identity`, `I/L Combinatorics` (переименованный лейбл, ключ `leucine_combinatorics` без изменений)
- `Match Correction Criteria` (4 чекбокса как сейчас)
- `Save AA Substitutions`

### 3.2. Блокировка контролов по чекбоксам заголовка

Правила (только визуальная блокировка через `disabled=True`; значения контролов **сохраняются** в `tool.settings` независимо от состояния блокировки — п. 9 ответов Developer):

| Чекбокс (Блок 1) | Блокирует |
|---|---|
| `Trust all identifications` (`ignore_criteria`) | Все контролы Блока 2 (Preferred settings) |
| `Use protein ID from file` (`use_protein_from_file`) | Все контролы Блока 4 (Protein search) |
| `Recalculate PTMs` (`recalculate_ptms`) | Все контролы Блока 3 (PTM) — **логика инвертирована**: блокировка происходит когда флаг **установлен** (см. текст требований: "Recalculate PTMs: если установлен, блокирует PTM") |
| `Trust PPM` (`trust_ppm`) | Ничего не блокирует |

Реализация: `on_change` хендлер на каждом из трёх управляющих чекбоксов, который проставляет `disabled` соответствующим контролам блока и вызывает `.update()` на контейнере блока (или на каждом контроле). Начальное состояние `disabled` при построении карточки (`_create_tool_controls` / `_build_tool_card`) должно быть выставлено сразу согласно загруженным значениям (а не только по `on_change`).

Технически удобно сгруппировать контролы каждого блока в список при построении (`self._preferred_block_controls`, `self._ptm_block_controls`, `self._protein_block_controls` — либо хранить как список внутри `controls` под служебным ключом, например `controls['_preferred_controls']`), чтобы единообразно проставлять `disabled`.

## 4. Core — логика "Trust PPM" и "Recalculate PTMs"

### 4.1. Trust PPM

**Смысл:** если для идентификации в БД уже сохранено значение `ppm` (пришло из файла импорта идентификаций, см. `v0.7.0a2`/`v0.7.0a3` changelog про `ppm`-маппинг у PowerNovo2/MQ/PLGS), и включён `trust_ppm`, то это значение не пересчитывается — используется как есть.

**Затронутые вычисления при `trust_ppm=True` и исходном `ppm is not None`:**
- `ppm` — берётся из БД, не пересчитывается.
- `theor_mass` — пересчитывается **только если у спектра отсутствует `charge`** (т.е. когда для расчёта нечем было бы оперировать). Если `charge` спектра присутствует — `theor_mass` также не пересчитывается (берётся консистентно с исходным ppm — рассчитывается из `sequence` один раз, без сканирования вариантов).
- `override_charge` — аналогично: пересчитывается (устанавливается) **только при отсутствии charge у спектра**; если charge есть — `override_charge = charge` спектра, без сканирования.
- `isotope_offset` — принудительно `0` (без сканирования офсетов).
- Для расчёта `intensity_coverage` / `ions_matched` / `ion_match_type` / `top_peaks_covered` — используется сразу оригинальная `sequence` без вызова `SeqFixer.get_ppm()` charge/isotope/PTM-перебора — аналог текущей ветки "no override" в `process_single_ident()` (строки 152-159 текущего кода).

**Если `trust_ppm=True`, но `ppm is None`** (в БД для этой идентификации ppm не был сохранён при импорте) — обработка идёт **как обычно** (полный пересчёт через `SeqFixer.get_ppm()`, включая charge/isotope/PTM enumeration), то есть `trust_ppm` не имеет эффекта для записей без исходного ppm.

**Не влияет на `protein_map.py`** (partial BLAST match, `SeqFixer.get_matched_ppm()`) — там логика остаётся без изменений (ответ Developer на вопрос 3).

### 4.2. Recalculate PTMs (default `True`)

**Смысл:** когда флаг **выключен** (`recalculate_ptms=False`), `SeqFixer` не должен перебирать новые PTM-комбинации на основе `attach_to`-сайтов из `ptm_list` (текущее поведение — `_collect_ptm_sites()` строит кандидатов от `canonical_split`, т.е. от последовательности без модификаций, и затем `_iter_ptm_combos()` перебирает их комбинации). Вместо этого:

- Модификации, уже позиционированные в исходной ProForma-строке (`sequence`), остаются зафиксированными как есть (не удаляются, не заменяются, не переставляются).
- Charge-override и isotope-offset сканирование **остаются активными** — просто без PTM-переборов на каждом шаге сканирования.
- **Нюанс с unlocalized-модификациями (`?`-нотация)**: если в исходной последовательности присутствуют *непривязанные* (unlocalized) модификации, то **только они** перебираются по допустимым сайтам (существующий механизм `_expand_unlocalized()`). Новые PTM-кандидаты, которых вообще не было в исходной последовательности, не добавляются.

**Реализация — минимальный подход (согласовано с Developer, вопрос 8):**

Добавить в `SeqFixer.__init__()` новый параметр:

```python
def __init__(
    self,
    ptm_list: list[FixedPTM],
    max_ptm: int,
    target_ppm: float,
    override_charges: tuple[int, int],
    max_isotope_offset: int,
    isotope_mode: IsotopeMode = "13C",
    force_isotope_offset_lookover: bool = False,
    max_ptm_sites: int = 10,
    unallocated_only: bool = False,   # NEW
) -> None:
    ...
    self.unallocated_only = unallocated_only
```

Логика ветвления — в `get_ppm()` (строка ~465, вызов `_collect_ptm_sites`):

```python
if self.unallocated_only:
    ptm_sites = []  # do not enumerate new attach_to-based positions
else:
    ptm_sites = _collect_ptm_sites(canonical_split, self.ptm_list)
```

Важно: при `unallocated_only=True` модификации, уже присутствующие в исходной последовательности на **фиксированных** позициях (не unlocalized), не должны передаваться в `_iter_ptm_combos` как варьируемые — они должны быть закреплены как часть базовой структуры `canonical_split`/`params`, что уже соответствует поведению `_split_and_strip()` (существующие мод-теги сохраняются в `split`, просто не участвуют в комбинаторике, если `ptm_sites=[]`).

**Обработка unlocalized-модификаций при `unallocated_only=True`:** остаётся без изменений — вызывается в `process_single_ident()` веткой `if '?' in sequence: positioned_variants = _expand_unlocalized(sequence, fixer.ptm_list)`. Эта ветка **уже** не пересекается с `_iter_ptm_combos()` (условие `if not seq_results.override` — только когда `SeqFixer.get_ppm()` не нашёл override через charge/isotope/PTM enumeration). При `unallocated_only=True` (`ptm_sites=[]`) `_iter_ptm_combos` будет перебирать только 0 внутренних PTM + терминальные варианты, что корректно ведёт к тому, что `seq_results.override` либо будет `None`, либо будет содержать только терминальные варианты — в обоих случаях ветка `_expand_unlocalized` для unlocalized-последовательностей сработает как обычно.

**Не влияет на `protein_map.py`** (`SeqFixer.get_matched_ppm()`, `extra_ptms`) — оставляем как есть (ответ Developer на вопрос 7). `unallocated_only` не передаётся в вызовы `SeqFixer` внутри `map_proteins()`.

**`process_single_ident()`** — добавить параметры `trust_ppm: bool = False`, `existing_ppm: float | None = None`. Новая ветка в начале функции:

```python
def process_single_ident(
    fixer: SeqFixer,
    params: IonMatchParameters,
    fragment_charges: list[int],
    sequence: str,
    pepmass: float,
    mz_array,
    intensity_array,
    mgf_charge: int | None = None,
    selection_criteria: str = "intensity_percent",
    trust_ppm: bool = False,          # NEW
    existing_ppm: float | None = None,  # NEW
) -> dict:
    if trust_ppm and existing_ppm is not None:
        # Trust the ppm value from the imported identification file.
        neutral = calculate_theor_mass(sequence)
        if mgf_charge is not None:
            charge = mgf_charge
            theor_mass = neutral
        else:
            # No spectrum charge available — recompute a working charge from ppm.
            # (fallback: derive charge from fixer.override_charges range using best abs_ppm)
            ...
        match_result = match_predictions(
            params=params, mz=mz_array, intensity=intensity_array,
            charges=fragment_charges, sequence=sequence,
        )
        return {
            "sequence": sequence,
            "ppm": existing_ppm,
            "theor_mass": theor_mass,
            "override_charge": charge,
            "isotope_offset": 0,
            "intensity_coverage": match_result.intensity_percent,
            "ions_matched": match_result.max_ion_matches,
            "ion_match_type": match_result.top_matched_ion_type,
            "top_peaks_covered": match_result.top10_intensity_matches,
        }
    # ... existing logic unchanged below
```

Примечание для разработчика: при отсутствии `mgf_charge` (нет заряда спектра) и `trust_ppm`-ветке нужно определить `charge`, чтобы посчитать `theor_mass`/`override_charge` — конкретный способ выбора заряда в этом крайнем случае (например, перебор `fixer.override_charges` и выбор charge с минимальным `abs_ppm` относительно `existing_ppm`) реализуется на усмотрение разработчика; главное требование — не делать полное PTM/isotope сканирование, только charge-подбор.

## 6. Тестирование (ручное)

1. Открыть проект, инструмент без `trust_ppm`/`recalculate_ptms` в `tool.settings` (старый проект) — форма должна показать `Trust PPM=False`, `Recalculate PTMs=True` (default), Блок3 (PTM) — заблокирован (т.к. `recalculate_ptms=True` → блокирует PTM согласно правилу "если установлен, блокирует PTM").
2. Включить `Trust all identifications` — Блок2 (Preferred settings) визуально блокируется; сохранить настройки, перезагрузить проект — состояние блокировки восстанавливается.
3. Включить `Use protein ID from file` — Блок4 (Protein search) блокируется.
4. Выключить `Recalculate PTMs` — Блок3 (PTM) разблокируется (инверсная логика).
5. Импортировать идентификации с исходным `ppm` (PowerNovo2/MQ/PLGS), включить `Trust PPM`, запустить "Calculate Ion Coverage" — убедиться, что для идентификаций с непустым `ppm` в БД значение не изменилось после пересчёта, `isotope_offset=0`.
6. С `Trust PPM=True` для идентификации без исходного `ppm` (None) — убедиться, что расчёт идёт как обычно (полный пересчёт).
7. Выключить `Recalculate PTMs`, запустить Ion Coverage на идентификациях с ProForma-модификациями на фиксированных позициях — убедиться, что новые PTM-варианты не перебираются (сравнить с результатом при включённом флаге на тех же данных).
8. С `Recalculate PTMs=False` и последовательностью, содержащей unlocalized-модификацию (`?`), — убедиться, что `_expand_unlocalized()` по-прежнему перебирает варианты позиционирования этой конкретной модификации.
9. Убедиться, что `protein_map.py` (Protein Search на partial BLAST matches) работает без изменений независимо от состояния `trust_ppm`/`recalculate_ptms`.
10. Проверить обратную совместимость `pipeline.py` и `dasmixer-cli calculate` — команды должны выполняться без ошибок (дефолтные значения новых параметров).
