## 0. Краткое содержание

Релиз вводит три импортируемых поля в таблицу `identification`:

- `fdr` REAL (nullable) — False Discovery Rate
- `e_value` REAL (nullable) — e-value
- `q_value` REAL (nullable) — q-value

В отличие от полей `quality`/`lcrr` (0.7.1/0.7.2), эти поля **импортируемые**, а не расчётные: они заполняются при импорте файла идентификаций (через `ColumnRenames`, опционально) и **не** вычисляются в пайплайне Ion Coverage. Следствия:

- `add_identifications_batch` (INSERT) — пишутся.
- `put_identification_data_batch` (UPDATE расчётных полей) — **не трогаем**.
- `clear_calculations` (сброс расчётных полей) — **не трогаем**; FDR/e-value/q-value **переживают** Clear Calculations.
- `identification_processor.py` (батч-воркер Ion Coverage) — **не трогаем**.
- `IdentificationWithSpectrum` (датакласс для расчёта) — **не трогаем**.

Дополнительно для **FDR** (только FDR, не для e-value/q-value) вводятся два фильтра «не более заданного»:

1. **Preferred-настройки инструмента** — `Max FDR` в Block 2 карточки инструмента. Применяется **только к normal-пулу** `get_idents_for_preferred` (не к trusted-пулу, симметрично `min_quality`/`min_lcrr`). **NULL-проход:** идентификации с `fdr IS NULL` проходят фильтр всегда (FDR — не расчётная величина, может отсутствовать и это не ошибка). Условие: `(i.fdr IS NULL OR i.fdr <= ?)`. Дефолт: `0.01`, диапазон валидации `[0, 1]`.

2. **Табличный фильтр** на вкладке Peptides — `Max FDR`. Применяется к `get_joined_peptide_data`/`count_joined_peptide_data` через `_build_peptide_filter_conditions`. **Строгая семантика** (симметрично `min_quality` в таблице): при заданном пороге идентификации с `fdr IS NULL` **отбрасываются** — условие `(id.fdr IS NOT NULL AND id.fdr <= ?)`. Чтобы увидеть строки без FDR — поле фильтра оставляют пустым (фильтр не применяется). Дефолт: пусто (фильтр отключен).

`e_value` и `q_value` — только отображаемые колонки, без фильтров.

> **Скоуп задачи — только инфраструктура.** Настройка конкретных парсеров (PowerNovo2, MQ_Evidences, PLGS, PeptideShaker и др.) на передачу этих полей через `ColumnRenames` в данном релизе **не выполняется** — выполняется отдельно/позже. Ни один из существующих парсеров пока не задаёт `fdr`/`e_value`/`q_value` в `ColumnRenames`, поэтому после релиза поля в БД будут `NULL` до тех пор, пока парсеры не будут настроены.

## 1. Решения по уточняющим вопросам (согласованы с разработчиком)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Скоуп парсеров | **Только инфраструктура.** Поля добавляются в `ColumnRenames` (опциональные), БД, GUI. Настройка конкретных парсеров под эти поля — отдельная задача, не в этом релизе. |
| 2 | Дефолт `max_fdr` в Preferred-настройках | `0.01`. Диапазон валидации `[0, 1]`. Формат хранения может зависеть от инструмента (доля `[0,1]` или проценты `[0,100]`) — валидация ограничена `[0, 1]`, т.к. дефолт `0.01` = 1% подразумевает хранение как долю; конкретные парсеры сами приводят значение к единому формату при настройке. |
| 3 | NULL-проход в табличном фильтре `max_fdr` | **Нет.** Чтобы пропустить строки без FDR — пользователь оставляет поле фильтра пустым (фильтр не применяется). При заданном пороге NULL-строки отбрасываются (строгая семантика, симметрично `min_quality` в таблице). |
| 4 | Область `max_fdr` в Select Preferred | Только **normal**-пул (`get_idents_for_preferred`). Для **trusted**-пула (`get_all_idents_for_preferred`, флаг `ignore_criteria`/"Trust all") фильтр не применяется — симметрично `min_lcrr`/`min_quality`. |
| 5 | SELECT'ы preferred-выбора | В `get_idents_for_preferred`/`get_all_idents_for_preferred` добавляется **только `i.fdr`** (для WHERE-фильтра и консистентности конкатенации пулов). `e_value`/`q_value` туда **не добавляются**. Все три поля добавляются в `get_joined_peptide_data`/`count_joined_peptide_data` и в bulk INSERT `import_project_mixin`. |

## 4. Интеграционная проверка (после реализации всех слоёв)

> Поскольку ни один парсер в этом релизе не настраивается на передачу FDR/e-value/q-value, для проверки с реальными значениями нужно либо временно подправить парсер вручную (вне коммита), либо проверить на NULL-значениях и через прямой SQL-`UPDATE`.

1. **Миграция:** открыть существующий проект версии `0.7.2` в GUI → диалог обновления схемы → `project_metadata.version` становится `0.7.3`; колонки `fdr`/`e_value`/`q_value` присутствуют в `identification`.
2. **Схема нового проекта:** создать новый проект → колонки присутствуют с типом `REAL`, nullable.
3. **Импорт (NULL-путь):** импортировать файл идентификаций любым существующим парсером → в БД `fdr`/`e_value`/`q_value` = `NULL` (т.к. парсеры не настроены) → ошибок нет.
4. **Импорт (значимый путь, ручная проверка):** временно задать `fdr="FDR"` в `ColumnRenames` парсера + подготовить тестовый файл с колонкой `FDR` → импорт → в БД `identification.fdr` = значения из файла. После проверки откатить изменение парсера (не коммитить).
5. **Clear Calculations:** выполнить `Clear Calculations` → `fdr`/`e_value`/`q_value` **остаются** (не сбрасываются, в отличие от `quality`/`lcrr`).
6. **Preferred-настройки — сохранение:** открыть карточку инструмента → изменить `Max FDR` на `0.05` → `Save settings` → перезагрузить → значение `0.05` сохранилось.
7. **Preferred-настройки — валидация:** ввести `1.5` → `Save settings` → ошибка `"Max FDR must be in [0, 1]"`.
8. **Select Preferred с max_fdr:** задать `Max FDR = 0.99` для инструмента без `Trust all` → запустить `Select Preferred` → normal-пул содержит строки с `fdr IS NULL` или `fdr <= 0.99`; строки с `fdr > 0.99` не становятся preferred.
9. **Trust all:** для инструмента с `Trust all identifications` → `Max FDR` не влияет (trusted-пул участвует целиком).
10. **Таблица Peptides — колонки:** через gear-диалог включить `FDR`, `e-value`, `q-value` → колонки видны со значениями (`NULL` отображается пусто). По умолчанию колонки скрыты.
11. **Таблица Peptides — табличный фильтр Max FDR:** ввести `0.01` в `Max FDR` → таблица показывает только строки с `fdr <= 0.01` (NULL-FDR **отбрасываются**); очистить поле → видны все строки, включая NULL-FDR.
12. **Импорт проекта:** импортировать проект 0.7.3 в проект 0.7.3 → значения `fdr`/`e_value`/`q_value` переносятся. Импорт проекта 0.7.2 в проект 0.7.3 → отказ (version guard), пока старый проект не мигрирован.
