## 1. Экспорт через CLI

Реализовать возможность экспорта через CLI:
- Новая команда `export`, дублирует функционал вкладки Export в GUI за вычетом простановки флагов
- Подкоманды:
  - `system` (полный системный экспорт, не делаем выбор устанавливаемых флагов)
  - `joined` с флагами:
    - `--all` (выгрузка всех данных)
    - `--sample` (флаг sample details в GUI)
    - `--idents` (флаг identifications)
    - `--proteins` (флаг protein identifications)
    - `--protein-stats` (флаг protein statistics)
    - `--format=(xlsx|csv)` (выбор формата файла)
    - `--per-sample` (флаг one file per sample, по умолчанию `False`)
  - `mgf` с флагами:
    - `--sample` (образец, один или несколько; если отсутствует, выгружается для всех)
    - `--mode=(all|preferred)` (режим: все, только preferred)
    - `--tool={tool}` — работает только с флагом `preferred`, в связке — аналог radio "All preferred by tool" в GUI
    - `--compress=(no|gz|zip|zip-per-file)` — режим сжатия файлов при экспорте
  - `mztab` с флагами:
    - `--title` — заголовок (поле header на форме экспорта)
    - `--description` — описание (поле description на форме экспорта)
    - `--lfq-method`
    - `--sample` (аналогично MGF)

## 2. Режим работы с readonly-файлами

Требуется добавить при инициализации `Project` флаг `initialize: bool = True`, который
управляет логикой инициализации БД в конструкции `with Project(path=...)` для доступа
на чтение и решения задач, не требующих изменения данных.

Проект должен корректно открываться и читаться, если права доступа к файлу проекта
подразумевают возможность чтения, при этом не требовать инициализации; не должно
возникать ошибки `project not initialized`.

При работе с GUI: проверять при открытии проекта права. Если проект readonly — подсвечивать
это в интерфейсе (детали UI-индикации не уточнены, требуют отдельного обсуждения перед
реализацией).
