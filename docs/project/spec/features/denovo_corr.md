# Улучшение алгоритма De Novo correction и AA substitutions

Общая концепция и цели:
- Уход от текущей логики I/L combinatorics к однократному преобразованию БД белков для первичного поиска -> повышение эффективности для (iso)leucine-rich пептидов
- Исправление типовых ошибок De Novo в секвенировании по списку вместо открытого поиска с перебором
- Несколько этапов поиска с разными условиями и разными параметрами фильтрации.

## Выгрузка во временные файлы

npysearch работает с текстовыми файлами, даже при вызове самой библиотеки происходит создание временных .fasta-файлов. Поэтому первым этапом предлагается создание двух файлов выгрузки белковой билиотеки:

выгружаем во временную папку: {tmp_dir}/peptide_match/project_name_stem/{datetime}. эта папка создаётся в заданной в настройках временной папке для обычных (не large) файлов.

В неё выгружаются два файла:

- proteins.fasta - выгрузка белковой библиотеки
- proteins_lic.fasta - та же библиотека с полной заменой L->I в последовательностях (только если хотяя бы для одного инструмента есть флаг I/L Combinatorics)

Библиотеку последовательностей при этом (в формате dict {protein_id: protein sequence} оригинальную из памяти не выгружаем, она ещё понадобится.

## Поиск уникальных последоватлеьностей и создание временных файлов

На первом этапе мы делаем чтение уникальных канонических последовательностей из БД для инструмента:

```sql
select * from 
             (select canonical_sequence, count(*) as cnt, group_concat(id) as idlist, min(abs(ppm)) as min_ppm 
                from identification GROUP by canonical_sequence where tool_id = ?)
         where min_ppm <= ?
```
подстановки: tool_id, min_ppm. min_ppm - значение max_ppm или max_denovo_correction_ppm для случаев когда используется denovo_correction

список последовательностей также сохраняем в fasta_file в формате st1_plain_{tool_id}.fasta. По пути:
- Преобразуем L->I по всей БД (если стоит флаг I/L combinatorics)
- Пропускаем последовательности, которые состоят из одной буквы (GGGGGGGGG и пр.)
- Пропускаем последовательности, в которых есть сегменты повторов одной и той же буквы больше заданного лимита. Лимит убираем в настройки (не затрагивая GUI пока): max_amino_repeats_in_seq=6

записи в файле формируем в виде:
```
>{idlist}
{canonical_sequence}
```

## Stage1: первичный поиск

Выполняем поиск с npysearch.blast() с условием identity=1.0

Найденные на этом этапе последовательности - точные совпадения. Процессинг для них:

idlist (QueryId в результатах npy.blast) разделяем через split по запятой.

Если использован режим I/L combinatorics - получаем из сохранённого выше словаря последовательностей по protein_id и номеру начальной аминокислоты.

Запись результатов этого этапа в БД делаем через пул до protein_mapping_batch_size идентификаций, при накоплении или при завершении - записываем в БД через executemany и последующий checkout (project.save(checkpoint=True))

также если есть флаг de novo correction или AA substitution - храним в памяти как set все QueryId, для которых получены результаты.

Записываем в таблицу peptide_match минимум информации:
- matched_sequence
- protein_id
- identification_id
- identity
- substitution (=0)

# Stage2: straight de novo correction

Этот этап выполняется только при наличии флага de novo correction.

Создаём новый промежуточный файл последовательностей: st2_straight_corr_{tool_id}.fasta.

Создаём два файла:
- st2_simplecorr_{tool_id}.fasta
- st3_opencorr_{tool_id}.fasta

Для каждой последовательности из файла st1... мы выполняем следующие действия:
- проверяем, была ли найдена последовательность в первой итерации, если была - пропускаем
- выполняем комбинаторику вариантов подстановки:
  - GG -> N
  - GA -> Q
  - AG -> Q
- 

---
```SQL
select * from (select canonical_sequence, min(abs(ppm)) as min_ppm, count(*) as cnt from identification where tool_id = ? group by canonical_sequence) where min_ppm < ? order by tool_id, cnt desc
```

Здесь второй "?" - max_ppm или max_denovo_correction_ppm для случаев когда используется denovo_correction

Сортировка по cnt позволяет отработать последовательности наиболее часто встречающиеся первыми.

Из этого списка сразу удаляем пептиды, не соответствующие дополнитлеьным критериям:
- Последоватлеьность состоит из одной буквы (GGGGGGGGG и пр.)
- Длина повтора одной и той же аминокислоты в последоватлеьности больше лимита (лимит пока хардкодим и станавливаем в 6: GGGGGGGAR не пройдёт).

Создаём временные файлы:
- FASTA-библиотека на основе таблицы protein. Если для хотя бы одного инструмента установлен флаг I/L combinatorics, делаем ещё одну FASTA-выгрузку с полной заменой I->L и выгрузку последовательностей делаем также с заменой везде I->L
- список уникальных канонических последовательностей в виде FASTA-файла. Для инструментов с I/L combinatorics - при экспорте делаем корректировку I->L

### Stage 1: поиск по полному совпадению с I/L combinatorics 

Выполняем поиск с npysearch сразу по всем, на этом этапе строго устанавливаем identity=1.0. Сразу обрабатываем эти результаты поиска:

- При включенных I/L combinatorics находим по protein_id в БД исходную последовательность безка и берём из него соответтвующий по начальному/конечному индексу фрагмент, если он не равен исходной последовательности в БД - сохраняем его версию в matched_sequence. ppm и параметры спектра при этом неизменные.
- Создаём новый промежуточный файл, который содержит только не найденные "в лоб" последовательности и готовимся работать с ним.

### Stage 2: Перебор стандартных замен

Этот этап выполняется только при наличии флага de novo correction.

Создаём новый список последовательностей, для которых применяем правила замен остатков.
При этом в список пускаем только последовательности с min_ppm <= max_ppm проекта
(эти замены не влияют на массу, нет смысла обрабатывать последовательности с высокой ошибкой по PPM, допускаемой denovo_correction_ppm)
- GG -> N
- GA -> Q
- AG -> Q

Строгое ограничение: не более 10 вариантов замен на одну последовательность. Создаётся новый файл перепоиска, в который вносятся только модифицированные последовательности, сохраняются варианты исходной последовательности.

Выполняется поиск с этой корректировкой, результаты сохраняются с привязкой: protein_id, source_sequence, found_sequence, identity. это результат "чистого" de novo correction, мы его сохраняем пока во временный файл для работы со спектром, но отдельно не процессируем.

Создаём ещё один файл с последоватлеьностями, которые не были процессированы на этом этапе.

### Stage 3: Перебор со сниженной точностью

Для этого этапа есть сложное условие: `(Установлен флаг De Novo correction ИЛИ флаг Save AA substitution) И (в параметрах инструмента protein_identity < 1.0)`.

Выполняем для оставшихся последовательностей поиск с identity, заданным в параметрах.

Дополняем результаты предыдущего этапа с сохранением identity
