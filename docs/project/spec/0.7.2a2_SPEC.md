# 0.7.2a2 — Specification

**Версия релиза:** `0.7.2a2` (устанавливается разработчиком при сборке — агент не меняет `versions.py`)
**PROJECT_VERSION (схема БД):** `0.7.2` (**не повышается** — расширяется существующая миграция `0.7.2`)
**Источник требований:** `docs/project/spec/0.7.2a2_REQUIREMENTS.md`
**Статус:** готов к реализации

---

## 0. Краткое содержание

Релиз вводит показатель **Unconfirmed PTMs** в пайплайн Ion Match, по аналогии с уже реализованным в `0.7.2a1` показателем **LCRR**: расчёт **уже есть** (поле `MatchResult.unconfirmed_ptms`, функция `calculate_unconfirmed_ptms` в `quality_calculations.py`) → нужно провести значение через схему БД → сохранение при расчёте Ion Coverage → фильтр `Max Unconfirmed PTMs` в Preferred settings инструмента → учёт в Select Preferred → отображение колонкой `Unconfirmed PTMs` в таблице Peptides (**скрытой по умолчанию**).

**Unconfirmed PTMs** — количество PTM в последовательности, не подтверждённых ни одним совпавшим фрагментным ионом (`seq_ptms - max_frag_ptm`, см. `_get_ptm_amount`/`calculate_unconfirmed_ptms`). Целое число `>= 0`. Если в последовательности нет PTM — возвращается `0` (уже учтено в расчёте, отдельной обработки не требует). Значение `0` также пишется в БД без изменений (никакой специальной трактовки «0 = не подтверждено» на уровне записи нет).

**Отличия от 0.7.2a1 (LCRR), зафиксированные разработчиком:**
1. **Версия проекта не повышается.** `PROJECT_VERSION` остаётся `"0.7.2"`. Миграция `0.7.2` в `migrations.py` **расширяется** вторым `ALTER TABLE` в том же SQL-блоке (не создаётся новая запись).
2. Т.к. пара тестовых проектов у разработчика уже имеет `project_metadata.version = '0.7.2'` (миграция с `lcrr` уже применена в них), для них подготовлен отдельный **SQL-скрипт отката** (раздел 6), который вручную возвращает версию на `'0.7.1'`, чтобы при следующем открытии в приложении расширенная миграция `0.7.2` отработала полностью (добавила и `lcrr`, и `unconfirmed_ptms`, если `lcrr` уже есть — `ALTER TABLE ... ADD COLUMN lcrr` в откате не выполняется повторно, колонка предварительно удаляется).
3. **Фильтр Preferred — инвертированная семантика.** В отличие от `min_quality`/`min_lcrr` (больше — лучше, `>=`), для `unconfirmed_ptms` используется **`max_unconfirmed_ptms`** с условием **`<=`** (чем меньше неподтверждённых PTM — тем лучше; фильтр «не более N»).
4. **В таблице Peptides колонка добавляется, но не входит в `default_columns`** — остаётся скрытой по умолчанию (в отличие от `LCRR`, которая была добавлена в `default_columns`). Причина — таблица уже перегружена колонками, показанными по умолчанию.
5. `has_ptm` — не связан с данной задачей, трогать не нужно (это отдельное поле "есть ли PTM в итоговой последовательности", булево).

> Работы по расчёту `unconfirmed_ptms` **не требуется** — задача полностью "проводочная", аналогично 0.7.2a1.

## 1. Решения по уточняющим вопросам (согласованы с разработчиком)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Как расширять миграцию `0.7.2` | Не создаём новую запись в `MIGRATIONS` — дополняем SQL существующей записи `"version": "0.7.2"` вторым `ALTER TABLE ... ADD COLUMN unconfirmed_ptms INTEGER;`. `PROJECT_VERSION` не меняется, остаётся `"0.7.2"`. |
| 2 | Откат для тестовых проектов | Готовится SQL-скрипт отдельно (не применяется автоматически кодом приложения) — см. раздел 6. Выдаётся разработчику в чат после написания спецификации. |
| 3 | Направление фильтра Preferred | Параметр `max_unconfirmed_ptms` (не `min_...`). SQL: `AND i.unconfirmed_ptms IS NOT NULL AND i.unconfirmed_ptms <= ?`. Семантика: "не более N неподтверждённых PTM". |
| 4 | NULL-обработка при ошибке расчёта | По аналогии с `quality`/`lcrr`: **`None`** в error-fallback `process_identificatons_batch()`. |
| 5 | Табличный фильтр в Peptides | Не добавляется — только колонка, отображение через `get_joined_peptide_data`, фильтрация только через Preferred settings инструмента (симметрично `lcrr`). |
| 6 | Видимость колонки по умолчанию | Колонка **не входит** в `default_columns` — скрыта по умолчанию, доступна через gear-диалог выбора столбцов. |
| 7 | Версия приложения (`APP_VERSION`) | **Не трогаем** — разработчик управляет версией сборки самостоятельно. |

## 2. Текущее состояние (контекст для исполнителя)

### 2.1 Расчёт `unconfirmed_ptms` — уже реализован, трогать не нужно

- `dasmixer-core/src/dasmixer/api/calculations/spectra/quality_calculations.py`:
  - `_get_ptm_amount(sequence: str) -> int` — подсчитывает количество PTM в последовательности (через `parse()` + n_term/c_term модификации).
  - `calculate_unconfirmed_ptms(matches: list[FragmentMatch], sequence: str) -> int`:
    ```python
    def calculate_unconfirmed_ptms(matches: list[FragmentMatch], sequence: str) -> int:
        seq_ptms = _get_ptm_amount(sequence)
        if seq_ptms == 0:
            return 0
        max_frag_ptm = max([_get_ptm_amount(x.fragment.sequence) for x in matches])
        return seq_ptms - max_frag_ptm
    ```
    Уже корректно обрабатывает случай отсутствия PTM (`return 0`).
- `dasmixer-core/src/dasmixer/api/calculations/spectra/ion_match.py`:
  - `MatchResult` (dataclass) уже содержит поле `unconfirmed_ptms: int` (последнее поле, после `longest_consec_run_rate`):
    ```python
    @dataclass
    class MatchResult:
        parameters: IonMatchParameters
        fragments: list[Fragment]
        fragment_matches: list[FragmentMatch]
        intensity_percent: float
        top10_intensity_matches: int
        total_peaks: int
        max_ion_matches: int
        top_matched_ion_type: str
        quality: float
        longest_consec_run_rate: float
        unconfirmed_ptms: int
    ```
  - `match_predictions()` уже вызывает `calculate_unconfirmed_ptms(matches, sequence)` и заполняет `MatchResult.unconfirmed_ptms`, включая fallback `unconfirmed_ptms=0` в ветке пустого спектра/`total_peaks == 0`.
- **Задачи по расчёту НЕТ.** Работа только по проводке уже готового значения — по тому же паттерну, что `lcrr`/`quality`.

```python
async def put_identification_data_batch(self, data_rows: list[dict[str, Any]]) -> None:
    """
    Batch-update ion-coverage fields for a list of identifications.

    Each dict in data_rows must contain at least 'id'; all other keys are
    optional — missing ones are written as NULL.

    Keys recognised:
        id, ppm, theor_mass, override_charge,
        intensity_coverage, ions_matched, ion_match_type, top_peaks_covered,
        source_sequence, isotope_offset, quality, lcrr, override_pepmass, has_ptm
    """
    query = """
        UPDATE identification
        SET
            sequence = ?,
            ppm = ?,
            theor_mass = ?,
            override_charge = ?,
            intensity_coverage = ?,
            ions_matched = ?,
            ion_match_type = ?,
            top_peaks_covered = ?,
            source_sequence = ?,
            isotope_offset = ?,
            quality = ?,
            lcrr = ?,
            override_pepmass = ?,
            has_ptm = ?
        WHERE id = ?
    """
    params = []
    for data_row in data_rows:
        src_seq = data_row.get('source_sequence')
        result_seq = data_row.get('sequence')
        source_sequence_value = src_seq if (src_seq and src_seq != result_seq) else None

        params.append((
            result_seq,
            data_row.get('ppm'),
            data_row.get('theor_mass'),
            data_row.get('override_charge'),
            data_row.get('intensity_coverage'),
            data_row.get('ions_matched'),
            data_row.get('ion_match_type'),
            data_row.get('top_peaks_covered'),
            source_sequence_value,
            data_row.get('isotope_offset'),
            data_row.get('quality'),
            data_row.get('longest_consec_run_rate'),
            data_row.get('override_pepmass'),
            data_row.get('has_ptm'),
            data_row['id'],
        ))
    await self._executemany(query, params)
```

## 6. SQL-скрипт отката для тестовых проектов

**Назначение:** тестовые `.dasmix`-проекты разработчика, к которым уже была применена миграция `0.7.2` из 0.7.2a1 (т.е. `project_metadata.version = '0.7.2'`, колонка `lcrr` уже существует, но `unconfirmed_ptms` — нет). Выполнить вручную (например, через SQLite console/CLI) **до** обновления приложения на билд 0.7.2a2, либо сразу после — но обязательно **до** следующего открытия проекта в приложении, если требуется, чтобы штатный `apply_migrations()` заново отработал расширенный SQL миграции `0.7.2` и добавил `unconfirmed_ptms` автоматически.

```sql
-- Откат применённой в 0.7.2a1 миграции 0.7.2 для тестовых проектов DASMixer.
-- Назначение: вернуть project_metadata.version на '0.7.1', чтобы при следующем
-- открытии проекта в приложении (после обновления на билд, где миграция 0.7.2
-- расширена unconfirmed_ptms) apply_migrations() заново применил ПОЛНЫЙ SQL
-- версии 0.7.2 (lcrr + unconfirmed_ptms) за один проход.
--
-- ВНИМАНИЕ: DROP COLUMN требует SQLite >= 3.35.0. Выполнять на копии файла
-- проекта (сделать backup .dasmix перед запуском).

BEGIN TRANSACTION;

ALTER TABLE identification DROP COLUMN lcrr;

UPDATE project_metadata SET value = '0.7.1' WHERE key = 'version';

COMMIT;
```

**Проверка после применения:**
```sql
SELECT value FROM project_metadata WHERE key = 'version';  -- должно быть '0.7.1'
PRAGMA table_info(identification);  -- колонки 'lcrr' и 'unconfirmed_ptms' отсутствуют
```

**После этого:** при следующем открытии проекта в приложении (собранном с расширенной миграцией `0.7.2` из раздела T1.2) сработает штатный `apply_migrations()`:
1. `get_project_version()` → `'0.7.1'`.
2. `needs_migration()` → `True` (`0.7.1 < 0.7.2`).
3. Применится миграция `{"version": "0.7.2", "sql": "ALTER TABLE identification ADD COLUMN lcrr REAL; ALTER TABLE identification ADD COLUMN unconfirmed_ptms INTEGER;"}`.
4. `project_metadata.version` → `'0.7.2'`.

**Примечание:** если у разработчика есть проекты, где `lcrr` уже нужен (данные в нём не хотелось бы стирать) — DROP COLUMN не теряет данные других полей, теряются только значения `lcrr` (что ожидаемо для тестовых проектов, где расчёт можно перезапустить через `Calculate Ion Coverage`). Если нужно сохранить значения `lcrr`, альтернативный путь — вручную выполнить `ALTER TABLE identification ADD COLUMN unconfirmed_ptms INTEGER;` без отката версии и без трогать `lcrr`/`project_metadata.version` (эквивалентный результат без даунгрейда версии, но тогда `project_metadata.version` останется `'0.7.2'`, что не отражает факт добавления новой колонки — на усмотрение разработчика, какой вариант применить к каждому конкретному тестовому проекту).
