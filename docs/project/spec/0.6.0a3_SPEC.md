## Задача 1. Баг: `Path` не определён в `settings_view.py`

### Диагноз

Файл: `dasmixer-gui/src/dasmixer/gui/views/settings_view.py`

Функция `_apply_logging_config` (строка ~33) использует `Path`, однако:
- Модульный `import` в начале файла не содержит `from pathlib import Path`
- Внутри функции есть локальные импорты `import logging` и `from datetime import datetime`, но `Path` не импортирован

**Стектрейс ошибки:**
```
NameError: name 'Path' is not defined
  File "settings_view.py", line 33, in _apply_logging_config
    else Path.home() / ".cache" / "dasmixer" / "logs"
```

### Реализация

**Файл:** `dasmixer-gui/src/dasmixer/gui/views/settings_view.py`

Добавить `from pathlib import Path` внутрь функции `_apply_logging_config` рядом с существующими локальными импортами:

```python
def _apply_logging_config(cfg) -> None:
    """Configure root logger based on AppConfig settings."""
    import logging
    from datetime import datetime
    from pathlib import Path          # ← добавить эту строку
    ...
```

> **Примечание:** Добавление внутрь функции, а не на уровень модуля — осознанное решение для консистентности с остальными локальными импортами в функции.

## Задача 2. CLI: команды управления инструментами (`tool`)

### Описание

Создать новый модуль CLI команд для управления инструментами проекта. Зарегистрировать в `main.py`.

### Синтаксис команд

```
dasmixer-cli tool add     <project_path> --name <name> --parser <parser> [--type <type>] [--color <hex>]
dasmixer-cli tool configure <project_path> --name <name> --key <key> --value <value>
dasmixer-cli tool param-list <project_path> [--name <name>]
dasmixer-cli tool list    <project_path>
```

### Новый файл: `dasmixer-cli/src/dasmixer/cli/commands/tool.py`

#### `tool add`

**Параметры:**
- `project_path: str` — Argument, путь к `.dasmix` файлу
- `--name / -n: str` — Required, имя инструмента
- `--parser / -p: str` — Required, имя парсера (`PowerNovo2`, `MGF`, `MQ_Evidences`, `PLGS`, или любой зарегистрированный)
- `--type / -t: str` — Optional, `"Library"` или `"De Novo"`, default `"Library"`
- `--color: str` — Optional, hex-цвет (например `#4CAF50`), default `None` (инструмент выберет цвет самостоятельно)

**Поведение:**
1. Открыть проект (create_if_not_exists=False)
2. Проверить, что инструмент с таким именем не существует → если существует: вывести ошибку и завершиться с кодом 1
3. Проверить `--type` — допустимые значения `"Library"` или `"De Novo"`
4. Вызвать `await project.add_tool(name=name, type=type, parser=parser, settings={}, display_color=color)`
5. Вывести: `✓ Tool added: <name> (parser: <parser>, type: <type>)`

**Пример вывода:**
```
✓ Tool added: PN2 (parser: PowerNovo2, type: De Novo)
```

#### `tool configure`

**Параметры:**
- `project_path: str` — Argument
- `--name / -n: str` — Required, имя инструмента
- `--key / -k: str` — Required, ключ настройки
- `--value / -v: str` — Required, значение настройки

**Поведение:**
1. Открыть проект
2. Найти инструмент по имени (`project.get_tools()`, фильтр по `tool.name == name`) → если не найден: ошибка
3. Обновить `tool.settings[key] = value` (строковое значение)
4. Вызвать `await project.update_tool(tool)` — если метод не существует, использовать `project._execute("UPDATE tool SET settings=? WHERE id=?", [json.dumps(tool.settings), tool.id])`
5. Вызвать `await project.save()`
6. Вывести: `✓ Tool '<name>' configured: <key> = <value>`

> **Примечание:** Проверить наличие метода `update_tool` в `ToolMixin`. Если отсутствует — реализовать через `_execute` напрямую.

#### `tool param-list`

**Параметры:**
- `project_path: str` — Argument
- `--name / -n: str` — Optional, имя инструмента; если не указан — вывести настройки всех инструментов

**Поведение:**
1. Открыть проект
2. Получить инструменты (`project.get_tools()`)
3. Если `--name` указан — фильтровать по имени → если не найден: ошибка
4. Для каждого инструмента вывести таблицу его `settings`:

```
Tool: PN2 (PowerNovo2, De Novo)
  min_score       = 0.5
  min_length      = 5
  (no settings)   ← если dict пустой
```

#### `tool list`

**Параметры:**
- `project_path: str` — Argument

**Поведение:**
1. Открыть проект
2. Вывести таблицу инструментов:

```
ID   Name           Type        Parser        Settings
1    PN2            De Novo     PowerNovo2    2 keys
2    MaxQuant       Library     MQ_Evidences  0 keys
```

### Регистрация в `main.py`

```python
from dasmixer.cli.commands import tool as tool_cmd

app.add_typer(tool_cmd.app, name="tool", help="Manage project tools")
```

### Регистрация в `main.py`

В текущем `main.py` команды `project.py` зарегистрированы как `name="create"`:
```python
app.add_typer(project.app, name="create", ...)
```

Необходимо **добавить** отдельную регистрацию с именем `"project"` для нового app (или переиспользовать тот же app, зарегистрировав его дважды):

```python
# Оставить существующую регистрацию для backward compatibility:
app.add_typer(project.app, name="create", help="Create a new project")

```

> **Примечание:** Typer поддерживает регистрацию одного `app` под разными именами. В этом случае `dasmixer-cli create <path>` и `dasmixer-cli project create <path>` будут оба работать.

### Реализация `ident-file`

**Параметры (существующие, оставить):**
- `project_path: str` — Argument
- `--file / -f: str` — Required, путь к файлу идентификаций
- `--sample-id / -s: str` — Required, имя образца (должен существовать)
- `--parser: str` — Required, имя парсера идентификаций (`PowerNovo2`, `MQ_Evidences`, `PLGS`)
- `--tool: str` — Required, имя инструмента (должен существовать в проекте)

**Добавить параметры:**
- `--spectra-file-id: int` — Optional, ID файла спектров; если не указан — берётся первый spectra_file образца
- `--recalc / --no-recalc: bool` — Optional, пересчитать уже импортированные, default False

**Workflow:**
```
1. Открыть проект (create_if_not_exists=False)
2. Найти образец по имени: project.get_samples() → фильтр по name
   └─ Если не найден → ошибка "Sample '<sample_id>' not found"
3. Найти инструмент по имени: project.get_tools() → фильтр по name
   └─ Если не найден → ошибка "Tool '<tool>' not found. Use 'dasmixer-cli tool add' first"
4. Определить spectra_file_id:
   └─ Если --spectra-file-id указан → использовать его
   └─ Иначе: project.get_spectra_files(sample_id=sample.id) → первый файл
   └─ Если файлов нет → ошибка "No spectra files found for sample"
5. Получить парсер: registry.get_parser(parser, "identification")
   └─ Если не найден → ошибка "Unknown parser '<parser>'"
6. Создать identification_file:
   └─ file_id = await project.add_identification_file(
         spectra_file_id=spectra_file_id,
         tool_id=tool.id,
         file_path=str(file_path)
      )
7. Получить список спектров: 
   └─ spectra_list = await project.get_spectra_idlist(spectra_file_id, by=parser_instance.spectra_id_field)
8. Парсить файл идентификаций батчами:
   async for batch_df, _ in parser_instance.parse_batch(batch_size=config.identification_batch_size):
       └─ Добавить колонку ident_file_id = file_id
       └─ Смержить batch_df со spectra_list по spectra_id_field → получить spectre_id
       └─ Отфильтровать строки без совпадений (предупреждение о количестве)
       └─ await project.add_identifications_batch(merged_df)
9. await project.save()
10. Вывести статистику: 
    ✓ Imported N identifications from <file>
      Tool: <tool_name>
      Sample: <sample_name>
      Spectra file: <path>
      Matched: N/M spectra
```

### Реализация `ident-pattern`

**Параметры (существующие):**
- `project_path: str` — Argument
- `--folder / -f: str` — Required, папка для поиска
- `--pattern / -p: str` — Optional, default `"*.csv"`
- `--id-pattern / -i: str` — Optional, default `"{id}*.csv"`
- `--parser: str` — Required, имя парсера
- `--tool: str` — Required, имя инструмента

**Workflow:**
1. Найти файлы через `seek_files(folder_path, file_pattern, id_pattern)` — возвращает `list[(file_path, sample_id)]`
2. Показать найденные файлы и запросить подтверждение (как в `mgf-pattern`)
3. Для каждого `(file_path, sample_id)`:
   - Найти образец по имени
   - Вызвать логику `ident-file` (вынести в вспомогательную async-функцию `_import_ident_file`)
4. Вывести итоговую статистику: `✓ Imported N files, M identifications total`

> **Примечание:** Вынести общую логику импорта идентификаций в приватную функцию `_import_ident_file(project, file_path, sample_name, parser_name, tool_name, spectra_file_id=None)` во избежание дублирования кода.

### Зависимости

- Потребуется метод `project.get_spectra_files(sample_id)` — проверить существование в `SpectraMixin`. Если отсутствует — реализовать через `execute_query_df("SELECT * FROM spectre_file WHERE sample_id=?", [sample_id])`.
- `parser_instance.spectra_id_field` — атрибут класса `IdentificationParser` (уже существует).

```
7. await project.save()
8. Вывести:
   ✓ Imported N proteins from <file>

     Generic entries: Y
```


## Задача 6. CLI: команды расчётов (`calculate`)

### Описание

Создать новый модуль `dasmixer-cli/src/dasmixer/cli/commands/calculate.py` с подкомандами, дублирующими кнопки GUI.

### Соответствие команд и GUI

| CLI команда | GUI кнопка | GUI метод |
|---|---|---|
| `calculate peptides` | "Calculate Peptides" | `ActionsSection.calculate_peptides` |
| `calculate ion-coverage` | "Calculate Ion Coverage" | `_run_ion_coverage` |
| `calculate preferred` | "Select Preferred" | `_run_select_preferred` |
| `calculate peptide-match` | "Match Proteins to Identifications" | `_run_match_proteins` |
| `calculate protein-idents` | "Calculate Protein Identifications" | `DetectionSection.calculate_identifications` |
| `calculate lfq` | "Calculate LFQ" | `LFQSection.calculate_lfq` |

### Общий принцип работы calculate-команд

Все команды:
1. Открывают проект через `async with Project(...)` 
2. Считывают **настройки расчётов** из `project_settings` (через `project.get_setting(key, default)`) — те же ключи, что сохраняет GUI
3. Позволяют **переопределить** настройки через CLI-опции (если опция указана — она имеет приоритет)
4. Выводят прогресс в stdout
5. Сохраняют результаты через `project.save()`

### Новый файл: `dasmixer-cli/src/dasmixer/cli/commands/calculate.py`

```python
app = typer.Typer(help="Run calculations")
```

#### `calculate ion-coverage`

**Параметры:**

- `ion_match_mode` (default `"largest"`) → режим матчинга
- `ion_match_water_loss` (default `"True"`) → потери воды
- `ion_match_ammonia_loss` (default `"True"`) → потери аммиака
- `ion_fragment_charges` (default `"1,2"`) → заряды фрагментов
- `seqfixer_min_charge` (default `"1"`)
- `seqfixer_max_charge` (default `"4"`)
- `seqfixer_max_isotope_offset` (default `"3"`)
- `seqfixer_max_ptm` (default `"2"`)
- `seqfixer_max_ptm_sites` (default `"3"`)

**Workflow:**
```
1. Загрузить настройки из project_settings
2. Собрать IonMatchParameters и seqfixer_params
3. Получить список идентификаций без coverage (или всех, если --recalc-all)
   └─ через project.get_identifications(sample_id=sample_id) + фильтр по ppm IS NULL
4. Разбить на батчи (config.identification_processing_batch_size)
5. Запустить process_identificatons_batch через ProcessPoolExecutor
6. Записать результаты через project.put_identification_data_batch()
7. await project.save()
8. Вывести: ✓ Processed N identifications
```

**CLI опции переопределения:**
- `--tolerance: float` — PPM tolerance
- `--ions: str` — через запятую, например `"b,y,a"`

## Задача 8. GUI: аудит и исправление диалогов в manage_samples_view

### Диагноз

**Корневая причина ошибки** `SampleViewPanel(6163) Control must be added to the page first`:

`SampleViewPanel` является `ft.Container`, но **не добавляется напрямую в дерево страницы**. В `build()` создаётся и возвращается `self._expansion_panel: ft.ExpansionPanel` — именно он добавляется в страницу. Сам `SampleViewPanel` (Container) остаётся неприкреплённым, поэтому `SampleViewPanel.page` всегда `None`.

В `_build_body()` все lambda-обработчики используют `self.page`:
```python
on_click=lambda e, s=sample: self.page.run_task(self._on_action, 'delete_sample', s) if self.page else None
```
— при `self.page is None` обработчик возвращает `None` и не делает ничего.

Дополнительно: диалоги в `manage_samples_view.py` (методы `_confirm`, `_on_mass_delete`) создают `ft.AlertDialog` и добавляют в `page.overlay`, используя `self.page` от `ManageSamplesView(ft.View)` — это корректно, т.к. `ft.View` ЕСТЬ в дереве страницы. Но если `_confirm` вызывается из контекста `SampleViewPanel` (через `_on_action`), то `self.page` у `ManageSamplesView` должен быть доступен.

**Фактическая ошибка:** вероятнее всего происходит в `_rebuild_panels_from_cache()` или при вызове `update()` на экземпляре `SampleViewPanel`.

### Полный аудит диалогов

Необходимо проверить и исправить следующие файлы:

| Файл | Проблемные паттерны |
|---|---|
| `sample_panel.py` | `self.page.run_task(...)` в lambdas (всегда None) |
| `manage_samples_view.py` | `_confirm()`, `_on_mass_delete()`, `_rebuild_panels_from_cache()` |
| `dialogs/assign_subset_dialog.py` | паттерн открытия диалога |
| `dialogs/drop_file_dialog.py` | паттерн открытия диалога |

### Исправление `sample_panel.py`

**Принцип:** Использовать `e.page` из события вместо `self.page`.

В Flet, `e.page` всегда доступна в `on_click`-обработчиках если контрол примонтирован. Поскольку `self._expansion_panel` (и все его дочерние контролы) добавлены в страницу, `e.page` в их обработчиках будет корректным.

**Замена для всех `on_click` в `_build_body()`:**

```python
# Было:
on_click=lambda e, _sf_id=sf_id: self.page.run_task(
    self._on_action, 'delete_spectra_file', _sf_id, self._sample
) if self.page else None,

# Стало:
on_click=lambda e, _sf_id=sf_id: e.page.run_task(
    self._on_action, 'delete_spectra_file', _sf_id, self._sample
),
```

**Применить ко всем lambdas в `_build_body()`:**
1. Кнопка "Add identification file" → `e.page.run_task(...)`
2. Кнопка "Delete spectra file" → `e.page.run_task(...)`
3. Кнопка "Delete identification file" → `e.page.run_task(...)`
4. Кнопка "Add spectra file" → `e.page.run_task(...)`
5. Кнопки action-панели ("Calculate ions", "Select preferred", "Match proteins", "Protein Identifications", "LFQ") → `e.page.run_task(...)`
6. Кнопка "Edit sample" → `e.page.run_task(...)`
7. Кнопка "Toggle outlier" → `e.page.run_task(...)`
8. Кнопка "Delete sample" → `e.page.run_task(...)`

**Итого: 8+ мест в `_build_body()`.**
