# v0.7.4a3

**Date:** 2026-10-09

---

## Summary

Оптимизация параллелизма двух CPU-bound расчётов: переход в ion matching со статической нарезки sub-batches на очередь чанков с промежуточной записью в БД, и распараллеливание per-row цикла protein map / de novo correction. Отдельный fix: перебор PTM при маппинге белков теперь использует default-PTM из GUI, а не полный список. Без изменения схемы БД.

---

## Core Changes

### Очередь чанков для ion matching — `queue_runner.py` (**New**)

Новый модуль `dasmixer-core/src/dasmixer/api/calculations/spectra/queue_runner.py`:

- `run_identification_queue(worker_dicts, executor, chunk_size, flush_every, process_fn, process_fn_kwargs, flush_callback, progress_callback=None, stop_check=None) -> int`.
- Нарезка `worker_dicts` на чанки по `chunk_size`, ограничение «в полёте» через `asyncio.Semaphore(worker_count)`, сбор через `asyncio.as_completed`.
- Промежуточный flush накопленных результатов через `flush_callback` каждые `flush_every` завершённых чанков + финальный flush остатка.
- `progress_callback(processed)` — накопительный счётчик обработанных идентификаций; `stop_check()` — кооперативная остановка (после остановки pending-таски отменяются).
- Чистая core-логика: без обращения к БД и без импортов из `dasmixer.gui.*`.
- Вызов воркера — `process_fn(chunk, **process_fn_kwargs)` через `functools.partial` (т.к. `run_in_executor` не принимает kwargs).

### Per-row воркер protein map — `protein_map_worker.py` (**New**)

Новый модуль `dasmixer-core/src/dasmixer/api/calculations/peptides/protein_map_worker.py`:

- `process_protein_map_row(row_dict, mz_array, intensity_array, pepmass, charge, seqfixer, ion_match_params_dict, fragment_charges) -> dict | None`.
- Top-level picklable функция для `ProcessPoolExecutor`: пересчёт PPM + ion coverage для `identity < 1.0`, применение Match Correction Criteria, AA-substitution fallback.
- Свежая копия `IonMatchParameters` создаётся на каждый вызов из `ion_match_params_dict` — устраняет гонку `params.charges`/`params.ions`.
- Без обращения к БД и без импорта `protein_map.py` (нет цикла импорта).

### Рефакторинг `map_proteins` (`protein_map.py`)

- Убран async-генератор: `map_proteins` теперь обычная `async def`, возвращает `None`.
- `ProcessPoolExecutor(max_workers=worker_count)` создаётся **отдельно на каждый `tool_id`**; `worker_count = config.max_cpu_threads or cpu_count - 1`.
- Запись результатов перенесена внутрь: `project.add_peptide_matches_batch()` + `project._commit()` на каждый batch, финальный `await project.save()` после всех tool_id.
- Новые параметры: `progress_callback(processed, total=-1)` и `stop_check()`.
- Сигнатура: `map_proteins(project, tool_settings, ion_params, fragment_charges, seqfixer_params, batch_size=5000, sample_id=None, use_src_protein_ids=False, progress_callback=None, stop_check=None)`.

### Fix — перебор PTM по default-PTM вместо полного списка

- `protein_map.py` и `identification_processor.py`: ветка `if ptm_names is None` теперь раскрывает `None` в `[x for x in PTMS if x.code in DEFAULT_PTM_CODES]`, а не в полный `PTMS`.
- Раньше GUI при выборе default-PTM отправлял `ptm_list=None`, а бэкенд трактовал `None` как «все ~43 PTM» — т.е. перебирались все возможные модификации вместо настроенных в GUI. Теперь «None = default-PTM».

## GUI Changes

### `ion_actions.py` — очередь чанков

`IonCoverageAction.run` переведён со статической нарезки sub-batches + `asyncio.gather` на `run_identification_queue`; `chunk_size = int(batch_size / worker_count)`, `flush_every = worker_count`; `flush_callback` = `put_identification_data_batch` + `_commit`.

### `protein_map_action.py` — новая сигнатура

`MatchProteinsAction.run` вызывает `await map_proteins(...)` вместо `async for`; передаёт `progress_callback` (indeterminate-бар) и `stop_check` (stoppable `ProgressDialog`); удалены лишние `add_peptide_matches_batch`/`save` (теперь внутри `map_proteins`).

### `tool_settings_section.py` — комментарии

Уточнены комментарии в `save_tool_settings` / `get_tool_settings_for_matching`: `ptm_list=None` означает «default-PTM» (раскрывается в `DEFAULT_PTM_CODES`), а не «все PTM».
