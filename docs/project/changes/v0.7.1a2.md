# v0.7.1a2

**Date:** 2026-08-17

---

## Overview

Версия 0.7.1a2 — четыре независимых quality-of-life доработки GUI-приложения:

1. **Масштабирование графиков** — адаптивный размер графиков `BasePlotView` под высоту окна с настраиваемым aspect ratio.
2. **Режим интерактивного просмотра** — переключатель между pywebview (Window) и браузером по умолчанию (Browser) для графиков и отчётов.
3. **Название проекта в заголовках** — имя открытого проекта в заголовке окна и AppBar.
4. **Пункт меню «Open Recent»** — модальное окно со списком недавних проектов из системного меню File.

Изменения локализованы в `dasmixer-gui` (GUI-слой) и `dasmixer-core` (только конфигурация). Схема БД и API проекта не затрагиваются.

---

## New Features

### Plot Aspect Ratio (масштабирование графиков)

- Новая настройка **Plot aspect ratio** (Settings → Appearance, Dropdown): `1:1`, `4:3`, `2:3`, `16:9` (по умолчанию `16:9`).
- `BasePlotView` (и наследники `PeptideIonPlotView`, `ProteinConcentrationPlotView`) теперь вычисляет размер графика динамически:
  - высота = высота окна − 130px, с ограничением в диапазон **[300, 1000]**;
  - ширина = `int(height × W/H)` для выбранного соотношения.
- Жёсткие константы `_PLOT_WIDTH = 1100` / `_PLOT_HEIGHT = 700` удалены; добавлена функция `_get_plot_dimensions(page)` с fallback `(1100, 700)` при недоступном окне.
- Размер применяется при каждой генерации графика и при восстановлении из suspend (`resume()`); автоматическая перерисовка при изменении размера окна не выполняется (следующий график строится в новых размерах).
- `PlotlyViewer` (отчёты) и HTML-отчёты (`ReportViewer`) не затрагиваются.

### Plot and Report View Mode (режим интерактивного просмотра)

- Новая настройка **Plot and report view mode** (Settings → Appearance, Dropdown): `Window` (по умолчанию) / `Browser`.
- `Window` — текущее поведение с `pywebview.create_window(html=...)` (без изменений).
- `Browser` — сгенерированный HTML сохраняется во временный файл (`tempfile.NamedTemporaryFile(suffix='.html', delete=False)`) и открывается в браузере по умолчанию через `webbrowser.open(...)`.
- Режим применяется ко всем трём точкам входа:
  - `BasePlotView._launch_webview` (одиночный график);
  - `PlotlyViewer.launch_interactive` (одиночный график из PlotlyViewer);
  - `ReportViewer.show_report` (HTML-отчёт с несколькими графиками).
- Очистка временных файлов: при открытии/создании/закрытии проекта удаляются все `dasmixer_plot_*.html` и `dasmixer_report_*.html` из системной temp-директории (функция `cleanup_temp_html_files()`).

### Project Name in Titles (название проекта в заголовках)

- При открытом проекте:
  - заголовок окна: `f'{project_name}: DASMixer - Mass Spectrometry Data Integration'`;
  - заголовок AppBar: `f'DASMixer — {project_name}'` (вместо статичного `"DASMixer"`).
- Имя берётся из `Path(project.path).stem` (без расширения).
- При закрытом/неоткрытом проекте заголовки возвращаются к значениям по умолчанию.
- Новый метод `DASMixerApp._update_titles()` вызывается после `new_project` / `open_project` / `close_project`.

### Open Recent (пункт меню)

- В системное меню **File** добавлен пункт **Open Recent** (сразу после «Open Project»), `disabled`, если список недавних проектов пуст.
- По клику открывается модальное окно (`AlertDialog`) со списком недавних проектов.
- Список вынесен в переиспользуемый компонент **`RecentProjectsList`** (используется и на стартовом экране `StartView`, и в модальном окне). Компонент автоматически фильтрует несуществующие файлы.
- При клике на проект: текущий проект сохраняется с checkpoint (`save(checkpoint=True)`, без предупреждения), модалка закрывается, выбранный проект открывается.

## Bug Fixes

### Stacked dialogs при открытии проекта через Open Recent / Open Project

При открытии проекта старой версии (требующей миграции) через пункты меню **Open Recent** или **Open Project** в `page.overlay` накапливались три диалога друг над другом: Open Recent, Project Update Required, Updating project. Последний зависал, кнопки не реагировали.

**Причины:**

1. **Stale dialog в overlay** — `on_project_selected` и `on_cancel` не удаляли диалог из `page.overlay` после закрытия. При показе следующего модального диалога Flet путался в modal barrier/scrim.

2. **Sync-обработчики `on_update`/`on_skip`** были `def` (синхронные), что в Flet 0.80.5 запускает их в отдельном потоке. `asyncio.Event.set()` из другого потока не thread-safe, а `page.update()` из потока конкурировал с корутиной — `event.wait()` просыпался до того, как Flet обрабатывал `dialog.open = False`.

3. **ProgressDialog не удалялся из overlay** — после закрытия через `open = False` объект оставался в `page.overlay[]`, блокируя последующие диалоги.

**Исправления (`dasmixer-gui/src/dasmixer/gui/app.py`):**

- **`_show_open_recent_dialog.on_project_selected`**: диалог удаляется из overlay через `page.overlay.remove()`; перед открытием нового проекта вызывается `close_project()` (полный teardown + стартовый экран), чтобы миграционный диалог показывался на чистом overlay.
- **`_show_open_recent_dialog.on_cancel`**: добавлено удаление диалога из overlay.
- **`_show_migration_dialog.on_update` / `on_skip`**: заменены с `def` на `async def`; убран `page.update()` из обработчиков — единственный update происходит в корутине после `event.wait()`, сразу с удалением диалога из overlay.
- **`_run_migration`**: в `finally` добавлен `page.overlay.remove(dialog)`.
- **`open_project`**: замена `await self.current_project.close()` на `await self.close_project()` для полного teardown старого проекта (сброс view, переход на стартовый экран) перед открытием нового.

### ValidationError при загрузке конфигурации со старыми ключами

При откате на версию без полей `plot_aspect_ratio` и `plot_view_mode` pydantic-settings выдавал `ValidationError: Extra inputs are not permitted`, так как по умолчанию `model_config` использует `extra="forbid"`.

**Исправление (`dasmixer-core/src/dasmixer/api/config.py`):**

В `SettingsConfigDict` добавлен `extra="ignore"`. Неизвестные ключи в `config.json` игнорируются без ошибки.

## Behavior Changes

- **Browser-режим**: `import webview` в `show_webview()` и `_show_html_in_webview()` стал ленивым (внутри ветки `else`), `pywebview` не импортируется при выбранном Browser-режиме.
- **Временные HTML-файлы**: при многократном открытии графиков/отчётов в Browser-режиме без закрытия проекта temp-файлы накапливаются до ближайшего open/create/close (полная очистка выполняется именно в этих точках).
