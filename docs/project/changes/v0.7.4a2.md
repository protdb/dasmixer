# v0.7.4a2

**Date:** 2026-10-08

---

## Summary

Расширение набора парсеров идентификаций: маппинг спектров по `title`, авто-обновление PTM-списков через `LASTRUN_VERSION`, три новых парсера (mzTab, CasaNovo, Pi-PrimeNovo) и мультиимпорт одного mzTab-файла на несколько `spectre_file`. Без изменения схемы БД.

---

## Core Changes

### Маппинг спектров по `title`

- `SpectralMixin.get_spectra_idlist()` (`spectra_mixin.py`): `by` теперь принимает `"title"` наряду с `"seq_no"`/`"scans"`. Для `title` выполняется регистронезависимая нормализация — `LOWER(TRIM(title))`, пустые/NULL title исключаются.
- `ColumnRenames` (`table_importer.py`): добавлено поле `title`; валидация в `remap_columns` расширена с «scans/seq_no» до «scans/seq_no/title».
- Новый индекс не добавлялся — существующий `idx_spectre_title` уже покрывает запрос.

### Обновление PTM-конфигурации + `LASTRUN_VERSION`

`ptm_config.py` — новые функции:

- `get_lastrun_version_path()` / `ensure_ptm_files()` / `_read_lastrun_version()` / `_write_lastrun_version()`.
- `merge_ptm_renames()` — дополняет `import_ptm_renames.csv` строками из `DEFAULT_PTM_RENAMES`, отсутствующими по паре (`parser`, `source`); существующие строки не трогаются.
- `merge_ptm_config()` — дополняет `all_ptm_config.csv` строками из `DEFAULT_PTM_CONFIG`, отсутствующими по `name`.
- `_refresh_caches()` — сбрасывает `lru_cache` (`load_ptm_config`, `load_ptm_renames`) и вызывает `reload_ptms()`.
- `check_and_update_ptm_config()` — hook для GUI (merge только при несовпадении `LASTRUN_VERSION`).
- `update_ptm_list()` — hook для CLI (merge всегда, идемпотентно).

Маркер `LASTRUN_VERSION` хранит текущий `APP_VERSION` одной строкой в корне `{app_dir}`.

`seqfixer_utils.py`:

- `reload_ptms()` — перестраивает module-level `PTMS` и `DEFAULT_PTM_CODES` из текущей конфигурации (после merge на диске).

### Новые парсеры идентификаций

| Парсер | Файл | Registry name | Особенности |
|---|---|---|---|
| mzTab (база) | `peptides/MzTab.py` | `mzTab` | мультиимпорт, `contain_proteins`, резолв `ms_run` → `spectre_file` |
| CasaNovo | `peptides/CasaNovo.py` | `CasaNovo` | готовая ProForma из opt-колонки, `aa_scores` → `positional_scores` |
| Pi-PrimeNovo | `peptides/PiPrimeNovo.py` | `Pi-PrimeNovo` | TSV, маппинг по `title`, преобразование `prediction` |

Регистрация — в `inputs/__init__.py` (`register_parsers()`).

#### `MzTabImporter` (база)

- Чтение MTD **по сырым строкам** (pyteomics теряет accession модификаций и падает на `ms_run[N]_location`); пропуск `COM`/пустых строк, остановка на данных таблицы.
- Список модификаций (`fixed_mod` + `variable_mod`) → `dict[accession → ProForma tag]`: `UNIMOD` (имя из MTD или `Unimod.by_id`), `MOD:` → `PSI-MOD:`, `CHEMMOD:` → массовый тег.
- Сборка ProForma через `pyteomics.proforma` (`n_term`/`c_term`/`unlocalized_modifications`), сборка канонической последовательности.
- Разбор `spectra_ref` (`ms_run[N]:scan=` / `ms_run[N]-scan=` / `index=`), определение `spectra_id_field` по первой строке.
- `ppm` считается от нейтральной массы ProForma и `charge` (см. Notes), а не из колонки `calc_mass_to_charge` (в PD-файлах она неконсистентна).
- Белки: `accession` → `src_file_protein_id`; схлопывание строк по `(PSM_ID, spectra_ref)` с join accession через `;`.
- Мультиимпорт: резолв `ms_run[N]-location` → `spectre_file` по нормализованному `basename(stem)`; неразрешённые — пропуск строк с warning; на каждый сопоставленный `ms_run` — свой `spectra_file_id` + `ms_run_index`.
- Новый флаг `IdentificationParser.can_import_multifile` (в `base.py`).

#### `CasaNovoImporter`

- Наследует `MzTabImporter`; `contain_proteins = False`, `can_import_multifile = False`, `spectra_id_field = "seq_no"`.
- Колонка `modifications` игнорируется; готовая ProForma берётся из `opt_global_cv_MS:1003169_proforma_peptidoform_sequence`.
- `opt_global_aa_scores` → `positional_scores` (список float).

#### `PiPrimeNovoImporter`

- Наследует `SimpleTableImporter`; TSV; `label` → `title` (нормализованный), `prediction` → `sequence`, `score` → `score`.
- Преобразование `prediction`: `B` перед S/T/Y → `[Phospho]`, удаление одиночного `B`, массовые/N-terminal замены.
- `canonical_sequence` синтезируется из преобразованной ProForma.

### `ident_spectra_pairing.py`

Добавлены `normalize_spectra_location()` (снятие `file://`, бэкслеши → `/`, `basename(stem)` в нижнем регистре) и `resolve_spectra_file_by_location()`. Существующая `resolve_ident_to_spectra_mapping()` сохранена.

### `identification_mixin.py`

- Новый метод `get_identification_file_by_path_and_spectra(file_path, spectra_file_id)` — для проверки дубликатов в мультиимпорте, где один файл привязан к нескольким `spectre_file`.

## GUI Changes

### Стартовое обновление PTM (`gui/main.py`)

Вызов `check_and_update_ptm_config()` на старте **до** загрузки плагинов и `import dasmixer.reports`, обёрнутый в `try/except` с логированием — чтобы модули, снапшотящие `PTMS`, видели актуальную конфигурацию.

### Режим «Import multi-file mzTab»

- `import_mode_dialog.py`: кнопка **"Import multi-file mzTab"** (+ подпись-подсказка), видимая при `parser.can_import_multifile`; новый колбэк `on_multifile_callback`.
- `dialogs/import_multifile_dialog.py` (**New**): `ImportMzTabDialog` — выбор одного mzTab/tsv-файла, чекбоксы белков (если `contain_proteins`), радио-группа «On duplicates» (skip / reload / add as new).
- `import_handlers.py`: `import_identification_files_multifile()` — импорт по образцу MaxQuant, но на каждый резолвленный `ms_run` создаётся отдельный `identification_file` (`selection_field="mz_run"`), батчи группируются по `(spectra_file_id, ms_run_index)` и мёржатся с соответствующим `spectra_mapping`.
- `samples_tab.py`: wiring — `on_multifile_callback` + метод `_on_import_identifications_multifile`.

## Notes

- `APP_VERSION` / `PROJECT_VERSION` **не повышались** (обновляются скриптом сборки; по правилам AGENTS.md агентом не меняются).
- Схема БД без изменений → `PROJECT_VERSION` остаётся `0.7.4`, миграций нет, `import_project_mixin.py` не затрагивался.
- **ppm на PD-mzTab**: в некоторых файлах `exp_mass_to_charge` хранит нейтральную массу, а не m/z — расчёт по формуле даёт некорректные значения; неконсистентность зафиксирована как known issue.
- `Unimod` для `UNIMOD:<id>` требует доступа к сети (offline-режим — отдельная доработка).
- Интеграционные тесты не писались (по правилам AGENTS.md); отладка — совместно.
- Changelog `D2` — создан по явному запросу Developer.
