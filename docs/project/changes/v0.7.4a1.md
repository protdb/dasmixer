# v0.7.4a1

**Date:** 2026-09-30

---

## Summary

Полная переработка архитектуры отчётов: реструктуризация пакетов, типизированные параметры через dataclass, именование отчётов, новый диалог экспорта, переработка HTML-шаблона. Все 7 встроенных отчётов мигрированы на новую структуру.

---

## Core Changes

### Реструктуризация пакета отчётов

Конкретные реализации отчётов вынесены из `dasmixer.api.reporting.reports` в новый пакет `dasmixer.reports/`:
- Каждый отчёт — отдельный Python-пакет: `reports/<name>/{report.py, params.py, form.py, __init__.py}`
- Старая директория `api/reporting/reports/` удалена
- `api/reporting/__init__.py` больше не импортирует старые отчёты
- Авто-регистрация встроенных отчётов — через `import dasmixer.reports` (триггерится из GUI и CLI)

### Типизированные параметры — dataclass `ReportParams`

- Новый файл `api/reporting/report_params.py` — маркерный dataclass-предок для всех параметров
- Каждый отчёт определяет `XxxReportParams(ReportParams)` с типизированными полями (int, float, bool, list[str], tuple[str,str] и т.д.)
- `BaseReport._generate_impl(self, params: ReportParams)` — сигнатура изменена с `dict` на typed dataclass
- `BaseReport.params_class` — атрибут класса, ссылающийся на соответствующий dataclass
- Удалены легаси-методы: `get_parameter_defaults()`, `_validate_parameters()`
- `BaseReport.generate()` теперь принимает и возвращает `ReportParams` → `int` (report_id)

### Именование отчётов

- `BaseReport.name_template = "{date} {time}"` — шаблон имени по умолчанию
- `BaseReport.get_report_name(params)` — вычисляет имя, подставляя `{field_name}`, `{date}` (YYMMDD), `{time}` (HH:MM)
- Новое поле `name TEXT` в таблице `generated_reports` (миграция 0.7.4)
- `BaseReport._save_to_db()` / `load_from_db()` — пишут/читают колонку `name`
- Старые записи (`name IS NULL`) отображаются в UI по дате создания

### Переработка экспорта

- `BaseReport.export()` — новая сигнатура с `formats: set[str]` и `xlsx_mode: str`
- `FORMATS`: только запрошенные форматы генерируются (`html`, `docx`, `xlsx`)
- `xlsx_mode='large_only'`: в Excel попадают только «фоновые» таблицы (`show_in_ui=False`)
- Имя файла экспорта: `{report_type_name}_{report_display_name}` (без timestamp, т.к. имя уже уникализировано)
- `BaseReport._sanitize_filename()` — санитизация для NTFS (замена `:` → `-`, удаление `\/*?"<>|`)

### White-list параметров проекта в отчёте

- `BaseReport.PROJECT_PARAMS_WHITELIST` — 19 допустимых ключей project_settings
- В HTML/Word-экспорт попадают только whitelist-параметры (не все подряд)

### HTML-шаблон — новый порядок блоков

`report.html.j2`: порядок секций изменён на:
1. Report Parameters
2. Visualizations
3. Data Tables
4. Project Parameters (white-list) + Tools Configuration

### Оптимизация joined-запросов пептидных данных

`JoinedPeptideDataMixin` (`joined_peptide_data_mixin.py`): подзапросы (subselects
с неявными JOIN через `FROM a, b WHERE`) заменены на явные `LEFT JOIN ... ON`.

Раньше SQLite **материализовал** каждый подзапрос (`sb`, `id`, `mp`) при каждом
вызове — создавал временную таблицу на 2.6M identification + 699K peptide_match
строк и строил автоматические covering indexes заново. Из-за этого `COUNT(*)`
сканировал материализованные данные полностью, а `SELECT ... LIMIT 200` всё
равно копировал все строки перед обрезкой.

После переписывания SQLite «flatten»-ит запрос и использует существующие
индексы (`idx_ident_spectre`, `idx_peptide_match_ident`). `LIMIT` теперь
прерывает сканирование сразу после нахождения нужного числа строк.

Алиасы в `_build_peptide_filter_conditions` обновлены: `id.`→`i.`, `mp.`→`m.`/
`p.`, `sb.*`→`sm.`/`sb.`/`f.`. Имена выходных колонок сохранены через `AS`.

Замеры на проекте Urology6 (10 GB, 2.19M спектров, 2.6M идентификаций):

| Тест (count + get, limit=200) | До | После | Ускорение |
|---|---|---|---|
| page 1, no filter | 18.2s | 2.8s | 6.5x |
| page 5, no filter | 17.9s | 2.8s | 6.4x |
| page 1, is_preferred=True | 79.2s | 3.3s | 24x |
| page 1, protein_identified=True | 18.6s | 2.7s | 6.9x |
| page 1, pref=T prot=F | 6.2s | 3.1s | 2.0x |
| page 2, max_ppm=20 | 18.6s | 2.3s | 8.1x |

GET-запросы с пагинацией: 10–11s → 0.001–0.009s.

### Схема БД и миграция

- `PROJECT_VERSION = "0.7.4"` (schema.py, versions.py, migrations.py)
- Миграция: `ALTER TABLE generated_reports ADD COLUMN name TEXT`
- `report_mixin.get_generated_reports()` — SELECT включает `name`
- `import_project_mixin` — синхронизирован с новой схемой (правило #15 AGENTS.md)

## GUI Changes

### Новый диалог экспорта (`export_dialog.py`)

- Выбор пути сохранения через Browse (directory picker)
- Чекбоксы форматов: DOCX, HTML, XLSX
- При включении XLSX — выпадающий список «All tables» / «Large tables only»
- Используется и для одиночного экспорта (ReportItem), и для batch (ReportsTab)

### Карточка отчёта — поле «Name format»

- Поле `ft.TextField` "Name format" на карточке отчёта (не в диалоге параметров)
- Значение по умолчанию — `report_class.name_template` или `"{date} {time}"`
- Сохраняется вместе с остальными параметрами формы в `report_parameters`
- При генерации подставляется в `params.name_template`

### Кнопка «Save and generate» в диалоге параметров

- Третья кнопка в `AlertDialog` параметров — сохраняет форму + name_template и сразу запускает генерацию

### Авто-выбор нового отчёта после генерации

- После `report.generate()` возвращается `report_id`
- Dropdown автоматически выбирает свежесгенерированный отчёт
- Кнопки View/Export сразу активируются

### Dropdown показывает `name` вместо даты

- Если `name` не null — отображается он; иначе fallback на форматированный `created_at`

### Авто-выбор последнего отчёта при загрузке вкладки

- `ReportItem.load_data()`: после загрузки списка сохранённых отчётов автоматически выбирается последний (самый свежий, `ORDER BY created_at DESC`)
- Dropdown сразу показывает его, кнопки View/Export активны — не нужно вручную кликать в список

### Переход на `form.get_params()`

- `ReportForm.get_params()` — строит typed dataclass из значений формы
- `ReportItem._get_params_from_form()` — возвращает `ReportParams`, а не `dict`
- `IntSelector.get_value()` / `FloatSelector.get_value()` — возвращают `int`/`float` (а не `str`)

### Удаление monkey-patch форм

- Пакет `gui/reports/` (с `forms.py`) удалён
- `gui/main.py`: `import dasmixer.gui.reports.forms` → `import dasmixer.reports`
- Формы теперь живут в `dasmixer/reports/<name>/form.py` и подключаются через `try/except ImportError` в `report.py`

## API Changes (breaking)

| Старое | Новое |
|--------|-------|
| `BaseReport._generate_impl(params: dict)` | `BaseReport._generate_impl(params: ReportParams)` |
| `BaseReport.generate(params: dict) -> None` | `BaseReport.generate(params: ReportParams) -> int` |
| `BaseReport.export(output_path) -> dict[str, Path]` | `BaseReport.export(output_path, formats=..., xlsx_mode=...) -> dict[str, Path]` |
| `BaseReport.get_parameter_defaults()` | Удалён |
| `BaseReport._validate_parameters(params)` | Удалён |
| `BaseReport.parameters = MyForm` (monkey-patch) | `BaseReport.parameters = _parameters` (try/except в модуле) |

## Migrated Reports

5 встроенных отчётов перенесены в `dasmixer/reports/<name>/` с новой структурой:

| Отчёт | Параметры (dataclass) |
|-------|----------------------|
| MedianReport | `subsets`, `lfq`, `include_outliers` |
| PCAReport | `subsets`, `group_by`, `lfq`, `show_labels`, `top_n_proteins`, `include_outliers` |
| ToolMatchReport | `tool1`, `tool2` |
| UpsetReport | `subsets`, `min_proteins` |
| VolcanoReport | `control_subset`, `exptl_subsets`, `lfq`, `stats_method`, `fdc`, `percent_to_calculate`, `fc_threshold`, `p_threshold`, `include_outliers` |

Все отчёты также получили поле `name_template: str = "{date} {time}"`.

### Тестовые отчёты вынесены в плагины

`SampleReport` и `ToolCoverageReport` изначально создавались как тестовые/демонстрационные модули
для проверки архитектуры системы отчётов. В составе production-пакета они не несут
практической ценности и только засоряют вкладку Reports.

Оба отчёта удалены из built-in (`dasmixer/reports/`) и перенесены в плагины:

- `SampleReport` → `{app_dir}/plugins/reports/sample_report.py`
- `ToolCoverageReport` → `{app_dir}/plugins/reports/coverage_report.py`

Каждый плагин — однофайловый (params + form под `try/except ImportError` + report + `registry.register()`),
следует формату из `docs/user/custom_reports.md`. При желании пользователь может удалить
эти `.py`-файлы из папки плагинов, и отчёты исчезнут из UI.
