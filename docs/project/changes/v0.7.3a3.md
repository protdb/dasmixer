# v0.7.3a3

**Date:** 2026-09-11

---

## Summary

This release introduces three major features: (1) batch MGF export with
a new single-query `SpectraMixin.get_full_spectrum_for_export` replacing
per-spectrum DB round-trips, (2) user-configurable PTM definitions moved
from hardcoded Python constants to editable CSV files, and (3) an "Open
configuration folder" button in Settings. All three are independent and
involve no database migration.

---

## New Features

### Batch MGF Export with Sequence Filter and File Suffix

Previously, `export_mgf` fetched each spectrum individually (up to 2 SQL
queries per spectrum: `get_spectrum_full` + `get_preferred_identification`).
This is replaced by a single JOIN query with LIMIT/OFFSET pagination.

**Core — new method `SpectraMixin.get_full_spectrum_for_export`**
(`spectra_mixin.py`):

- Accepts `sf_ids`, `by` (`"all"` / `"all_preferred"` / `"preferred_by_tool"`),
  `tool_id`, `need_ident`, `sequence_contains`, `limit`, `offset`.
- Builds a single SQL query with `SELECT s.*, i.sequence, ... FROM spectre s
  [LEFT|INNER] JOIN identification i ON ... WHERE ... ORDER BY s.seq_no
  LIMIT ? OFFSET ?`.
- JOIN type depends on `by`: `LEFT JOIN` for `"all"` (spectra without
  preferred identifications must still be returned); `INNER JOIN` for
  preferred modes.
- `sequence_contains` filter: for `by="all"` uses an `EXISTS` subquery
  on `identification` (checks *any* identification of the spectrum); for
  preferred modes filters on the already-joined `i.sequence LIKE ?
  COLLATE NOCASE`.
- Returns `list[dict]` with decompressed arrays (`mz_array`,
  `intensity_array`, `charge_array`) and flat identification fields
  (`sequence`, `canonical_sequence`, `override_charge`, `isotope_offset`).

**Core — reworked `mgf_export.py`:**

- Removed 3 private functions: `_get_preferred_identification`,
  `_get_spectrum_ids`, `_iter_spectra_batched` (were only used internally).
- `_write_mgf_to_file` rewritten as a batch-driven loop calling
  `get_full_spectrum_for_export` with `limit`/`offset`; returns the count
  of exported spectra. Ident dict is reconstructed from flat fields.
- `export_mgf` now accepts `sequence_contains: str | None` and
  `file_suffix: str | None`. Before opening any output file, a lightweight
  `limit=1` probe call checks whether the unit has any matching spectra
  (preserving the old "no empty MGF files" behavior).
- `file_suffix` is inserted between `base_name` and timestamp:
  `{sample}_{suffix}_{timestamp}.mgf.gz`. A leading `_` is added if the
  suffix does not start with one.

**GUI — Export Tab** (`mgf_section.py`):

- Two new text fields: **Sequence contains** (filters spectra by
  identification sequence substring) and **File Suffix** (appended to
  file names before timestamp).
- Values are persisted in `ExportTabState` (`mgf_sequence_contains`,
  `mgf_file_suffix`) and passed to `export_mfg`.

### User-Configurable PTM Definitions

All PTM data moved from hardcoded Python constants to editable CSV files
in `~/.config/dasmixer/ptm/`. Files are generated from built-in defaults
on first run and can be edited by the user.

**New module `dasmixer.utils.ptm_config`:**

- `all_ptm_config.csv` — 43 PTMs with columns: `name`, `attach_to`
  (semicolon-separated amino-acid codes), `mono_mass` (float or empty for
  unimod lookup), `n_term`, `c_term`, `default` (`Y`/`N`).
- `import_ptm_renames.csv` — 18 rename entries for MaxQuant, PLGS, and
  PeptideShaker XLS parsers. Columns: `source`, `proforma`, `parser`,
  `is_terminal`.
- Defaults: 3 PTMs marked `default=Y` (Amidated, Deamidated, Pyridylethyl).
- Functions: `load_ptm_config()` and `load_ptm_renames()` — both
  `@lru_cache(maxsize=1)`, auto-create CSV on first call if missing.

**Core — `seqfixer_utils.py`:**

- `PTMS` list now built from `load_ptm_config()` (43 entries) instead of
  3 hardcoded `FixedPTM` objects.
- New module-level constant `DEFAULT_PTM_CODES: frozenset[str]` containing
  the codes of PTMs with `default=Y` in the CSV.

**Core — `IdentificationParser` (`base.py`):**

- New class attribute `PARSER_ID: str | None` — must match the registry
  name (`"MaxQuant"`, `"PLGS"`, `"PeptideShaker XLS"`).
- New static method `get_ptm_renames(parser_id, is_terminal=None)` — reads
  `import_ptm_renames.csv`, filters by `parser` column and optional
  `is_terminal`, returns `dict[source, proforma]` in file order.

**Core — parser renames moved to CSV:**

- `MQ_Evidences.py`: module-level `ptm_replacements` list and
  `_fix_sequence()` method removed. Class now sets `PARSER_ID = 'MaxQuant'`
  and `field_to_proforma = 'Modified sequence'`. `transform_df` only does
  deduplication; PTM replacement is handled by the new
  `SimpleTableImporter.apply_ptm_renames()`.
- `PLGS.py`: module-level `ptm_renames` dict removed. Class sets
  `PARSER_ID = 'PLGS'`. `get_modified_sequence` now calls
  `get_ptm_renames('PLGS')` at runtime.
- `PeptideShaker.py`: module-level `terminal_ptm` and `internal_ptm` dicts
  removed. Class sets `PARSER_ID = 'PeptideShaker XLS'`.
  `to_proforma()` calls `get_ptm_renames(..., is_terminal=True/False)`.

**Core — `SimpleTableImporter` (`table_importer.py`):**

- New attribute `field_to_proforma: str | None` — source column name to
  which substring replacements from `import_ptm_renames.csv` are applied.
- New method `apply_ptm_renames(df)` — sequential `.replace(source, proforma)`
  in the specified column using `IdentificationParser.get_ptm_renames`.
- Called in `parse_batch` after `prepare_df` and before `transform_df`
  (and likewise in `validate`).

**GUI — new default PTM semantics:**

- `tool_settings_section.py`: `_DEFAULT_PTM_CODES` (3 entries) used for
  initial checkbox state when no saved settings exist, and for `None`
  encoding in `save_tool_settings` / `get_tool_settings_for_matching`.
  Previous behavior: `None` meant "all 43 PTMs selected" → now means
  "the 3 default PTMs".
- `ion_actions.py`: comparison changed from `set(ptm_selected) == all_codes`
  (43 PTMs) to `set(ptm_selected) == DEFAULT_PTM_CODES` (3 PTMs).
- PTM selection dialog checkboxes show **site and mass info** in labels:
  e.g. `Acetyl (K, N-term, 42.0106)`, `Amidated (C-term, -0.984016)`.

**Backward compatibility:** for existing projects where
`tool.settings['ptm_list']` is `None`, the UI now shows the 3 default PTMs
instead of all 43. This is an intentionally accepted behavior change (no
data migration).

### Open Configuration Folder Button

**Core — `dasmixer.gui.utils`:**

- New function `open_folder(path)` — cross-platform folder opening via
  `os.startfile` (Windows), `open` (macOS), `xdg-open` (Linux). Creates
  the folder if it doesn't exist.

**GUI — `plugins_view.py`:**

- Static method `_open_directory` removed; calls replaced with
  `open_folder()` from `dasmixer.gui.utils`. Unused `os`/`subprocess`
  imports removed.

**GUI — `settings_view.py`:**

- New `ElevatedButton` "Open configuration folder" (icon `FOLDER_OPEN`)
  placed at the top of the Settings screen, opening
  `typer.get_app_dir("dasmixer")`.

---

## Notes

- **No database migration:** `PROJECT_VERSION` unchanged. The PTM
  semantics change (3 defaults instead of 43) applies only at the UI
  level when `ptm_list` is `None`; back-end functions
  (`identification_processor`, `protein_map`) still treat `None` as "all
  PTMs".
- **No version bumps:** `APP_VERSION` and `PROJECT_VERSION` are not
  changed in this release (no schema changes).
- **PTM CSV hot-reload:** CSV files are read once at import time
  (`@lru_cache`); editing them requires an application restart.

## GUI Design Details

- Sequence contains field: width 250, hint "Filter by substring in
  identification sequence". Placed in a row next to File Suffix.
- File Suffix field: width 200, hint "Appended to file name (before
  timestamp)". Suffix logic (leading `_` insertion, placement before
  timestamp) is handled in `export_mgf`, not in the UI.
- PTM dialog: width 300×300, scrollable column of checkboxes. Each
  checkbox label now includes sites and mass in parentheses.
- Open configuration folder button: top of Settings view, full-width row
  with a divider below it.
