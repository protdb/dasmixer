# v0.7.0a4 — Оптимизация Manage Samples View

**Date:** 2026-07-17

---

## Summary

Полная переработка `ManageSamplesView` — устранение N+1 SQL-запросов, добавление пагинации и фильтрации над данными в памяти, ленивая загрузка тела аккордеонов, персистентность порогов и фильтров. Двухэтапная оптимизация агрегирующего запроса: отказ от единого CTE-запроса с двойным JOIN в пользу split-запросов + Python-схлопывания (ускорение ~50×), и последующий отказ от кэширования статистики в `sample_status_cache` — статистика теперь считается свежим запросом (~0.6с) при каждом открытии view, с показом лоадера.

---

## Core Changes

### Агрегирующий запрос статистики — двухэтапная оптимизация

Подробный анализ — в `docs/review/sample_management_query.md` (раздел 7).

**Этап 1. Переписан `get_all_samples_stats()` (`sample_mixin.py`):**

Исходный единый CTE-запрос (`WITH sf_counts / if_counts / ident_counts / protein_counts`) группировал таблицу `identification` (2.6M строк) по `sample_id`, которого физически нет в этой таблице — требовался двойной JOIN (`identification → spectre → spectre_file`), выполняемый построчно. Заменён на:

- **1 тяжёлый запрос**: `GROUP BY ident_file_id` по `identification` (использует covering index `idx_ident_file`, без JOIN'ов).
- **5 тривиальных запросов** по маленьким таблицам (spectre_file, identification_file, protein_identification_result, sample) + lookup `ident_file_id → sample_id`.
- Все 6 запросов запускаются параллельно через `asyncio.gather`.
- Схлопывание сумм до `sample_id` в Python через dict-lookup; `empty_ident_files_count` считается как set difference (ident_file без записей в `identification`).

Результат на реальной БД (131 sample, 2.6M identifications): **30.3с → 0.6с** (ускорение ~50×), идентичность подтверждена сверкой всех 131 sample × 7 числовых колонок. Схема БД и индексы не менялись.

**Этап 2. Отказ от кэширования в `sample_status_cache`:**

Поскольку свежий запрос стал достаточно быстрым (~0.6с), кэширование статистики в отдельной таблице больше не нужно. Таблица `sample_status_cache` и методы для работы с ней сохранены в коде (для обратной совместимости), но больше **не читаются и не пишутся**.

- `get_sample_status_summary()` переписан: вместо чтения из `sample_status_cache` считает свежие данные через `get_all_samples_stats()`. Поле `uncached` всегда 0 (больше нет "отложенных" sample'ов).
- `add_spectra_file()` / `add_identification_file()`: убраны вызовы `invalidate_sample_status_cache()` (кэш больше не используется, инвалидировать нечего).
- `joined_export.py::_get_sample_details()`: `get_all_cached_sample_stats()` → `get_all_samples_stats()` (свежие данные вместо кэша).

**Сохранившиеся методы кэша (не вызываются, но оставлены в коде):** `upsert_sample_status_cache()`, `upsert_sample_status_cache_batch()`, `get_cached_sample_stats()`, `get_all_cached_sample_stats()`, `invalidate_sample_status_cache()`, `compute_and_cache_sample_stats()`.

## GUI Changes

### Пороги min_proteins/min_idents → project_settings

**`update_row.py`:**

- Конструктор принимает `project: Project` вместо отсутствия параметра.
- Добавлен `on_change` на оба поля порогов → `_save_thresholds()` (сохраняет в `project_settings` по ключам `manage_samples_min_proteins`/`manage_samples_min_idents`).
- Метод `load_thresholds()` — загружает сохранённые значения при открытии вьюхи.
- Пороги больше не сбрасываются на дефолт (30/1000) при переоткрытии.

### Компонент фильтров

**`filters_row.py` (новый файл):**

- `SamplesFilterRow` — панель фильтров: поиск по имени (`TextField`), статус (`Dropdown` OK/WARNING/ERROR), subset (`Dropdown` из subset'ов проекта), outlier (`Dropdown` yes/no/All), кнопка Apply Filters.
- Методы `get_filters()`/`set_filters()` — чтение/установка состояния фильтров.
- Персистентность: ключи `manage_samples_filter_name`, `manage_samples_filter_status`, `manage_samples_filter_subset_id`, `manage_samples_filter_outlier`.

### Компонент пагинации

**`pagination_row.py` (новый файл):**

- `SamplesPaginationRow` — размер страницы (10/20/50/100/All), prev/next кнопки, текст "Showing X-Y of Z".
- Метод `slice(items)` — возвращает срез текущей страницы, работает над списком в памяти (без SQL).
- При выборе "All" — `page_size=None`, `total_rows = len(items)`.

### Вынос формулы статуса

**`sample_panel.py`:**

- Из `_build_sample_header()` вынесена module-level функция `compute_sample_status(stats, tools_count, min_proteins, min_idents) → 'OK' | 'WARNING' | 'ERROR'`.
- `_build_sample_header()` переиспользует `compute_sample_status()`.

### Ленивая загрузка тела аккордеона

**`sample_panel.py`:**

- `build()` теперь создаёт **только заголовок** + лёгкий placeholder (`_collapsed_placeholder()` — `ft.Container(height=0)`) вместо немедленного вызова `_build_body()`.
- Добавлены поля `_body_cache`/`_detail_cache`/`_is_expanded`.
- `on_expand()` — лениво строит тело при первом разворачивании, при повторном — использует кэш.
- `on_collapse()` — удаляет тело из Flet-дерева (оставляет кэш в памяти).
- `invalidate_detail_cache()` — сбрасывает кэш при изменении состава файлов sample'а.

### Data Manager — переход на свежий запрос, без кэша

**`data_manager.py`:**

- `load_all()`: использует `get_all_samples_stats()` вместо `get_all_cached_sample_stats()` — каждый вызов считает свежую статистику (~0.6с).
- `refresh_single()`: убран параметр `save_cache`, не пишет в `sample_status_cache`.
- `refresh_all_fresh()`: упрощён до делегирования `load_all()` (запрос быстрый, отдельный путь не нужен).

### Интеграция пагинации/фильтрации/ленивой загрузки

**`manage_samples_view.py` (полная переработка):**

- Добавлены поля состояния: `_all_stats`, `_filtered_samples`, `_page_samples`.
- `_build_body()`: размещены `SamplesFilterRow` и `SamplesPaginationRow` между `MassOperationsRow` и списком панелей; `ExpansionPanelList` подписан на `on_change=self._on_panel_expansion_changed`.
- `_load_data()`: загрузка порогов + фильтров, затем `_reload_all_with_loader()`. Убран цикл по uncached sample'ам (кэш больше не используется, все sample'ы присутствуют в результате свежего запроса).
- `_reload_all_with_loader()` (новый): единый метод загрузки с лоадером (`UpdateRow.set_loading`), используется при открытии view, после импорта, после массовых операций. Показывает ProgressRing во время выполнения запроса (~0.6с), затем отрисовывает панели.
- `_recompute_filtered()` — фильтрация `self._samples` → `self._filtered_samples` в памяти (без SQL). Применяет поиск по имени, статус, subset, outlier.
- `_recompute_page()` — `self._pagination_row.slice(self._filtered_samples)` → `self._page_samples` (без SQL) + `_rebuild_panels_from_page()`.
- `_rebuild_panels_from_page()` — строит `SampleViewPanel` только для `self._page_samples` (не для всех sample'ов проекта). Заменяет старые `_rebuild_panels()`/`_rebuild_panels_from_cache()`.
- `_on_panel_expansion_changed()` — обработчик `ExpansionPanelList.on_change`; определяет развернули/свернули через `expanded` флаг, вызывает `on_expand()`/`on_collapse()`.
- `_on_apply_filters()` — сохраняет фильтры в `project_settings`, сбрасывает пагинацию на 0, пересчитывает.
- `refresh_single_panel()` + `_refresh_single_stats_in_place()`: убран параметр `save_cache`. При обновлении: инвалидирует detail-кэш, перестраивает панель, сохраняет состояние `_is_expanded` (если панель была развёрнута — автоматически переразворачивает со свежими данными).
- `_on_import_additional_clicked()`/`_on_mass_op_complete()`/`_delete_sample()`/`_on_mass_delete()`: используют `_reload_all_with_loader()` вместо прямого `load_all()` + `_recompute_filtered()`.
- `_on_select_all()`/`_on_deselect_all()`: работают по `self._panel_controls` (текущая страница). `_selected_ids` сохраняется при смене страницы/фильтров.

### DropFileDialog — упрощение

**`dialogs/drop_file_dialog.py`:**

- `_execute_delete()`: убран цикл пересчёта кэша по affected samples (запись в `upsert_sample_status_cache` + `get_sample_stats`). Обновление статистики происходит через `on_complete` → `_reload_all_with_loader()`, который пересчитывает все sample'ы одним быстрым запросом.
