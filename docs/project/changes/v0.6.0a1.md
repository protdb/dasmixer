## Changes

### Block A — Portable Projects

#### Core (`dasmixer-core`)

- **`save(checkpoint=True)`** — new optional `checkpoint: bool = False` argument on `Project.save()`. When `True`, executes `PRAGMA wal_checkpoint(TRUNCATE)` after the commit, consolidating the WAL file into the main database. This enables safe portable copies of `.dasmix` files without needing `-wal` / `-shm` satellites.
- **`save_as()` uses checkpoint** — `save_as()` now calls `save(checkpoint=True)` before `shutil.copy2`, ensuring the copied file is fully self-contained.
- **`vacuum()`** — new method on `Project` that runs `SQLite VACUUM` to reclaim free pages. Expected usage pattern: `await project.save(checkpoint=True)` → `await project.vacuum()`.

### Block B — Project Merge / Import

#### Core (`dasmixer-core`)

- **`ImportProjectMixin`** — new mixin providing `import_project()` method on `Project`. Implements a full 7-step merge of another `.dasmix` file into the current project:

  1. **Subset mapping** — by name (`subset_match=True`) or with conflict suffix (`subset_match=False`)
  2. **Tool mapping** — three strategies: `'parser'` (match by parser name), `'name'` (match by tool name), or `None` (add all as new)
  3. **Sample mapping** — by name or with suffix; IDs offset by `MAX(id)` of target samples; `subset_id` remapped via step 1
  4. **Bulk insert** via `ATTACH DATABASE` — 10 tables (`protein`, `spectre_file`, `spectre`, `identification_file`, `identification`, `peptide_match`, `protein_identification_result`, `protein_quantification_result`, `generated_reports`, `saved_plots`) — IDs offset by `MAX(id)`, FK columns remapped via temp mapping tables (`_sample_id_map`, `_tool_id_map`)
  5. **Project settings** — `INSERT OR REPLACE` or `INSERT OR IGNORE` depending on `project_settings_match`
  6. **Autoincrement reset** — `sqlite_sequence` updated for all 12 tables
  7. **Finalization** — `DETACH`, restore PRAGMA, `save(checkpoint=True)`

  Entire operation runs in a single `BEGIN/COMMIT` transaction; `ROLLBACK` on any error. Progress callback (`status_callback(table_name, fraction)`) called between steps.

- **`ImportProjectMixin` registered** in `Project` MRO (between `ProteinMixin` and `PlotMixin`) and exported from `mixins/__init__.py`.

## Bug Fixes

- **PRAGMA inside transaction** (`import_project_mixin.py`) — `PRAGMA synchronous` and `PRAGMA cache_size` were being set after `BEGIN`, which SQLite rejects with "Safety level may not be changed inside a transaction". Moved both PRAGMA saves and changes to **before** `BEGIN`, keeping the restore in `finally` (after COMMIT/ROLLBACK).

## What is NOT included in 0.6.0

- Recalculation of `sample_status_cache` after import — manual via GUI.
- Import of `report_parameters` — not transferred.
- Import of `project_metadata` (version, created_at, modified_at) — taken from target project.
- Progress bar in CLI (`typer.progressbar`) — text-only status lines.
- Cancel button during import — `ProgressDialog` is not cancelable.
