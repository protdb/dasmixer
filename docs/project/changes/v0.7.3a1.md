## New Features

### Экспорт MGF: режим Merge MGF + флаг «Add timestamp to file name»

Добавлен выбор режима объединения спектров при экспорте MGF через radio-группу **Merge MGF** в разделе Export → MGF:

- **One file** — все спектры выбранных образцов объединяются в один файл `dasmixer_mgf.mgf`. В этом режиме `zip_all` и `zip_each` дают идентичный результат (один архив с одним MGF внутри).
- **By sample** (поведение по умолчанию, как раньше) — по одному MGF-файлу на каждый образец, имя `{sample_name}.mgf`.
- **By Spectre file** — по одному MGF-файлу на каждый `spectre_file` образца (без объединения спектров из разных файлов), имя `{sample_name}_{spectre_file_id}.mgf`.

Новый чекбокс **Add timestamp to file name** управляет добавлением суффикса `_YYYYMMDD_HHMMSS` к именам выходных файлов и zip-контейнера (включён по умолчанию, совместимо с предыдущим поведением). При выключении таймстемп не добавляется нигде.

### Экспорт MGF: флаг «Replace SCANS with Spectre ID»

Новый чекбокс **Replace SCANS with Spectre ID** в разделе Export → MGF. При включении в поле `SCANS` выходного MGF записывается числовой идентификатор спектра в БД проекта (`spectre.id`) вместо оригинального значения `SCANS` из исходного файла. Это позволяет однозначно сопоставить строки MGF со спектрами в проекте при последующей внешней обработке, независимо от пересечения диапазонов `seq_no`/`scans` между несколькими `spectre_file` одного образца.

## Bug Fixes & Improvements

### Исправление выбора `spectre_file` при импорте идентификаций для образцов с несколькими спектральными файлами

**Проблема:** при batch-импорте идентификаций (CLI `ident-pattern`/`ident-file` без `--spectra-file-id`, GUI pattern-диалог) для образца, имеющего несколько `spectre_file`, всегда выбирался «первый по `id`» без проверки соответствия содержимому. Это могло приводить либо к нулевому импорту (диапазоны `seq_no`/`scans` не пересекаются), либо к тихой порче данных (пересекающиеся `seq_no`/`scans` → идентификации привязываются к чужим спектрам).

**Решение:** детерминированная авто-привязка identification-файлов к `spectre_file` по имени: файлы сортируются по `basename(path)` внутри каждого образца и сопрягаются позиционно (i-й identification-файл → i-й `spectre_file`). Лишние identification-файлы (когда их больше, чем `spectre_file`) пропускаются с предупреждением.

- **Core:** утилита `resolve_ident_to_spectra_mapping()` в `dasmixer/utils/ident_spectra_pairing.py`.
- **CLI `ident-file`:** при отсутствии `--spectra-file-id` выбор «первый по basename» вместо «первый по id».
- **CLI `ident-pattern`:** pre-pass с группировкой файлов по образцу и авто-привязкой, лишние пропускаются.
- **GUI pattern-диалог:** для identification-файлов при Preview Files показывается выпадающий список Spectre file со всеми `spectre_file` образца (значение по умолчанию — авто-пара, доступна ручная замена). Файлы без пары помечаются красным как skipped и исключаются из импорта. В callback передаётся 3-tuple `(path, sample_id, spectra_file_id)`.
- **GUI handler:** поддержка 3-tuple из pattern-диалога (обратно совместима с 2-tuple); fallback-выбор «первый по basename» при отсутствии явного `spectra_file_id`.

**Вне scope:** stacked-импорт, single-импорт, legacy `samples_tab.py`, панельный импорт (уже корректно передаёт явный `fixed_spectra_file_id`).
