# v0.7.5a3

**Date:** 2026-11-26

---

## Summary

Реализована спецификация 0.7.5a3: определение и отображение пика прекурсора на графике ионной разметки, а также его исключение из метрик Quality / LCRR / Peaks covered / Top peaks covered с сохранением в Intensity Coverage и Unconfirmed PTMs.

Пик прекурсора — это фрагментный ион, полностью покрывающий последовательность пептида (full-length b/y со всеми вариантами потерь `-H2O`/`-NH3` и заряда). Он рисуется с чёрным контуром и меткой `P` + loss + charge (`P`, `P-H2O`, `P+2`, …), а в hover добавляется суффикс `(Precursor peak)`.

Спецификация: `docs/project/spec/0.7.5a3_SPEC.md`.

## Core Changes

### Детекция прекурсора и метрики (`calculations/spectra/ion_match.py`)

- Новый helper `is_precursor_match(match, full_sequence)`: возвращает `True`, если `match.fragment.sequence == full_sequence`.
- `MatchResult` дополнен полем `precursor_matches: list[FragmentMatch]` (в конец, `field(default_factory=list)`, чтобы не ломать существующие конструкторы).
- `match_predictions` сохраняет объект `Fragmenter` и вычисляет `full_sequence = fragmenter.annotation.serialize()` **после** `fragment()` (labile-модификации вырезаются внутри `fragment()` — это единственный корректный эталон для сравнения). Матчи разбиваются на `precursor_matches` и `metric_matches`.
- Метрики, считаемые **без** precursor-матчей: Quality, LCRR, `get_match_coverage` (`max_ion_matches` / `top_matched_ion_type`), `top10_intensity_matches`.
- Метрики, считаемые **по полному** списку матчей: Intensity Coverage и Unconfirmed PTMs (код не менялся).
- `get_matches_dataframe` дополнен колонками `is_precursor` (bool) и `display_label` (для прекурсора — `P{loss}{charge}`, иначе совпадает с `label`); `label` остаётся исходным для hover. После `pd.merge` флаг нормализуется через `fillna(False).astype(bool)` — иначе у несовпавших пиков `NaN` (а `bool(nan) == True`).
- Граничные случаи: `total_peaks == 0` — `MatchResult` создаётся без ошибок (поле берётся из дефолта); «только прекурсор» — Quality=0, LCRR=0, `ions_matched`=0, `top_peaks_covered`=0, `unconfirmed_ptms`=0, Intensity Coverage и `total_peaks` не меняются.

### Рендеринг (`calculations/spectra/plot_matches.py`)

- Hover: `customdata` расширен до трёх полей (`frag_seq`, `label`, суффикс); для прекурсора суффикс — ` (Precursor peak)`, для остальных — пустая строка. Для DataFrame без колонки `is_precursor` — fallback (суффикс пустой).
- Бар прекурсора: чёрная обводка (`line={'color': 'black', 'width': 2}`); тело бара остаётся `lightgray`.
- Аннотация: текст — `display_label` (fallback на `label`), цвет чёрный для прекурсора, иначе цвет типа иона.
- Защита от `bool(nan)` при чтении флага (`pd.notna` — `bool(nan) == True`).

## Verification

- Синтетический спектр `PEPTIDE` (charge 1, b/y, water+ammonia losses): 8 матчей → 4 прекурсора (`P`, `P-H2O`, `P-H2O`, `P`); Quality 0.3333→0.1667, LCRR 0.4286→0.2857, `max_ion_matches` 6→4, top-10 8→4; intensity 100 %, unconfirmed 0.
- Граничный случай «только прекурсор»: Quality=0, LCRR=0, `ions_matched`=0, `top_peaks_covered`=0, intensity=100 %, `unconfirmed_ptms`=0.
- Пустой спектр и «нет матчей» — отрабатывают без ошибок, колонки присутствуют.
- Рендеринг: 4 прекурсор-пика с чёрной обводкой и чёрными `P`-аннотациями; DataFrame без новых колонок (пример из docstring) рендерится без ошибок.
- Совместимость: конструктор `MatchResult` вызывается только в `ion_match.py`; потребители (`identification_processor`, `coverage_worker`, `protein_map_worker`, `plot_flow`) используют атрибуты по имени с `getattr(..., None)` — поле в конце с дефолтом не ломает их.
