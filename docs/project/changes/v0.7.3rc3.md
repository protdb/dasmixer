## New Features

### Импортируемые поля FDR, e-value, q-value в таблице Identifications

В таблицу `identification` добавлены три новых импортируемых поля:

| Поле | Тип | Назначение |
|---|---|---|
| `fdr` | `REAL` (nullable) | False Discovery Rate |
| `e_value` | `REAL` (nullable) | e-value |
| `q_value` | `REAL` (nullable) | q-value |

Поля **импортируемые** (не расчётные) — заполняются при импорте файла идентификаций через `ColumnRenames` (опционально); при отсутствии во входном файле — `NULL` в БД. Поля **переживают** Clear Calculations (в отличие от `quality`/`lcrr`/`intensity_coverage` и других расчётных полей).

Новые поля доступны в `ColumnRenames`:
- `fdr` — имя колонки источника для FDR
- `e_value` — имя колонки источника для e-value
- `q_value` — имя колонки источника для q-value

Все три параметра опциональны, могут отсутствовать во входных данных.

> **Скоуп — только инфраструктура.** Настройка конкретных парсеров (PowerNovo2, MQ_Evidences, PLGS, PeptideShaker и др.) на передачу этих полей выполняется отдельно. Ни один парсер пока не задаёт `fdr`/`e_value`/`q_value` в `ColumnRenames` — поля будут `NULL` до настройки парсеров.

### Фильтр Max FDR в Preferred-настройках инструмента

В карточку инструмента (Block 2 «Preferred settings:») добавлен новый контрол **Max FDR** (по умолчанию `0.01`, диапазон `[0, 1]`). Фильтр применяется **только к normal-пулу** `get_idents_for_preferred` (для trusted-пула с флагом `ignore_criteria`/«Trust all identifications» фильтр не действует, симметрично `min_quality`/`min_lcrr`).

**Семантика NULL-прохода:** фильтр Max FDR в Preferred-настройках пропускает идентификации с `fdr IS NULL` — условие `(i.fdr IS NULL OR i.fdr <= ?)`. Обоснование: FDR — не расчётная величина, её отсутствие не означает ошибку, в отличие от `quality`/`lcrr`.

Фильтр проброшен через всю цепочку:
- `tool_settings_section.py` → сохранение в `tool.settings['max_fdr']`
- `matching.py` → чтение из `tool_params` и передача в `get_idents_for_preferred`
- `identification_mixin.py::get_idents_for_preferred` → SQL WHERE с NULL-проходом

### Табличный фильтр Max FDR на вкладке Peptides

Добавлен табличный фильтр **Max FDR** на вкладке Peptides (рядом с `Min Quality`). По умолчанию пуст (фильтр отключен — видны все строки).

**Строгая семантика** (симметрично `Min Quality` в таблице): при заданном пороге идентификации с `fdr IS NULL` **отбрасываются** — условие `(id.fdr IS NOT NULL AND id.fdr <= ?)`. Чтобы увидеть строки без FDR — поле оставляют пустым.

Фильтр проброшен через:
- `peptide_ion_table_view.py` → UI-поле + сериализация в `kwargs['max_fdr']`
- `joined_peptide_data_mixin.py::_build_peptide_filter_conditions` → строгий SQL WHERE
- Сигнатуры `get_joined_peptide_data`, `count_joined_peptide_data` → параметр `max_fdr`

### Колонки FDR, e-value, q-value в таблице Peptides

В `header_name_mapping` таблицы Peptides добавлены три колонки с читаемыми именами:
- `FDR` (`fdr`)
- `e-value` (`e_value`)
- `q-value` (`q_value`)

**По умолчанию колонки скрыты** (не добавлены в `default_columns`), но могут быть включены через gear-диалог выбора столбцов.

Колонки доступны в `get_joined_peptide_data` (внешний SELECT: `id.fdr, id.e_value, id.q_value`; внутренний подзапрос: `i.fdr, i.e_value, i.q_value`) и `count_joined_peptide_data`.

## Migrations

- **PROJECT_VERSION** повышен с `0.7.2` до `0.7.3` — миграция `0.7.3` добавляет три колонки в `identification`:
  ```sql
  ALTER TABLE identification ADD COLUMN fdr REAL;
  ALTER TABLE identification ADD COLUMN e_value REAL;
  ALTER TABLE identification ADD COLUMN q_value REAL;
  ```
- При открытии проекта версии ≤ `0.7.2` в GUI отрабатывает `apply_migrations()`, `project_metadata.version` становится `0.7.3`.
- Bulk-копирование в `import_project_mixin.py` синхронизировано с новой схемой (правило 15 AGENTS.md).

## Notes

- Парсеры не настроены — все три поля будут `NULL` в БД до отдельной задачи по настройке конкретных форматов.
- `put_identification_data_batch`, `clear_calculations`, `identification_processor.py`, `IdentificationWithSpectrum` **не затронуты** — поля импортируемые, не расчётные.
- `e_value` и `q_value` — только отображаемые колонки, без фильтров.
- В `get_all_idents_for_preferred` добавлен `i.fdr` в SELECT (для консистентности конкатенации с нормальным пулом); `e_value`/`q_value` не добавлены (не используются в preferred-выборе).
- Legacy CLI-путь `select_preferred_identifications` не затрагивался (вне скоупа).
