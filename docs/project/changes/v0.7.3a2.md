## New Features

### Интеграция импорта проектов MaxQuant (mqpar.xml + txt + apl)

Полноценный импорт результатов MaxQuant напрямую в DASMixer-проект без промежуточных утилит.
Функциональность перенесена из standalone-утилиты `mq2dasmix` и интегрирована в core/GUI/CLI.

**Core — новый модуль `MaxQuantProject`** (`dasmixer.api.inputs.complex`):

- `mqpar_parser.py` — парсинг `mqpar.xml` (lxml), извлечение путей к FASTA, TXT, RAW-файлам.
- `apl_convert.py` — чтение `msms.txt`/`msmsScans.txt`, конвертация `.apl` → MGF + CSV (идентификации).
  Новый параметр `keep_contaminants` управляет фильтрацией `Potential contaminant` (Decoy всегда отбрасываются).
- `importer.py` — оркестратор `run_maxquant_import()`: создание tool/subset/sample, импорт спектров (MGFParser) + идентификаций (MaxQuantEvidenceParser) + опционально белков (FastaParser). Поддержка on-duplicates (skip/reload/add_as_new). Не открывает/закрывает Project самостоятельно.
- `progress.py` — общий тип `MaxQuantImportProgress` для GUI/CLI.

**Core — новое:**

- `get_maxquant_import_temp_dir()` в `config.py` — временная директория `~/.cache/dasmixer/tmp/maxquant_import/<ts>/`.
- Прямая зависимость `lxml >=5.0.0,<7.0.0` в `dasmixer-core`.

**GUI — Samples Tab:**

- Новая секция `MaxQuantImportSection` в один ряд с `ImportSection` (кнопка «Import From MaxQuant...»).
- Новый диалог `ImportMaxQuantDialog` с тремя экранами:
  1. **MQPar File** — выбор `mqpar.xml` + кнопка Parse.
  2. **Configure** — редактируемые пути (RAW/TXT/FASTA) со статус-иконками; поле Tool name с проверкой parser; список RAW-файлов с чекбоксами (Select All/Deselect All); чекбоксы «Import proteins from FASTA», «Sequences are in UniProt format», «Delete temporary files», «Skip contaminant identifications»; radio on-duplicates.
  3. **Progress** — прогресс-бар без возможности отмены.
- Кнопка Import блокируется при несуществующих путях, несовпадении parser у Tool, отсутствии отмеченных RAW-файлов.

**CLI — новая команда:**

- `dasmixer-cli import maxquant PROJECT_PATH MQPAR_PATH` с опциями `--fasta-path`, `--raw-path`, `--txt-path`, `--tool-name`, `--subset-name`, `--keep-contaminants`, `--delete-temporary-files`/`--keep-temporary-files`, `--import-fasta`/`--no-import-fasta`, `--fasta-uniprot`/`--fasta-generic`, `--on-duplicates`.
- Проект создаётся автоматически, если не существует (`create_if_not_exists=True`).
- Несовпадение `Tool.parser` — жёсткая ошибка `typer.Exit(1)`.

### Альтернативный режим PCA: точка = (белок × группа)

В отчёт `PCA ROC-AUC` добавлен новый режим разбивки точек данных. Раньше
каждая точка соответствовала образцу (sample) и описывалась вектором LFQ
по всем белкам. Теперь доступен режим **Protein**, где точка — это пара
**(protein_id, subset)**, а признаки — отсортированный профиль LFQ-значений
белка внутри группы.

**Логика режима Protein:**

- Точка = `(protein_id, subset)`.
- Признаки: `rep_1..rep_N`, где значения LFQ белка внутри группы
  **отсортированы по убыванию** (rep_1 = максимум), N = максимальное число
  реплик среди всех пар (protein, subset).
- Если у пары меньше реплик, чем N — недостающие ячейки заполняются
  **средним по этой же строке** (по реально измеренным значениям).
- Ограничение количества белков: **top_n_proteins** (по умолчанию 100), отбор
  — по дисперсии LFQ по всем выбранным образцам (глобально, до разбивки).
- Подпись точки: **gene** (fallback: `protein_name` → `fasta_name` →
  `protein_id`).
- Цвет/группа точки = `subset` (как и в режиме Sample).
- ROC/AUC — работает по той же схеме (PC1 vs subset, one-vs-rest).

**Параметры формы (`PCAReportForm`):**

- `group_by` — `EnumSelector` (`"Sample"` / `"Protein"`, default `"Sample"`).
- `top_n_proteins` — `IntSelector` (default 100, применяется только в
  режиме Protein).
- `show_labels` — переименован с «Show sample labels» на «Show point labels».

**Переиспользование кода:** `_compute_pca`, `_compute_roc` и
`_build_pca_figure`/`_build_roc_figure` работают в обоих режимах без
изменений логики — добавлен только параметр `entity_name` для заголовков.
Новый хелпер `_build_protein_group_matrix` строит матрицу из длинного
DataFrame. Режим Sample не изменился.

### Согласованные ограничения (см. раздел 1 спецификации)

- `.apl` только из `{raw_parent}/{raw_name}/p0/` (`combined/andromeda` не поддерживается).
- Несколько `raw_parents` — используется только первый.
- Cancel недоступен во время прогресса импорта.
- Debug-опция `--limit` не перенесена.

## Notes

- Миграция БД не требуется — схема без изменений, все данные пишутся в существующие таблицы.
- Временные файлы создаются в `~/.cache/dasmixer/tmp/maxquant_import/<timestamp>/` и удаляются по завершении (если включён «Delete temporary files»).
- Тяжёлые синхронные вызовы (`load_and_merge`, `process_apl`) обёрнуты в `asyncio.to_thread()` для неблокирующего прогресса.

## GUI Design Details

- Path fields (RAW/TXT/FASTA) have **Browse buttons** with native file/folder pickers:
  - RAW and TXT paths use `get_directory_path()` (folder picker).
  - FASTA path uses `pick_files()` with `*.fasta`, `*.fa`, `*.fas`, `*.txt` filters.
- Each path field has a green (valid) / red (invalid) **status icon** that updates on change/blur.
- Tool name field: green check if tool doesn't exist OR exists with `parser == "MaxQuant"`; amber warning if exists with a different parser.
- **Import** button is disabled until: all paths are valid (or FASTA import is unchecked), tool status is OK, at least one RAW file checkbox is selected.
- Clicking **Import** immediately replaces the configure dialog with a progress screen showing `Processing {raw_name} ({idx}/{total})`.
- All heavy blocking operations (`load_and_merge`, `process_apl`) run on worker threads, ensuring the progress bar updates smoothly.
- **Cancel** is available only on the MQPar and Configure screens — not during progress.

## Fixes During Implementation

- `process_apl` and `load_and_merge` wrapped in `asyncio.to_thread()` to prevent event-loop blocking and enable real-time progress updates.
- Flet 0.81.0 API corrections: `ft.Icon(icon=...)` positional parameter, `.icon` property (not `.name`).
- Function definition ordering in `_show_screen2` changed to avoid `NameError` in closures.
- Dialog close simplified to `self.dialog.open = False` + `self.page.update()` (matching existing codebase pattern).
