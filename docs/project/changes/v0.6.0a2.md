# v0.6.0a2 — Windows Build Fixes

**Date:** 2026-06-17

---

## Changes

### Windows dependency: `npysearch-win`

`npysearch` не собирается под Windows, поэтому добавлен условный форк `npysearch-win`, который доступен на PyPI и поставляется с готовыми wheels для Python 3.10–3.14 / win_amd64.

Оба пакета устанавливают модуль с одинаковым именем `npysearch`, поэтому код вызовов не изменился.

**`dasmixer-core/pyproject.toml`**

- `[project.optional-dependencies].proteins` — заменён на два условных пакета с PEP 508 environment markers:
  ```toml
  "npysearch >=1.3.1,<2.0.0 ; sys_platform != 'win32'"
  "npysearch-win >=1.3.1,<2.0.0 ; sys_platform == 'win32'"
  ```
- `[tool.poetry.dependencies]` — убраны ручные URL-зависимости на GitHub releases (`.whl`-файлы от `protdb/npysearch`); заменены на стандартные версионные записи с маркерами.

**`dasmixer-core/src/dasmixer/api/calculations/peptides/protein_map.py`**

- `import npysearch as npy` обёрнут в `try/except ImportError` — при отсутствии пакета `npy = None`.
- В начале `map_proteins()` добавлена явная проверка: если `npy is None` — выбрасывается `ImportError` с понятным сообщением об установке `dasmixer-core[proteins]`.

### Сборка PyInstaller: шаблоны Jinja2 не попадали в бандл

При запуске собранного приложения при экспорте отчётов возникала ошибка:

```
jinja2.exceptions.TemplateNotFound: 'report.html.j2'
```

Причина: `.j2`-файлы не были указаны в `datas` spec-файла — PyInstaller копирует только `.py`-модули, data-файлы нужно добавлять явно.

**`dasmixer.spec`** — в блок `datas` добавлены два entry:

```python
# report export template (base.py → Path(__file__).parent / 'templates')
(
    "dasmixer-core/src/dasmixer/api/reporting/templates",
    "dasmixer/api/reporting/templates",
),
# plots export template (plots_tab.py → Path(__file__).parent / 'templates')
(
    "dasmixer-gui/src/dasmixer/gui/views/tabs/plots/templates",
    "dasmixer/gui/views/tabs/plots/templates",
),
```

Целевые пути совпадают с тем, что вычисляет `Path(__file__).parent / 'templates'` в замороженном процессе, поэтому изменений в Python-коде не потребовалось.

### Сборка PyInstaller: Kaleido/Chrome — неверный путь к исполняемому файлу

При первом запуске приложение скачивало Chrome через `kaleido.get_chrome_sync()`, но затем не могло его найти:

```
[Kaleido] Chrome installed: ...chrome\chrome-w\chrome.exe
```

Реальная директория после загрузки — `chrome-win64`, а не `chrome-w`. Причина: имя папки формировалось через `get_google_supported_platform_string()` из внутреннего API choreographer, который возвращал сокращённый идентификатор платформы, не совпадающий с фактическим именем директории, создаваемой Kaleido.

**`dasmixer-gui/src/dasmixer/gui/main.py`**

- Добавлена вспомогательная функция `_find_chrome_exe(chrome_dir)` — ищет исполняемый файл через `glob("chrome-*/chrome.exe")` (Windows), `glob("chrome-*/chrome")` (Linux) или соответствующий паттерн для macOS. Не зависит от конкретного имени подпапки.
- `_ensure_chrome()` переписана с использованием `_find_chrome_exe()` вместо ручной сборки пути; убрана зависимость от `choreographer.cli._cli_utils.get_google_supported_platform_string`.
- `BROWSER_PATH` устанавливается по реальному найденному пути.
