**Date:** 2026-09-01

## New Features

### Longest Consecutive Run Ratio (LCRR)

- Показатель **LCRR** (Longest Consecutive Run Ratio, 0..1) теперь сохраняется в БД (`identification.lcrr`) при расчёте Ion Coverage. Расчёт — на основе функции `calculate_longest_consec_run_ratio` в `quality_calculations.py`, значение уже возвращается полем `MatchResult.longest_consec_run_rate` из `match_predictions` (реализация — в 0.7.1).
- **LCRR** — отношение длины максимальной непрерывной последовательности совпавших ионов одного типа к длине пептида. Косвенный показатель качества спектра: чем ближе к 1, тем непрерывнее подтверждение теоретическими ионами.
- **Min LCRR** (по умолчанию 0.2) — новый параметр Preferred settings инструмента. Фильтрует кандидатов в Select Preferred: идентификации с `lcrr < Min LCRR` (или без вычисленного LCRR) не выбираются preferred через normal-пул; trusted-пул (`Trust all identifications`) игнорирует этот порог, как и все остальные.
- При Clear Calculations поле `lcrr` сбрасывается в NULL наравне с остальными расчётными полями.

### Peptide Table

- Новая колонка **LCRR** видна по умолчанию в таблице Peptide Identifications (после Quality). Для необсчитанных идентификаций отображается пустое значение. Колонку можно скрыть/показать через стандартный gear-диалог выбора столбцов.


### Interactive mode

- Для графиков разметки ионов в интерактивном режиме теперь при наведении отображается подпись с последовательностью фрагмента.
- **Платформозависимая директория для Browser-mode:** на Linux и macOS временные HTML-файлы интерактивных графиков/отчётов сохраняются в `~/.cache/dasmixer/tmp/plots/` вместо системного `/tmp`. Это решает проблему с Firefox, который отказывается открывать `file://` URL, указывающие на `/tmp`. На Windows поведение не изменилось — используется `tempfile.gettempdir()`.
- `cleanup_temp_html_files()` теперь вызывается **один раз при старте приложения** (а не при каждом открытии/закрытии проекта). Удаляются только файлы старше 24 часов (по `mtime`), что безопасно при одновременном запуске нескольких экземпляров приложения.

## Bug Fixes

### ProForma: 2+ N-terminal modifications

- **Ошибка:** при разборе ProForma-последовательностей с двумя и более N-терминальными модификациями возникала ошибка парсинга. Баг находился в самой библиотеке `pyteomics` (версии < 5.0.1).
- **Решение:** обновление `pyteomics` до 5.0.1, где этот баг исправлен (см. [Dependencies](#dependencies)).
