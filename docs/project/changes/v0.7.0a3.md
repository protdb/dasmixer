## New Features (Part 1 — Tool Settings Form + PPM/PTM Logic)

### UI — форма параметров инструмента (4 блока, блокировка, новые флаги)

**`tool_settings_section.py`:**
- Форма перестроена в 4 визуальных блока: Block 1 (без заголовка, 4 чекбокса 2×2), Block 2 "Preferred settings:", Block 3 "PTM", Block 4 "Protein search"
- Блоки 2-4 разделены тонкой линией сверху (`border-top: 1px solid grey`), без общей рамки, без сворачивания
- Добавлен новый чекбокс **Trust PPM** (`trust_ppm`, default `False`) — не блокирует ничего
- Добавлен новый чекбокс **Recalculate PTMs** (`recalculate_ptms`, default `True`) — при установленном флаге блокирует Block 3 (PTM)
- Лейбл `leucine_combinatorics` переименован: `"Use Leucine Combinatorics (I/L)"` → `"I/L Combinatorics"` (ключ в tool.settings не изменился)
- Реализована блокировка контролов: `ignore_criteria` → Block 2, `use_protein_from_file` → Block 4, `recalculate_ptms` → Block 3 (инверсно: disabled когда True)
- `save_tool_settings()` и `get_tool_settings_for_matching()` сохраняют/возвращают `trust_ppm` и `recalculate_ptms`

### Core — Trust PPM (логика пропуска пересчёта)

**`identification_processor.py`:**
- `process_single_ident()`: новый параметр `trust_ppm: bool = False`, `existing_ppm: float | None = None`. При `trust_ppm=True` и `existing_ppm is not None` — SeqFixer не вызывается, ppm из БД используется как есть, `isotope_offset=0`, charge подбирается по спектру или из `override_charges`
- `process_identificatons_batch()`: новые параметры `trust_ppm: bool = False`, `unallocated_only: bool = False`. SeqFixer создаётся с `unallocated_only=unallocated_only`. В `process_single_ident()` прокидывается `trust_ppm` и `existing_ppm=item.get('ppm')`

### Core — Recalculate PTMs / unallocated_only

**`seqfixer.py`:**
- `SeqFixer.__init__()`: новый параметр `unallocated_only: bool = False`
- `get_ppm()`: при `unallocated_only=True` — `ptm_sites = []` (не перебирает новые PTM-кандидаты из `attach_to`; существующие модификации на фиксированных позициях остаются)
- `_expand_unlocalized()` не затрагивается — unlocalized-модификации перебираются как обычно
- `get_matched_ppm()` (protein_map.py) не затрагивается

### Core — проброс ppm в worker

**`dataclasses.py`:** `IdentificationWithSpectrum` — добавлено поле `ppm: float | None = None`, обновлены `from_dict()` и `to_worker_dict()`

**`identification_mixin.py`:** `get_identifications_with_spectra_batch()` — добавлен `i.ppm` в SELECT

### GUI — проброс флагов в пайплайн

**`ion_actions.py`:**
- `IonCoverageAction.run()`: читает `trust_ppm` и `recalculate_ptms` из `state.tool_settings_controls`, вычисляет `unallocated_only = not recalculate_ptms`
- `_compute_batch()`: принимает и передаёт `trust_ppm` и `unallocated_only` в `process_identificatons_batch()`

## Bug Fixes

### `matching.py` — KeyError: nan при выборе preferred идентификации

**Проблема:** `candidates['_sort_key'].idxmin()` возвращал `nan`, когда все значения `_sort_key` были `NaN` (ppm или intensity_coverage равны None). Это приводило к `KeyError: nan` в `candidates.loc[nan, 'id']`.

**Fix — `matching.py`:** Добавлен `dropna()` перед `idxmin()`/`idxmax()` — если после удаления NaN кандидатов не осталось, спектр пропускается.

### "Trust all identifications" — `ignore_criteria` не сохранялся в БД

**Проблема:** Флаг `ignore_criteria` (Trust all identifications) в настройках инструмента на вкладке Peptides никогда не попадал в базу данных. В методе `save_tool_settings()` ключ `ignore_criteria` отсутствовал в словаре настроек, поэтому при повторной загрузке проекта значение всегда сбрасывалось в `False`.

**Fix — `tool_settings_section.py`:** Добавлен `'ignore_criteria': bool(controls['ignore_criteria'].value)` в словарь `tool.settings` в методе `save_tool_settings()`.

### "Trust all identifications" — логика выбора preferred идентификаций

**Проблема:** Функция `calculate_preferred_identifications_for_file()` полностью игнорировала `ignore_criteria` — всегда применяла все фильтры качества (PPM, score, coverage, длина пептида, кол-во пиков, ионов) через `get_idents_for_preferred()`. Кроме того, критерий выбора (`ppm` / `intensity`) не применялся — всегда выбирался лучший по `min_ppm`.

**Fix — `matching.py`:** Полностью переписана `calculate_preferred_identifications_for_file()`:
- Инструменты с `ignore_criteria=True` формируют **trusted pool** — все идентификации без фильтров качества
- Инструменты с `ignore_criteria=False` формируют **normal pool** — с фильтрацией по стандартным критериям
- **Приоритет:** для каждого спектра сначала выбирается лучшая идентификация из trusted pool; если их нет — из normal pool
- Критерий выбора (`ppm` → min |PPM|, `intensity` → max intensity_coverage) корректно применяется в обоих пулах

**Fix — `identification_mixin.py`:** Добавлен новый метод `get_all_idents_for_preferred()` — возвращает все идентификации для файла+инструмента без WHERE-фильтров по качеству. Колонки совместимы с `get_idents_for_preferred()`.
