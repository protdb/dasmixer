## Bug Fixes

### Unlocalized PTM (ProForma `?` notation) Crash & Infinite Loop

**Problem:** Identifications with unlocalized modifications (e.g., `[Deamidated]?FQNALLVR`) caused `Fragmenter` from `peptacular` to throw an exception because it only supports positioned ProForma. The exception was silently swallowed (worker logger sent to no-op logger when `log_to_file=False`), and `intensity_coverage=None` was written to DB. On the next run with `only_missing=True`, the same rows were re-read at offset=0, creating an infinite loop.

**Fix — `seqfixer.py`:** New function `_expand_unlocalized()` — extracts `unlocalized_modifications` from ProForma params, finds valid attachment sites per `ptm_list`, generates all positioned variants using `combinations` (for duplicate mods) + `product` (across different mod groups). **Guard** (`_MAX_UNLOCALIZED_COMBOS=256`): when variant count exceeds limit, each group's site list is reduced to `[first, last]` to keep combos tractable. Falls back to canonical sequence when no valid site exists.

**Fix — `identification_processor.py`:** `process_single_ident()` now detects `'?' in sequence`, calls `_expand_unlocalized()`, runs `match_predictions` for each variant, and picks the winner by `intensity_percent`. Original `ppm`/`theor_mass` (correctly calculated by pyteomics proforma) are preserved.

**Fix — Exception handler robustness:** `intensity_coverage: None` changed to `intensity_coverage: 0` — failed rows are written as processed (0% coverage) rather than unprocessed (`NULL`), preventing infinite re-processing. Added unconditional `print(..., file=sys.stderr, flush=True)` fallback to make errors visible regardless of logger config.

### Schema — `protein_quantification_result` columns mismatch

**Problem:** The `CREATE TABLE` statement in `schema.py` still used the old column name `abs_value REAL`, while migration 0.7.0 renames it to `abs_value_mol REAL` and adds `abs_value_gl REAL`. A project created from scratch (without migration path) would have the wrong schema, causing `add_protein_quantifications_batch` to fail with `no such column: abs_value_mol`.

**Fix:** Updated `schema.py` CREATE TABLE to match the post-migration state: `abs_value REAL` → `abs_value_mol REAL` + `abs_value_gl REAL`.
