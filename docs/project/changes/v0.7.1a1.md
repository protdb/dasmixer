## New Features

### Identification Quality
- Показатель **Quality** (0..1) теперь сохраняется в БД (`identification.quality`) при расчёте Ion Coverage. Расчёт — на основе `calculate_peptide_quality` (Bern et al., 2004, https://doi.org/10.1093/bioinformatics/bth947).
- **Quality Threshold** (по умолчанию 0.25) — новый параметр Preferred settings инструмента; гейтит перебор PTM в SEQFixer (High Quality → только charge/isotope, не PTM) и фильтрует кандидатов в Select Preferred (кроме инструментов с *Trust all identifications*).
- SEQFixer: `get_ppm` получил параметр `allow_ptm`; `match_predictions` теперь выполняется **до** SeqFixer на исходной последовательности; результат reuse'ится, когда SeqFixer не меняет последовательность (только charge/isotope).
- Новые поля `identification`: `override_pepmass` (исправленный precursor m/z при isotope offset, иначе NULL), `has_ptm` (1 если финальная sequence != canonical_sequence).
- Исключение: последовательности с unlocalized PTM (`?`) — pre-match не выполняется, поведение раскрытия вариантов сохранено.

### Peptide Table: новые колонки и фильтры
- В `get_joined_peptide_data` добавлены: `override_charge`, `override_pepmass`, `source_sequence`, `theor_mass`, `quality`, `peaks_count`, `has_ptm`, `isotope_offset` (helper).
- Таблица Peptide Identifications:
  - вычисляемые колонки **Charge** (`final_charge`) и **Pepmass** (`final_pepmass`) показываются по умолчанию; значение из override помечается глифом `♻`, tooltip показывает исходные spectre-значения и isotope offset;
  - `charge`/`pepmass` переименованы в `Source charge`/`Source pepmass` и скрыты по умолчанию;
  - колонка **Quality** видна по умолчанию;
  - новые фильтры: **Min Quality**, **Has PTM** (All/Yes/No), **Has AA Substitution** (All/Yes/No);
  - проставлены человекочитаемые заголовки для всех колонок.

### Clear Calculations
- Красная кнопка **Clear Calculations** на вкладке Peptides (рядом с Save settings) с модальным подтверждением и чекбоксом «I am sure».
- Действие (глобально по проекту): восстанавливает `sequence` из `source_sequence` где был override; сбрасывает в NULL все расчётные поля (`intensity_coverage`, `ions_matched`, `ion_match_type`, `top_peaks_covered`, `ppm`, `theor_mass`, `quality`, `override_pepmass`, `has_ptm`, `isotope_offset`, `override_charge`, `source_sequence`); `is_preferred` → 0. `peptide_match` не затрагивается.

### Documentation
- Добавлена пользовательская документация по показателю Quality: `docs/project/identification_quality.md`.

## Bug Fixes

- `SeqFixer.get_ppm` / `get_matched_ppm`: добавлен недостающий аргумент `original_ppm` во все 8 вызовов конструктора `SeqResults()` — предсуществующий баг, проявлявшийся при загрузке исходников вместо установленного пакета (TypeError: missing required positional argument).
- Таблица: глиф `♻` в колонке `final_charge` теперь показывается только когда `override_charge` реально отличается от исходного `charge`, а не при любом не-NULL override.
- `SeqFixer.get_ppm`: при `unallocated_only=True` (чекбокс "Recalculate PTMs" снят) новые PTM (в т.ч. **терминальные** — например `Amidated`) больше не "протекают" в перебор `_iter_ptm_combos` — при отключённом PTM-переборе шаг 3 (PTM-enumeration) полностью пропускается, работает только charge/isotope-offset коррекция исходной последовательности.
- `SeqFixer.get_ppm`: логика перебора переработана — теперь всегда выполняется полный грид charge×isotope-offset для исходной (импортированной) последовательности без добавления новых PTM, с гарантированным best-effort fallback-кандидатом (лучший по abs_ppm вариант, даже если он выше `target_ppm`). PTM-кандидаты (если включён "Recalculate PTMs") добавляются к этому же списку. `identification_processor._get_best_override()` теперь выбирает лучший вариант **по Quality** (первично), при равенстве — по наименьшему `abs_ppm` (ранее выбор шёл по `intensity_percent`).

## Behavior Changes

### SeqFixer variant selection (get_ppm / process_single_ident)

Раньше выбор лучшего варианта шёл по `intensity_percent` и `get_ppm()` останавливался на первом удачном шаге (direct hit → charge override → PTM enumeration). Новая логика:

1. **Полный перебор** вместо раннего выхода: `get_ppm()` больше не останавливается на direct hit/charge override, а собирает всех кандидатов.
2. **Гарантированный fallback**: для исходной (импортированной) последовательности всегда выполняется комбинированный грид `charge × isotope-offset` (без добавления новых PTM) — и лучший по `abs_ppm` вариант добавляется в список кандидатов, **даже если он выше `target_ppm`**.
3. **Все кандидаты ниже threshold** попадают в `override` (charge/isotope-варианты исходной последовательности + PTM-варианты, если включён "Recalculate PTMs").
4. **Выбор по Quality**: `identification_processor._get_best_override()` сортирует кандидатов по убыванию `Quality` (Bern et al., 2004), при равенстве Quality — по возрастанию `abs_ppm`. Параметр `selection_criteria`/`seq_criteria` более не влияет на ранжирование.

Следствия:
- При снятом "Recalculate PTMs" (`unallocated_only=True`) PTM не добавляются вовсе — ни внутренние, ни терминальные.
- Последовательности с unlocalized PTM (`?`) по-прежнему раскрываются через `_expand_unlocalized` независимо от `seq_results.override` (раньше ветка зависела от `override is None`, что стало недостижимо из-за гарантированного fallback).
