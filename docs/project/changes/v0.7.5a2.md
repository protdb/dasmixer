# v0.7.5a2

**Date:** 2026-11-26

---

## Summary

Реализована спецификация 0.7.5a2: новый поиск белков (protein match v2) — препроцессинг уникальных последовательностей, точный поиск и поиск со сниженной точностью через npysearch в дочернем процессе, пересчёт частичных совпадений со спектрами; расширение схемы БД (PROJECT_VERSION 0.7.4 → 0.7.5); резерв исходного PPM (`source_ppm`); переработка preferred selection; новые фильтры и колонки в joined peptide data; обновление GUI (фильтры, прогресс, tool settings); очистка временных папок при старте приложения.

Спецификация: `docs/project/spec/0.7.5a2_SPEC.md`.

## Core Changes

### Схема БД (PROJECT_VERSION 0.7.5)

- `spectre.file_name TEXT` (nullable) + индекс `idx_spectre_file_name`. Индекс НЕ входит в `CREATE_SCHEMA_SQL` (скрипт исполняется при каждом открытии проекта до миграций) — только в миграцию `0.7.5` и в новую константу `NEW_PROJECT_EXTRA_SQL`, исполняемую `initialize()` при создании новой БД.
- `identification.source_ppm REAL` (nullable).
- `peptide_match`: `lcrr REAL`, `unconfirmed_ptms INTEGER`, `quality REAL`, `fasta_start INTEGER`, `correction VARCHAR(8)` (NULL | `'ilc'` | `'denovo'`) — все nullable.
- `saved_plots.plot_format VARCHAR(16)` (nullable, без DEFAULT; NULL == `plotly`).
- `import_project_mixin.py` синхронизирован по правилу AGENTS #15: spectre 16, identification 28, peptide_match 19, saved_plots 6 колонок (INSERT/SELECT совпадают со схемой).
- Данные не мигрируются: старые `peptide_match` остаются с NULL в новых полях, требуется перезапуск protein match.

### `source_ppm` (бэкап исходного PPM)

- `put_identification_data_batch`: `source_ppm` пишется один раз — при первом реальном изменении `ppm` (новое значение отличается более чем на 1e-9 либо стало NULL); повторные пересчёты и пересчёты без изменений `source_ppm` не трогают.
- `clear_calculations`: `ppm` восстанавливается из `source_ppm`, затем `source_ppm` обнуляется (в одном UPDATE).

### Protein match v2 (`calculations/peptides/`)

Новые модули:

- `types.py` — dataclasses `SearchMember`, `SearchSequence`, `Candidate`, `ProteinMapProgress`.
- `fasta_export.py` — выгрузка белков и запросов в FASTA (`make_work_dir`, `write_proteins_fasta`, `write_queries_fasta`).
- `blast_runner.py` — запуск `npysearch.blast` в дочернем процессе (ProcessPoolExecutor, 1 воркер, `os.chdir` внутри воркера, `outputToFile=True` + переименование CSV).
- `blast_parse.py` — разбор CSV, фильтры покрытия, `unique_evidence`.
- `tmp_cleanup.py` — `cleanup_peptide_match_tmp()`.

`map_proteins` переписан (Stage 0–3 на инструмент):

- Stage 0 подготовка: белковая БД → `proteins.fasta` [+ `proteins_lic.fasta`]; per tool — `get_unique_sequences_for_search()` → `st1_plain_{tool_id}.fasta`.
- Stage 1 точный поиск: `blast(identity=1.0)`, принимаются только хиты с полным покрытием запроса (`NumMatches == qlen AND NumGaps == 0 AND NumMismatches == 0`). Учтено, что npysearch выполняет ЛОКАЛЬНОЕ выравнивание: `Identity == 1.0` в выдаче не означает полного покрытия запроса. Ограничение `maxAccepts` (частичные хиты занимают слоты) зафиксировано в docstring.
- Stage 2 поиск со сниженной точностью (только при `denovo_correction` или `save_aa_substitutions` и `min_protein_identity < 1.0`): отдельный файл запроса из «ненайденных» индексов, `eff_identity = NumMatches / qlen >= min_protein_identity`.
- Stage 3 пересчёт со спектрами: батчи по `identification_processing_batch_size`, спектры + поля идентификации, `process_protein_map_row` в пуле воркеров; после пересчёта — отбор по максимальной `identity` с приоритетом `denovo` > `substitution`.
- I/L: без пересчёта, `correction='ilc'`, `matched_sequence` — подпоследовательность оригинального белка (не `TargetMatchSeq`).
- `use_src_protein_ids`: идентификации с `src_file_protein_id` превращаются в точные строки `peptide_match` напрямую (новый `IdentificationMixin.get_idents_with_src_protein`) и исключаются из поиска; `sample_id` сохраняется.
- Уникальные последовательности: I/L-слитие вариантов, отсев гомополимеров (`len(set(seq)) == 1`), порог длины `length >= max(min_peptide_length, 4)`.
- Прогресс: новый объект `ProteinMapProgress` (tool_index/tool_count/stage/message/fraction/processed/total); доли по этапам (15% × 4 + processing 60→100% при Stage 2/3; трети — без), `fraction` нормирован на весь запуск.
- Запись пулами через новый `PeptideMixin.add_peptide_matches_batch_fast` (`executemany`, без построчного fallback); перед вставкой строки с неизвестными `protein_id` отбрасываются (FK safety). Stage 1 — `save(checkpoint=True)` после каждого сброса; Stage 3 — `save()` после сброса, checkpoint в конце инструмента.
- Временная папка `{tmp}/peptide_match/{project_stem}/{timestamp}` НЕ удаляется после запуска (нужна для отладки) — очищается при старте приложения (B12).
- Удалены `denovo_correction_ppm`, `query_ppm` и использование `get_leucine_combinations` (модуль `utils/lic.py` оставлен без изменений).

### Критерии de novo коррекции (логика «И», обновление Developer от 2026-11-26)

- `_check_correction_criteria` (protein_map_worker): **все выбранные** критерии должны выполняться (логика И вместо ИЛИ), сравнение «не хуже» (нестрогое, было строгое улучшение):
  - `ppm`: `abs(match.ppm) <= abs(ident.ppm)`
  - `lcrr`: `match.lcrr >= ident.lcrr`
  - `quality`: `match.quality >= ident.quality`
  - `intensity_coverage`: `match.intensity_percent >= ident.intensity_coverage`
- Пустой список критериев = принять. NULL у идентификации — критерий проходит при любом рассчитанном значении матча; NULL у матча — критерий провален. Старые ключи `ions_matched`/`top10_ions_matched` молча игнорируются.
- `correction='denovo'` выставляется только при включённом `denovo_correction` (B9); без него partial-совпадения сохраняются только как `substitution=1` (при `save_aa_substitutions`).
- Worker дополнительно возвращает `lcrr`, `quality`, `unconfirmed_ptms` (из `MatchResult`) и `fasta_start`; в `row_dict` передаются `ident_lcrr`, `ident_quality`, `denovo_correction`, `score` (чинит `min_score` в AA-gate, B10).
- Core-дефолт `match_correction_criteria` выровнен на `['ppm', 'intensity_coverage']`.

### Preferred selection

- `get_idents_for_preferred` / `get_all_idents_for_preferred`: убран агрегирующий подзапрос `GROUP BY identification_id` (смешивал разные матчи и считал AA-substitution строки); прямой `LEFT JOIN peptide_match ... AND m.correction = 'denovo'`.
- Фильтры по логике «исходное значение ИЛИ denovo-значение» (ppm, intensity coverage, ions matched, top peaks, quality, lcrr, unconfirmed PTMs); подтверждено Developer — по каждому фильтру независимо.
- Эффективные значения: `eff_abs_ppm`, `eff_intensity_coverage` (CASE по значению, не по факту наличия строки — hardening); исходные `i.ppm`, `i.intensity_coverage`, `i.lcrr`, `i.unconfirmed_ptms` сохранены для обратной совместимости.
- Несколько denovo-матчей одной идентификации сворачиваются в одну строку по `criterion` (`'ppm'` → минимум `eff_abs_ppm`, `'intensity'` → максимум `eff_intensity_coverage`); новый параметр `criterion` пробрасывается из `calculate_preferred_identifications_for_file`.
- `matching.py`: удалены `denovo_correction`/`denovo_correction_ppm` и denovo-ветки; сортировка по `eff_*`; legacy `select_preferred_identifications` упрощён до `max_ppm`.

### Joined peptide data (`joined_peptide_data_mixin.py`)

- Новые колонки SELECT: `i.source_ppm`, `m.correction`, `m.fasta_start`, `m.lcrr AS matched_lcrr`, `m.quality AS matched_quality`, `m.unconfirmed_ptms AS matched_unconfirmed_ptms` (алиасы с `matched_` — чтобы не конфликтовать с `i.*`).
- Новые параметры `correction` (None/'all'/'none'/'ilc'/'denovo'; неизвестное — `ValueError`) и `apply_to_matched` — Max PPM и Min Quality принимают также значения denovo-скорректированных матчей (новый построитель `_build_peptide_filter_conditions_matched`).
- `min_score` добавлен в `get_joined_peptide_data` (был только в `count_…` и в построителе).

## Fixes

- `get_joined_peptide_data(min_score=...)`: параметр отсутствовал в `get_…` при наличии в `count_…` — `TypeError` при передаче из GUI.
- AA-substitution gate: `score` не попадал в `row_dict` воркера — `min_score` не работал (B10).
- `plot_mixin.get_spectrum_plot_data`: для строк Stage 1 (`matched_*` = NULL) и `ilc`-строк — fallback на значения идентификации (`i.ppm`/`i.intensity_coverage`/`i.quality`/`i.lcrr`); для denovo-строк — реальные `m.quality`/`m.lcrr` вместо жёстких `None`. `0.0` корректно обрабатывается как значение (без truthiness-проверок).
- Hardening preferred: `eff_abs_ppm`/`eff_intensity_coverage` вычисляются по наличию значения (`m.matched_ppm IS NOT NULL`), а не по факту наличия denovo-строки.
- Аудит потребителей `peptide_match` (§8 спеки): NULL-безопасность подтверждена (`get_peptide_matches_with_spectra`, `calculate_protein_metrics_internal`, toolmatch report, `map_identifications`, LFQ, mzTab export, system export) — правок не потребовалось.
